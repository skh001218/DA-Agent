# Discord 분석 문제 — 기본형 템플릿

생성된 분석 문제의 첫 안내와 재개 안내에 사용하는 구성이다. 제목과 구역 사이에 빈 줄을 넣고, 해야 할 일은 번호로, 데이터와 조건은 항목으로 표시한다. Discord 전송에서는 일반 텍스트로 표시하며 이모지와 줄바꿈으로 구역을 구분한다.

```text
📌 {문제 제목}
난이도: {초급 / 중급 / 고급} · 연습 유형: 데이터 분석

배경
{공개 업무 배경과 관측된 문제를 원문에서 가져온 1~2문장, 최대 180자}

🎯 해야 할 일
1. {저장된 공개 분석 질문}
2. {다음 공개 분석 질문}
{공개 질문은 모두 표시. 긴 판단 조건은 문제 원문에서 열람}

데이터와 조건
• 관측 기간: 한국 시간 · {연도}
  기간 A: {월/일 시:분} ~ {월/일 시:분, 필요한 경우 초}
  기간 B: {월/일 시:분} ~ {월/일 시:분, 필요한 경우 초}
• 자료 관측 종료: {한국 시간으로 변환한 시각} 미만
• 제공 표: {표 이름} — {한 행 단위의 첫 문장}
• 자료 안내: {합성 자료 및 품질 검토 상태}
• {가상 사례 안내 — 해당하는 경우}

📝 제출할 내용
결론 · 저장 조회 근거 · 가능한 설명과 한계 · 대응 또는 추가 확인 제안

시작하기
/query로 데이터를 조회하세요.
/help kind:문제 원문으로 전체 배경·가정·판단 조건을 확인하세요.
/help로 데이터 사전·평가 기준을 확인하세요.
/report로 보고를 작성하고 후속 질문에 답한 뒤 /submit로 제출하세요.

{실제로 저장된 사례 출처 — 있는 경우에만 표시}
```

## 작성 규칙

- 형식은 고정하고 내용은 검증을 통과한 문제의 공개 정보에서 가져온다. 임의의 현상·수치·기간·출처·제출 기준을 추가하지 않는다.
- 질문 수는 문제에 따라 달라진다. 모든 공개 질문을 번호로 표시하며 명시된 판단 조건과 가정은 `/help kind:문제 원문`에서 그대로 제공한다. 초급의 기준과 중급·고급의 선택 여지를 유지하고 풀이 순서·지표·정답 힌트를 추가하지 않는다.
- 기간은 저장된 공개 관측 설명의 날짜·시각을 한국 시간으로 변환한다. 데이터의 최소/최대 날짜로 대체하지 않는다. UTC·오프셋·날짜 변경·연도 변경과 끝 경계를 보존한다. 0초는 생략하되 실제 초·소수 초가 있으면 보존한다. 해석할 수 없는 기간은 임의 변환하지 않고 원문 열람을 안내한다.
- 한 행 단위의 첫 문장, 합성 자료와 품질 상태는 첫 안내에 표시한다. 한계 목록과 검산 제한 설명은 첫 안내에서 나열하지 않는다. 전체 가정·판단 조건·한계·검산 범위·원문 시간은 문제 원문, 긴 컬럼 설명은 데이터 사전, 세부 배점과 인정할 한계는 평가 기준에서 열람한다.
- 요청한 데이터를 제공할 수 없거나 실행·수집 제한에 실제로 도달한 때는 해당 응답에서 기존 제한 안내를 제공한다. 문제 안내를 짧게 만들기 위해 실제 실패나 불완전 결과를 숨기지 않는다.
- 저장된 구조화 안내가 없는 이전 생성 문제는 공개 설명의 표준 구역을 읽어 배경과 질문을 복원한다. 전체 업무 요청은 문제 원문에서 보존한다. 내부의 `valid_paths`를 필수 풀이 순서로 바꾸지 않는다.
- 기존 고정 튜토리얼 및 SQL 연습 안내는 각각의 계약을 유지한다.
- 실행 템플릿과 렌더러: `src/da_agent/discord_presentation.py`, `discord_task_brief.py`. 공개 안내 항목 저장: `src/da_agent/discord_generation.py`. 기존 `objective`와 평가 기준은 보존한다.
