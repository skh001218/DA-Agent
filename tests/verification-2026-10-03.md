# 프로토타입 검증 기록

- 검증일: 2026-10-03 (Asia/Seoul)
- 환경: Windows AMD64, Docker Desktop, Linux AMD64 Python3.12.10 / PostgreSQL17.4
- 범위: 기존 Spec001~004의 문제1 훈련 흐름. PRD의 문제2·3 전체 MVP 완료를 뜻하지 않는다.
- 구현 방식: 공통 API·서버는 루트에서, 데이터·웹·인증은 서로 다른 관리 워크트리와 서브 에이전트에서 구현한 뒤 커밋을 통합했다.

## 자동 확인

실제 PostgreSQL 포함 테스트72개 통과. DB 없는 호스트 실행은67개 통과, DB 통합5개는 건너뜀. tests/test_churn.py, test_packages.py, test_sql_policy.py, test_auth.py, test_review.py, test_integration.py를 사용했다. Starlette/httpx의 테스트 도구 교체 예정 경고가 있으나 테스트 실패는 없다.

실제 DB 패키지 검증기는 v1·v2 기준 SQL과 독립 Python 집계가 일치함을 확인했다. 각 버전에서 빈 코호트 및12개 경계 유저도 실제 SQL로 확인했다. 같은 배포를 다시 적재·검증하여 기존 DB 내용을 유지함을 확인했다.

혼합 ID·버전, 파일 변조·경로 이탈·기준자료 누락 차단을 테스트했다. 조회는 공개 표에 제한하고 쓰기·시스템 표·외부 파일 함수·설정 변경·다중문을 차단했다. 조회0행, 문법 오류, 실행 제한, 최대 행 수와 부분 결과, 큰 정수·numeric·UTC 직렬화를 확인했다.

## 실제 화면 확인

[실행 화면](http://127.0.0.1:8087). agent-browser의 전용 da-prototype 세션으로 조작했다.

- 문제1 v2 시작, 서술 입력 자동 저장, SELECT count(*) 실제 실행 및200명 표시.
- 실행A 선택 저장, 실행B 미저장 후 새로고침: A만 복구하고 SQL 편집기와B 결과는 사라짐.
- 보고서 초안·저장 근거 선택 후 새로고침: 서술과 근거 선택 복구.
- 보고서 v1 제출, 리뷰 요청 실패, 수정 보고서 v2 제출: 두 제출본과 실패 리뷰 보존.
- 서버 재시작 후 이전 미저장 실행 저장: 만료 안내, 원래 화면 결과 유지, 자동 재실행 없음.
- 앱·DB 로그 및 영구 기록에 미저장 검증용 marker가 없고 localStorage/sessionStorage는 비어 있음.
- 화면에서 실제0행 조회와 없는 컬럼 오류를 실행해 성공0행과 SQL 오류가 구분됨을 확인함.
- 정적 파일·화면 표시를 다시 확인하고 보고서/데이터 사전의 표시 오류를 수정함. 브라우저 오류 목록은 비어 있음.

브라우저 검증 자료는 prototype-report.png와 prototype-home.png를 참고한다. 홈 스크린샷은 초기 통합 상태이며 보고서 스크린샷은 최종 표시를 갱신했다. 테스트용 훈련 기록 일부와 화면 검증용 시도는 로컬 기록 DB에 남아 있다.

## 아직 확인하지 않은 항목

- 실제 ChatGPT 계정 로그인·권한 승인·컨테이너 콜백·실제 모델 조회와 코칭/리뷰 완료 응답.
- 실제 AI 리뷰5개 표본·3회 반복의 평가 품질과 일관성. 현재 점수/근거 형식 검증은 모의 응답 테스트다.
- 다른 PC의 Git 체크아웃·Compose·패키지 지문·재개·별도 로그인, ARM 환경.

접근 거부 원인을 계정·조직 또는 앱 등록 정책에서 확인하고 해결한 뒤 짧은 코칭/리뷰를 요청하는 것이 다음 실제 확인 행동이다. 해당 성공 검증 전에는 Spec003·004의 대기 항목을 완료로 변경하지 않는다.

후속 확인: 사용자는 로그인·승인 완료를 알려줬지만 앱의 `/api/auth/status`는 disconnected/plan_enabled=false/inference_verified=false였다. 공식 discovery 응답200과 issuer·endpoint, 콜백 http://127.0.0.1:8087/auth/callback, 외부 키·별도 인증 저장 설정은 확인했다. 앱에 실제 등록된 계정이나 완료 호출이 확인되지 않아 사용자는 공식 로그인 화면에 “조직에서 이 앱에 접근 권한을 부여하지 않았습니다.”가 표시됐다고 알려줬다. 승인이 완료되지 않았으며 정책 확인 전에는 같은 로그인 요청을 반복하지 않는다.

후속 형식 수정: 공식 preview 요구사항에 맞춰 코칭·리뷰의 지시 메시지를 developer 역할로 변경했다. 오프라인 인증 테스트는 전송 본문(input 배열·store=false·stream=true·허용 필드)을 검사하며 DB 통합 리뷰 테스트는 실제 앱이 developer/user 역할을 전달하는지 확인한다. 이 검증은 실제 계정 접근 승인이나 모델 호출 성공을 의미하지 않는다.

수정 후 재검증: 호스트67개 통과/DB5개 건너뜀, 새 Docker 이미지에서 PostgreSQL 포함72개 통과. 수정 이미지를 앱에 반영한 뒤 health 정상과 인증 disconnected를 확인했다.


## Gemini API 전환 검증 (2026-10-03)

사용자는 OpenAI 비용 우려로 Gemini API를 선택했다. generateContent·systemInstruction·contents·키 헤더 방식으로 구현하고 store=false·최대4096 출력토큰·timeout90초를 설정했다. 키는 로컬 숨겨진 터미널 입력과 Compose secret으로 전달하며 브라우저·DB·로그·Git에 저장하지 않는다.

호스트83개 통과/실제DB6개 건너뜀, Docker PostgreSQL 포함89개 통과. 신규 어댑터 테스트는 모의 Google HTTP 응답으로 완료·키 누락/오류·403·404·429·500·부분응답·안전차단·빈응답·타임아웃·모델 확인을 검증했다. 통합 테스트는 모의 Gemini 완료 응답으로 코칭·리뷰5개 기준·근거 ID·점수 계산·DB 재조회와 키 비노출을 확인했다. 이는 실제 Google 모델 호출이나 평가 품질 확인을 의미하지 않는다.

실제 실행 중인 앱의 provider=gemini, configured=false, inference_verified=false를 확인했다. 브라우저에서 OAuth 버튼이 숨겨지고 Gemini 키 설정 필요가 표시됨을 확인했다. 코칭 요청과 기존 보고서v2 리뷰 요청은 api_key_missing 안내를 표시했고, 새로고침 후 기존 제출본·근거·실패 리뷰가 보존됐다. 브라우저 오류 목록은 비어 있다. gemini-key-pending.png가 검증 화면이다. 실제 키 설정과 Google 완료 응답은 사용자 설정 대기다. 기존 Spec003/004 진행도60%는 유지한다.

읽기 전용 서브 에이전트 검토 후 키 교체·인증 실패가 이전 호출 성공 표시를 유지하는 문제를 수정했다. 키 지문은 메모리에서만 비교하고 공개 상태에 반환하지 않는다. 최종 PostgreSQL 포함90개 테스트 통과.


## 실제 Gemini 완료 응답 확인

사용자가 Gemini 설정 완료를 알려준 뒤 앱 컨테이너를 재생성해 configured=true를 확인했다. 키·토큰 내용은 출력하지 않았다. 공식 모델 목록 조회200 후 gemini-2.5-flash 생성은 신규 사용자 지원 중단404를 반환해 서버가 안내한 gemini-3.8-flash로 설정을 변경했다. 공식 가격표의 무료 티어 제공을 확인했으나 현재 프로젝트의 결제 상태·청구액은 확인하지 않았다.

최초 코칭은 완료됐지만 created_at 등 실제와 다른 컬럼 예시가 있었다. 공개 데이터 사전을 코칭·리뷰 입력에 추가하고 실제 컬럼만 쓰도록 지시했다. 수정 후 코칭은 signup_at·Asia/Seoul·D1~D8·관측 완료 경계 조건을 올바르게 설명했다. Gemini3.8의 thinkingLevel=low를 사용한다. 수정 이미지의 PostgreSQL 포함90개 테스트가 통과했다.

보고서v2의 실제 리뷰 최초 요청은 API 서버 오류로 실패했고, 진단을 포함한 명시적 재시도1회가 upstream200·review completed로 완료됐다. 리뷰ID c388a338-8d56-46e7-8d73-046a54e62ad1, 모델 gemini-3.8-flash, 서버 계산40점. 이 보고서는 전체 유저수 확인까지만 작성한 미완성 검증용 제출본이므로 낮은 점수는 정상 흐름 결과다. 새로고침 후5개 항목·점수·근거·다음 행동과 이전 실패 기록 보존을 실제 화면에서 확인했고 브라우저 오류는 없었다. gemini-review-live.png에 화면을 저장했다.

Spec003 기록 흐름5/5 완료, Spec004 호출 완료4/6으로 갱신했다. Spec004의 품질표본5개×반복3회와 다른 PC/ARM은 여전히 검증 대기다. 이전 키 설정 대기·60% 표현은 이 최신 결과 이전의 검증 이력이다.
