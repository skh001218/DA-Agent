# Discord 분석 훈련 난이도와 취업 준비 효용 검토

현재 훈련은 고유 사용자·분모·기간을 정의하고, 관측 결과를 근거로 대응을 설명하는 연습에 도움이 된다. 그러나 틀린 구성 변화 해석도 100점을 받는 평가 오류를 재현했고, 평가 완료 후 수정 보고도 차단됐다. 초급·중급·고급의 문제 내용·데이터·평가 기준은 동일하다. 요청 주제 확장 전에 평가의 판별력, 수정 제출, 난이도별 완료 조건을 먼저 보완하는 것을 권한다.

- 검토일: 2026-10-06, Asia/Seoul.
- 관점: 게임 데이터 분석가 취업 준비생을 가정한 에이전트의 실습·검토. 실제 취업 준비생 참여 실험이나 사람의 교육 품질 승인이 아니다.
- 대상: 현재 작업 폴더의 Discord 출제·자연어 조회·분석 기록·보고·평가 서비스. 웹의 요청별 합성 데이터 생성기는 별도 구현이며 이번 판정과 구분한다.
- 표준 구조: docs, scripts, specs/examples, src, template, tests 모두 존재. 폴더 생성·기존 파일 이동 없음.
- 실행: 기존 PostgreSQL 서버에 별도 `discord_audit_20261006` DB를 생성하고 관리자·읽기 전용 학습자 계정을 사용했다. 기존 학습 DB·기록과 Discord 메시지는 변경하지 않았다.
- 코드: 실행 중인 컨테이너의 서비스 파일과 작업 폴더 파일 해시가 달라 현재 소스를 `/tmp/audit-current`에 복사해 별도 프로세스로 실행했다. 봇 배포·재시작은 하지 않았다. 따라서 결과는 현재 소스의 검사이며 배포본 전체와 같다고 보장하지 않는다.
- 재현 도구: `scripts/verification/audit_discord_training_levels.py`, `audit_discord_training_followups.py`. 실제 모델을 호출하므로 API 사용량이 발생한다. 감사 전용 DB와 `/run/secrets/gemma_key`를 전제로 한다.
- 원본 근거: [실행 기록](../artifacts/training-level-audit-2026-10-06/audit.json), [후속 검사](../artifacts/training-level-audit-2026-10-06/followups.json).

## 실제 생성한 세 난이도 문제

`representative_task(difficulty=...)`와 `DiscordTrainingService.start`로 각 난이도를 생성했다. 아래 문제는 검토자가 새로 쓴 출제안이 아니라 현재 함수의 공개 결과다.

현재 Discord 출제는 고정 대표 과제 함수이며 이 단계에서 LLM으로 새로운 문제를 만든 것이 아니다. 실제 모델 호출은 자연어 조건 해석과 제출 평가에 사용했다.

> **튜토리얼 완료율 변화와 우선 대응**
>
> 신규 가입자의 튜토리얼 3단계 완료율을 두 주와 유입 채널별로 비교하고, 신뢰성과 대안 설명을 점검해 우선 대응을 제안하세요.
>
> 1주차: 2026-09-01~09-07 가입자. 2주차: 2026-09-08~09-14 가입자. UTC, 관측 종료 2026-10-01 제외. 유입 채널 organic/ads. 가입자, 단계별 도전·완료, 접속 테이블을 제공한다. 재도전은 중복 이벤트가 될 수 있고 실제 수집 누락은 합성 테이블로 판정할 수 없다.

| 항목 | 초급 | 중급 | 고급 |
| --- | --- | --- | --- |
| 문제·기간·학습 목표 | 동일 | 동일 | 동일 |
| 데이터 | 가입자 40명, 도전 130건, 접속 100건 | 동일 | 동일 |
| 기본 도움 수준 | guided | independent | independent |
| 공개 평가 항목·배점 | 동일한 5항목, 100점 | 동일 | 동일 |
| 난이도 기준 일치 판정 | 부분 미달 | 부분 충족 | 미달 |

판정 근거는 PRD의 “초급은 안내된 기준 적용, 중급은 기준·대안 선택, 고급은 교란·관측 한계·후속 검증 설계”다. 현재 `difficulty`와 `help_policy`를 제외하면 과제 객체가 동일하고 생성 데이터도 동일하다. 도움 차이는 있지만 분석의 복잡도 차이가 없다.

초급은 공개된 분모·관측 기간을 적용하는 연습에 적합하지만, 시작부터 채널 구성 대안과 대응 판단까지 요구한다. 초급용 단계별 완료 조건이나 결과 작성 틀이 없고 도움을 사용자가 찾아야 한다. 중급은 가설·반박 비교에 적합하지만 `valid_paths`와 공개 평가 기준이 분석 방향을 상당 부분 알려준다. 고급은 새로운 교란 요인·로그·실험 결과를 실제 검증할 자료가 없어 복잡한 분석보다 한계를 말하는 활동으로 끝나기 쉽다.

## 실제 조회와 원인 해석

다음은 자연어로 두 가입 코호트의 채널별 완료율을 요청해 실제 PostgreSQL에서 얻은 값이다. 날짜·분모·완료 관측 기간을 명시했다. 검산용 고정 조건 SQL도 별도로 실행했으며, 자연어 조회 실패를 검산 결과로 대체하지 않았다.

| 가입 코호트 | 채널 | 가입자 | 완료자 | 완료율 |
| --- | --- | ---: | ---: | ---: |
| 1주차 | ads | 5 | 4 | 80% |
| 1주차 | organic | 15 | 12 | 80% |
| 2주차 | ads | 15 | 10 | 66.67% |
| 2주차 | organic | 5 | 4 | 80% |
| 1주차 전체 | 전체 | 20 | 16 | 80% |
| 2주차 전체 | 전체 | 20 | 14 | 70% |

전체 변화는 **-10%p**다. 감소율로 표현하면 **-12.5%**이며 둘은 다른 값이다. 전체 완료율은 채널 완료율의 단순 평균이 아니라 완료자 합/가입자 합으로 계산해야 한다.

ads 비중은 25%→75%로 늘고 ads 내부 완료율은 80%→66.67%로 낮아졌다. 하지만 1주차 두 채널 비율이 모두 80%이므로 1주차 비율을 고정한 채 구성만 바꾸면 전체도 80%다. **“채널 구성 변화만으로 전체 하락을 설명한다”는 결론은 이 데이터에 맞지 않는다.** 2주차 비율을 고정해 1주차 구성으로 표준화하면 76.67%다. 이 기준의 서술적 분해는 채널 내 변화 -3.33%p, 구성 변화 -6.67%p이며 기준 시점에 따라 분해값이 달라진다. 어느 분해도 광고나 난이도의 인과 효과를 식별하지 않는다.

가능한 보고는 “ads 집단의 관측 변화와 구성 변화가 함께 확인된다. 난이도·숙련도·기기·수집 상태 등의 원인 후보는 현재 자료로 구분할 수 없다. 수집 및 세부 집단 정보를 확인한 뒤 변경 실험을 검토한다”다. 원인 식별 불가와 타당한 추가 검증도 성공적인 분석으로 인정해야 한다.

## 전체 과정의 실행 결과

| 난이도 | 성공한 자연어 조회 | 제출 상태 | 모델 점수 | 보고·조회·평가 재개 |
| --- | ---: | --- | ---: | --- |
| 초급 | 2건 | completed | 100/100 | 보존 확인 |
| 중급 | 3건 | completed | 95/100 | 보존 확인 |
| 고급 | 4건 | completed | 100/100 | 보존 확인 |

완주한 기본 검사의 실제 모델 호출은 15회이며 13회 응답 완료, 2회 API429 제한이었다. 제한된 두 건은 인과 단정과 틀린 수치 보고의 추가 품질 표본이다. 이들은 점수 null·평가 보류로 기록되었으며 오류 탐지 성공으로 계산하지 않는다. 세 학습 흐름의 제출 평가는 모두 완료했다.

추가 실제 모델 호출 2회로 고급 보고의 동일 입력 반복과 잘못된 구성 해석을 대조했다. 완주한 기본 검사와 합하면 17회 호출, 15회 응답 완료, 2회 API 제한이다. 준비 과정에서도 조회 모델을 2회 호출한 뒤 검증 스크립트가 존재하지 않는 `SqlRunner.run`을 사용해 중단됐다. `execute`로 바로잡고 처음부터 재검사했으며, 준비 단계의 호출까지 포함한 이번 작업의 실제 호출 수는 19회다. 준비 단계 결과는 최종 품질 표본 수에 합산하지 않았다.

| 평가 표본 | 결과 | 검토 판정 |
| --- | ---: | --- |
| 원래 고급 보고 | 100점 | 기본 제출 응답 완료 |
| 같은 고급 보고 반복 | 100점 | 이 입력의 두 평가 점수 일치 |
| 근거는 유지하고 구성 변화 해석만 잘못 변경 | 100점, 모든 항목 4등급 | 잘못된 해석을 탐지하지 못함 |

잘못된 대조 보고에는 “1주차 채널 비율이 모두80%이지만 유입 구성만 바꾸면 전체70%가 된다. 채널 내 완료율 변화는 전체 하락에 기여하지 않는다. 따라서 구성 변화만으로 전체 하락을 완전히 설명한다”를 넣었다. 실제 조회 결과와 나머지 보고·초기 가설·후속 답변은 유지했고, 대화에 중복 저장된 보고 문장도 동일하게 바꿨다. 1주차 양 채널이 80%이면 어떤 구성으로 가중평균해도 80%이므로 이 주장은 수학적으로 틀렸다.

그런데 평가의 `hypothesis_review`는 **4등급**으로 “구성 변화 가설을 채택하는 논리적인 검토 과정을 수행함”이라 설명했고, `evidence_interpretation`도 **4등급**으로 “구성 효과를 명확히 설명함”이라 판단했다. 근거 ID가 존재하고 응답 JSON이 유효한 것만으로 해석의 정확성은 보장되지 않는다는 실제 반례다. 한 오류 표본의 결과이며 전체 오류율 추정은 아니다. 초급·중급·고급의 높은 점수 또한 이 한계를 고려해서 읽어야 한다.

평가 이후 `report` 요청도 실제 서비스에서 검사했다. 응답은 “완료 또는 중단된 훈련입니다. 기록을 열람하거나 중단된 훈련을 재개하세요”였고, 상태는 completed, 보고 버전 수는 1→1이었다. 제출 전 수정은 가능하지만 **완료된 평가의 피드백을 반영한 동일 과제 재제출은 현재 차단**된다. 잘못된 피드백을 그대로 받거나 개선 내용을 다시 평가받지 못하면 학습 순환이 끊어진다.

각 과제에서 초기 가설을 기록하고, 자연어로 두 주 채널별 완료율을 조회했다. 중급에는 재도전 중복 조회, 고급에는 D7 조회를 추가했다. 실제 실행 ID를 근거로 선택한 뒤 난이도별 보고를 작성하고 업무 담당자 후속 질문에 답한 다음 제출했다. 저장 기록을 재개해 보고·실행·평가 보존을 확인했다.

초급의 보고는 정의·숫자·한계 중심, 중급은 대안 가설과 채널 비교, 고급은 표준화 해석과 실험·보호지표 제안을 추가했다. 비교 점수는 같은 보고서의 난이도만 바꾼 통제 실험이 아니다. 초기 가설과 후속 답변도 평가에 포함되며, 이 답변들은 숙련된 에이전트가 작성했다. 실제 초급 학습자의 성취 수준이나 서비스 전체 성공률로 일반화하지 않는다.

표 렌더러가 만든 실제 PNG의 글자·열·숫자를 확인했다. [초급 결과 표](../artifacts/training-level-audit-2026-10-06/beginner-result-1.png)는 두 채널의 분자·분모·80%를 표시한다. 서비스 실행과 렌더링 확인은 실제 Discord에서 슬래시 명령을 입력하고 결과 포럼을 여는 검증을 대신하지 않는다. 이번에는 외부 메시지 전송을 수행하지 않았다. 사람 계정에서 확인할 핵심 행동은 `/submit`의 평가를 받은 뒤 같은 훈련에 `/report`로 수정 보고를 저장할 수 있는지 확인하는 것이다.

관련 현재 소스 자동 검사: **66 passed, 15 skipped**. 교육·조회·서비스·결과 카드 계약을 검사했다. 15개는 별도 테스트 DB 환경 변수가 필요한 검사이며 통과로 계산하지 않았다. 이 숫자가 실제 모델 의미 평가의 타당성을 입증하지는 않는다.

## 문제의 질과 취업 준비 효용

| 과정 | 도움이 되는 점 | 현재 부족한 점 | 판단 |
| --- | --- | --- | --- |
| 문제 생성 | 업무 질문·기간·단위·한계가 공개되어 시작 가능 | 장르·게임 규칙·변경 이력·결정 비용이 없고 난이도 내용 동일 | 입문용 대표 과제로 유용 |
| 자연어 SQL 조회 | 고유 사용자, 분모, 날짜 범위, 중복 제거를 말로 정의하고 실제 결과 확인 | 고정 연산만 지원, SQL을 직접 작성·수정하는 역량은 평가하지 않음 | 분석 질문 훈련에 유용, SQL 채용 과제 대비는 부족 |
| 원인 파악 | 전체 변화와 집단 변화를 구분하고 가설을 기각하는 연습 | 숨겨진 원인 식별 자료가 적고 데이터가 규칙적으로 반복됨 | 중급 사고 연습 가능, 고급 조사 재현 제한 |
| 보고서 작성 | 실행 근거와 결론·한계·우선순위를 연결하고 후속 질문에 답함 | 대응 비용·담당자·목표 효과·검증 종료 조건이 문제에 부족 | 면접의 분석 설명 연습에 유용 |
| 제출 평가 | 항목별 근거 ID·이유·개선 문구, 시스템 실패 보류 | 수학적으로 틀린 구성 해석에도 100점, 평가 후 수정 차단 | 현재 점수 신뢰 부족, 피드백은 검토 필요 |

**취업 준비생이라면 분석 사고와 보고 연습을 위해 사용하겠다.** 다만 이것만으로 SQL 코딩 테스트, 통계·실험 설계, 실제 게임 도메인 분석, 포트폴리오를 모두 준비했다고 판단하지 않겠다. 학습 시간이 같은 경우, 대표 과제 반복보다 새 게임 상황에서 지표를 선택하고 직접 SQL을 검증하는 활동을 추가하는 편이 역량 전이에 유리하다는 검토 의견이다. 이번 실습만으로 학습 효과를 측정한 것은 아니다.

직무 범위를 점검하는 보조 자료로 Riot의 공개 분석 직무 설명을 확인했다. [Central Product Insights](https://www.riotgames.com/en/work-with-us/job/8148781/principal-insights-analyst-central-product-insights-los-angeles-usa)는 SQL·Python·시각화와 결과를 의사결정 제안으로 전달하는 활동을 함께 요구한다. [TFT AXE](https://www.riotgames.com/ko/work-with-us/job/7592030/principal-insights-analyst-axe-teamfight-tactics-los-angeles-usa)는 실험 설계, 데이터 정확성, 보고와 제품 판단을 다룬다. 두 자료는 경력직 설명이므로 신입 합격 기준이나 국내 채용시장 전체 기준으로 사용하지 않았다.

완료 관측을 공통 종료일로 잡으면 첫 가입 코호트가 더 오래 관측되는 문제도 고려해야 한다. 현재 fixture는 모든 시도가 가입 당일이어서 실제 왜곡을 확인한 것은 아니다. 새 주제로 확장할 때 고정 가입 후 기간과 공통 관측 종료 중 무엇을 측정하는지 과제 계약으로 명시해야 한다.

평가 보완은 문구 하나를 추가하는 것으로 끝내지 않는 편이 좋다. 공개 평가 조건에 실행 수치와 주장 일치·가중 집계·반례 검토를 명시하고, 검산 가능한 수치 주장은 선택된 실행과 계산식으로 확인한 뒤 의미 평가에 전달해야 한다. 수치 검산과 가설 타당성 평가를 구분하고, 계산으로 판단할 수 없는 인과 원인은 타당한 보류를 인정한다. 위 오류 보고와 타당한 보고의 반복 대조를 통과하기 전에는 만점을 분석 숙련도 증거로 쓰지 않아야 한다.

이번 요청은 구현 전 점검이므로 제품 코드는 변경하지 않았다. 다음 확장에서는 “모든 주제 요청을 성공시킨다”보다 **요청한 학습 목표→난이도별 분석 행동→필요 데이터·조회→공개 평가 조건**의 연결을 먼저 보장해야 한다. 자료가 부족한 주제는 조건 확인 또는 범위 설명을 제공하고 튜토리얼로 몰래 바꾸지 않아야 한다.

## 난이도별 문제 개선 예시

아래는 현재 출시된 문제가 아니라 다음 수정의 검토용 출제안이다. 주제 확장 구현과 승인된 교육 기준으로 간주하지 않는다.

**초급:** “두 주의 신규 가입자 대비 3단계 완료율을 공개된 기간·분모로 계산하세요. 분자·분모와 -10%p의 의미를 적고, 이 값만으로 난이도 악화를 확정할 수 있는지 한 문장으로 설명하세요.” 계산 대상과 보고 틀을 제공하고, 채널 구성 분해나 실험 설계를 필수로 요구하지 않는다. 완료 조건은 정의 적용·정확한 수치·인과 단정 회피다.

**중급:** “전체 완료율 하락이 채널 구성 변화만으로 설명되는지 조사하세요. 두 가설과 이를 약화시킬 비교를 스스로 선택하고, 주별·채널별 분자/분모를 제시하세요. 유지·기각한 가설과 우선 점검을 보고하세요.” 현재 데이터로 수행 가능하다. 공개 분석 경로는 요청한 힌트로 제공하고 기본 과제에서 선택 이유를 먼저 받는 방식이 적합하다.

**고급:** “전체 하락을 채널 내 변화와 구성 변화로 서술적으로 분해하고 기준 시점에 따른 차이를 설명하세요. 표본·관측 기간·숙련도/기기/버전의 교란 가능성을 검토한 뒤 가장 가치 있는 추가 로그 또는 실험을 설계하세요. 주지표·보호지표·중단 및 판단 조건을 적으세요.” 분해는 현재 집계로 계산할 수 있으나 교란의 실제 검증과 독립적인 D7 확인에는 새로운 데이터가 필요하다. 문제를 공개할 때 가능한 검증과 제안만 가능한 검증을 구분해야 한다.
