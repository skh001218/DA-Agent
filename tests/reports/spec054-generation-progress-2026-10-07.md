- 날짜: 2026-10-07 (Asia/Seoul)
- 요청: 문제 출제 중 퍼센트를 메시지로 표시. 사용자는 ‘단계 완료율 + 현재 단계 표시’를 선택했다.
- 범위: `codex/discord-generation-progress`에서 구현·자동 검증·로컬 화면 확인 후 사용자가 운영 배포를 요청했다. PR·main 병합·운영 반영·실제 Discord 확인으로 확장했다.
- 구조 검사: `docs`, `scripts`, `specs/examples`, `src`, `template`, `tests` 존재. 생성·이동·경로 변경 없음.

## 구현과 결과

실제 출제 상태가 저장된 후 공개 상태·완료 수만 콜백으로 전달한다. 설계·검토 0%, 자료 생성·검산 33%, 공개 준비 67%, 공개 저장 성공 100%다. `stage_adaptive`는 자료 생성과 검산을 함께 수행하므로 이 작업 동안 33%를 유지한다. 시간 경과·토큰 수·남은 시간 추정은 사용하지 않는다.

Discord 전송 계층은 작업 스레드의 알림을 비동기 큐로 받아 최초 메시지 하나를 보내고 같은 메시지를 수정한다. 최초 출제·수동 재시도·추가 조건 답변·봇 질문 답장에 적용된다. 내부 호출 수 저장처럼 공개 상태가 같은 갱신은 중복 알림을 내지 않는다. 메시지 전송·수정 실패는 출제 결과에 영향을 주지 않는다.

완료 단계 수를 세션에 저장해 `/resume`의 진행 상태와 실패·취소·중단 안내에 표시한다. 오래된 종료 기록에 단계 수가 없으면 ‘확인 불가’로 표시한다. 취소 요청은 실행 중 메시지를 즉시 수정하며, 뒤늦게 도착한 활성 단계 알림은 취소 표시를 덮어쓰지 않는다. 재시도는 새 시도의 메시지에서 0%로 시작한다.

- 최신 main의 자연어 데이터 조회 기능 통합 후 전체 회귀: **773 passed / 83 skipped**, 동일한 기존 경고 1개. 진행률 변경은 8개 파일이며 기존 자연어 조회 기능을 보존했다.
- `git diff --check`: 통과.
- 새 검증은 실제 서비스 코드와 메모리 저장소·모의 모델·모의 DB 적재를 연결한다. 생성의 저장 상태와 콜백 공개 상태 일치, 준비 단계 실패 후 33% 보존, 취소 후 33% 보존, 공개 실패 후 67% 보존·100% 미표시, 추가 질문 답변 및 재시도 초기화를 확인했다.
- 전송 검증에서 생성 작업이 끝나기 전 진행 메시지 수정이 실제 발생하고, 동일 메시지 ID에 33→67→100을 반영하는지 확인했다. slash 재시도·답변과 질문 답장 경로, 수정 실패 후 최종 문제 안내 전달, 취소 즉시 표시·늦은 알림 무시도 확인했다.
- 표시 콜백 자체가 예외를 내도 서비스는 정상 생성·공개를 완료한다. 알림에는 공개 상태와 단계 수 두 필드만 포함한다.

## 로컬 화면 확인

서비스의 실제 상태 알림 4개를 모의 모델·DB 환경에서 수집하고 동일한 `progress_message` 렌더러 출력을 로컬 HTML에 표시했다. IAB `http://127.0.0.1:8768/progress.html`에서 다음 단계 버튼으로 0→33→67→100, 새 시도 버튼으로 0%, 실패·취소 버튼으로 마지막 완료율과 종료 상태를 확인했다. 390px 메시지 폭에서 문장이 줄바꿈돼 읽을 수 있었다.

미리보기와 알림·메시지 JSON 및 화면 캡처는 Git 제외 `.local/spec053/`에 보관한다. 화면 캡처는 `progress-67.png`다. 검증 후 미리보기 탭과 HTTP 서버를 종료했다. 이 HTML은 메시지 표시 확인용이며 제품 화면이나 실제 Discord 연결을 대신하지 않는다.
