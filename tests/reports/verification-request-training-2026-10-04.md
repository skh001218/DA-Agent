# 요청 기반 훈련 첫 사용 구간 검증

- 날짜: 2026-10-04 (Asia/Seoul)
- 대상: Spec 006·007, PRD-v2.2의 초기 사용 범위
- 결과: 핵심 사용 흐름은 실행 가능. 삭제 확인창 취소는 브라우저 제어 제한으로 최종 확인하지 못해 화면 검증 일부 대기. PRD 전체 기능·평가 품질 승인·파일럿 완료와 구분.

## 구현한 범위

검증된 users/sessions 패키지를 재사용하는 규칙 기반 요청 해석과 승인된 세 사고 과제 구성. 초·중·고급 정보 공개 수준, 고정 업무 조건 확인, 과제별 배점과 계산 없는 제출, 누적 일반 대화·임시 근거 코칭, 선택 가능한 SQL 결과 자동 코칭, 호출 상한·버전 재개, 운영 이벤트·사용량·출제 상태 집계·JSON 내보내기, 훈련 삭제 API와 확인 UI.

새 데이터 생성·적재, 임의 분야·목표의 자유 생성, 다양한 데이터 상황·의미적 중복 판정, 학습 상태 편집, 사람 판정 기반 전체 지표는 후속 작업이다. 자동 코칭은 현재 SQL 결과 행동에 연결했다. 질문은 직접 요청하고 제출 뒤 자동 제안은 후속 범위다.

## 자동 검증

- 전체 실제 PostgreSQL 테스트: 108개 통과. 기존 97개와 신규 11개. 기존 테스트의 사용 중단 예정 라이브러리 경고 2건이 있으며 테스트 실패는 없음.
- 마지막 내보내기 수정 후 관련 계약·DB 테스트 10개 추가 실행, 모두 통과.
- scripts/verification/verify_request_training.py는 매 실행 새 recorder 스키마를 만들고 테스트 프로세스의 search_path를 그 스키마로 제한한다. 종료 후 자신이 만든 스키마만 제거해 사용자 기록과 분리한다. 학습 DB는 읽기 조회·기존 검증 패키지 기반이다.
- 요청 충돌·재전송, 세 유형의 고정 계획, 비공개 필드 차단, 관측 기준의 실제 SQL·독립 계산 대조, 실패·취소·재시작 시 미공개, 계산 없는 평가·ID 참조, 임시 코칭·원문 비수집, 삭제 후 요청·이벤트 제거를 검증했다.
- 신규 리뷰의 비공개 기준 수치 노출 차단과 Gemini가 반환한 실제 사용량 전달을 검증했다. 숫자 필터는 일부 노출 방지이며 의미적 품질 승인 전체를 대신하지 않는다.
- Python 컴파일·JavaScript 문법 검사 통과.

## 실제 화면·모델

- 초급 계산 요청 → 패키지 v2 출제 → 실제 SQL → 선택 저장 → 임시 근거 코칭 → 보고서 v1 → 실제 Gemini 리뷰 → 수정 v2 제출 → 새로고침·재개 확인.
- 실제 집계는 대상 165명·미재접속 50명·관측 제외 34명·미재접속률 약 30.3%. 실제 실행 근거로 확인했으며 출제 수치를 임의 작성하지 않았다.
- 새로고침 후 임시 코칭과 SQL 편집기는 비었고, 선택 저장·초안·연결 근거·보고서·리뷰는 보존되었다.
- 고급 업무 요청 구체화 과제는 처음에 기간·관측 상세를 숨기고 조건 확인 버튼에서 고정 사실을 공개했다. 일반 대화·공개한 조건·보고서·리뷰는 서버 재시작 후 복구되었다.
- SQL 없이 분석 설계를 제출하고 현재 모델의 4개 항목 리뷰를 받았다. SQL 미제출 항목은 배점에 없으며 서버 총점은 75점이었다.
- 중급 분석 오류 수정 과제의 공개 초안 SQL을 실제 실행. JOIN 결과 521행에 자동 코칭이 연결되어 세션 행 수를 유저 수로 해석하는 오류를 설명했다. 이 응답은 임시 처리되었다.
- 실제 모델 호출 총 5회: 직접 코칭 2회, 리뷰 2회, 자동 코칭 1회. 모두 완료, 사용량 누락 0건. 시험용 입력이며 학습자 파일럿으로 세지 않는다.
- 매출 요청은 지원 범위·대안을 안내하고 입력을 유지했다. 기존 v1 훈련의 재개 API도 확인했다.
- 운영 집계의 실제 호출·누락 수 표시와 JSON 다운로드 확인. Blob 방식은 다운로드 감지가 실패해 서버 Content-Disposition 응답으로 수정 후 실제 파일을 내려받았다. 이벤트 허용 목록에 SQL·행·대화·프롬프트·응답 원문이 없음을 확인했다.
- 실제 브라우저 error/warn 로그 없음(확인 시점). 선택 탭 hover 시 글자 대비 문제를 수정했다.
- 삭제 API는 실제 연결 기록 제거와 404·집계 제외까지 확인. 화면 삭제 버튼의 확인창 조작 중 브라우저 제어가 응답하지 않아 취소·유지의 최종 화면 확인은 대기다. 새 탭에서 핵심 화면은 정상 열렸다. 사용자가 확인할 행동: 검증용 훈련에서 ‘훈련 삭제’ → ‘취소’를 선택하고 목록에 남는지 확인.
- 검증용 새 훈련 3개는 API로 정리했으며 기존 사용자 훈련·공유 패키지는 보존했다. 실제 이벤트 표본은 request-training-first-use-events.json에 보관.

## 품질 제한과 다음 개선

계산 리뷰는 실제 근거를 인정했지만 보완점에 세그먼트 분석을 제안했다. 설계 리뷰에도 더 구체적인 지표 예시 제안이 있었다. 불필요한 추가 요구와 수준 판정의 정확성은 실제 반복 표본·사람 검토로 개선해야 한다. 총점이나 호출 성공을 평가 품질 승인으로 세지 않는다.

사용자 실사용에서 요청 해석·과제 다양성·난이도·코칭 개입 정도를 먼저 확인하고 수정한다. 그 뒤 신규 데이터 생성 흐름, 더 다양한 목표·판단·상황, 전체 품질 지표·다른 PC·ARM·학습자 5명 파일럿을 진행한다.

## 환경 복구

Docker Desktop이 오래된 dockerInference·engine.sock 통신 파일 접근 오류로 시작하지 못했다. Docker/run과 docker-secrets-engine의 통신 폴더를 동일 부모의 날짜 포함 백업 이름으로 보존하고 함께 재시작해 복구했다. DB 볼륨·패키지 삭제나 공장 초기화는 하지 않았다. 새 앱은 http://127.0.0.1:8087 에서 실행 중이다.
