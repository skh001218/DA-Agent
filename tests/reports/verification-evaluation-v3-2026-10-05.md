## 실제 변경

1. 새 과제 출제 시 공개 조건·핵심 오류·4등급 조건과 배점을 고정하고 불변 평가 해시에 포함한다. 접속과 adaptive 경로 모두 v3를 사용한다. 과제 목표에 시간 조건이 없는 adaptive 정의에 기간 조건을 일괄 요구하지 않는다.
2. AI는 조건별 met/missing/error/unverifiable, 이유, 제공된 출처 경로만 반환한다. 등급·배점·총점·원문 발췌를 생성하지 않는다. 서버가 실제 제출/저장 실행의 원문을 연결하고 없는 출처·필수 출처 누락을 차단한다.
3. 서버가 보류→내용 없음0→핵심 오류1→필수 누락2→추가 조건 충족4→기본 충족3 순서로 계산한다. 정의·계획·해석·다음 행동은 각각 독립 조건을 사용한다. 마지막 결론 우선과 명시 철회 규칙은 조건 판별 프롬프트에 포함한다.
4. SQL은 실제 선택 저장 실행·완전성·고정 집계 검산으로 판단한다. 실행 없음0, 고정 계약과 결과 불일치1, 완전한 결과에서 고정 필수 열 일부만 누락하고 제출 부분을 검산할 수 있으면2, 잘림/계약 없음/알 수 없는 출력은 보류다. 4등급에는 실제 실행 출처가 필요하다. 보류를0으로 바꾸거나 배점을 재분배하지 않는다.
5. 항목 보류가 있으면 total_score=null, 확정 점수·확정 배점·항목별 보류를 표시한다. 설계는 SQL 미적용이다. AI 설명만 비공개 정보 검사에 전달하고 서버 점수·공개 기준·검증된 발췌의 우연한 수치 일치는 노출로 보지 않는다.
6. 새 리뷰의 평가·규칙·프롬프트 버전을 저장하고 품질 반복 도구에도 연결한다. 총점이 보류여도 핵심 오류 조건 판정의 회차별 변화를 탐지한다. 기존 과제는 기존 frozen_evaluation·리뷰 버전으로 평가하며 소급 변경하지 않는다.

## 남은 품질 실패

최종18회에 형식 오류는 없지만 전체 품질 verdict=fail·semantic_approval=false다. 핵심 오류 표본에서 analysis_approach가1→4→1, next_actions가3→4→3으로 달라졌다. 핵심 오류 조건도 error/met으로 바뀌었다. SQL은 기준 출력 형태가 없는 JOIN 행 집계라 보류하며 총점 범위는null이다. 이를0점 편차나 안정화 성공으로 표시하지 않는다.

근거 누락 표본은 확정 총점과 항목 등급이 같아도 interpretation의 핵심 오류 조건이error/met으로 달라졌다. 새 검출 규칙은 이 변화도 조사 대상으로 남긴다. 또한 해당 표본의 problem_definition은1로 판정됐으나 v3 문서의 ‘평가할 정의 자체가 없음’인0과 구분이 적절한지 사람 검토가 필요하다. 조건 판별과 출처의 의미적 연결은 단순 출처 존재 검사로 보장되지 않는다.

서버는 같은 조건 상태를 항상 같은 점수로 변환한다. 다음 개선은 AI가 계획/실행을 혼동하는 조건 판별과 누락/오류 구분을 대상으로 하고, 기존 최종 주장·출처·조건 상태를 고정해 비교해야 한다. v3 구현 완료와 전체 평가 품질 완료를 구분한다. 기존 PRD5/11·Spec010 2/5 유지, v3 세부 구현/검증은 해당 Spec 표에서 추적한다.
