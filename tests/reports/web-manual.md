# 웹 핵심 흐름 검증

실행: Docker Compose 앱에서 제공하는 루프백 URL을 브라우저로 연다. 콘솔 오류와 네트워크 응답을 함께 확인한다.

1. 신규 훈련을 시작한다. 문제, 데이터 사전, 가입 범위·수집 완료 경계와 고정 버전이 표시되는지 확인한다.
2. 문제 정의를 입력하고 `저장됨`을 확인한다. 새로고침 후 같은 URL의 훈련과 서술 입력이 복구되는지 확인한다.
3. SQL A와 B를 실행한 뒤 A만 기록에 저장한다. SQL 편집기를 수정하고 A의 저장 SQL이 실행 당시 원문인지 확인한다. 새로고침 경고를 승인하면 A만 복구되고 B와 편집기는 사라져야 한다. 브라우저 localStorage/sessionStorage에 SQL·결과가 없어야 한다.
4. 정상 0행, 문법 오류, 쓰기 금지, 시간 제한, 미리보기 잘림을 각각 확인한다. 전체 미확보·전체 행 수 미확인과 0행 성공이 구분되어야 한다.
5. 실행 저장 네트워크 실패 후 결과가 남고 재시도 가능해야 한다. 동일 request_id의 재시도에 중복 기록이 없어야 한다. 임시 실행 만료 후 저장은 재실행 안내를 보여야 한다.
6. 별도 탭에서 같은 훈련을 수정해 초안 충돌을 만든다. 기존 화면 입력을 유지하고 `최신 수정 번호로 내 입력 저장`을 명시적으로 선택하기 전 덮어쓰지 않아야 한다.
7. 발견사항을 빈 줄로 두 개 작성하고 주장별 저장 성공 실행을 연결한다. 보고서를 제출하고 새로고침 후 제출본·연결이 보존되는지 확인한다. 저장 오류나 실행 실패를 근거 선택 목록에 표시하면 안 된다.
8. 제출본 리뷰 요청 실패 후 제출·근거가 보존되고 재시도 가능해야 한다. 해당 제출본을 수정하고 새 버전으로 제출한 뒤 이전 제출본·리뷰가 남아야 한다.
9. 방향/지표/SQL 구조 힌트와 명시적인 해설 공개를 확인한다. 서버 인증 차단 상태에서도 SQL·저장·보고서·힌트를 계속 사용할 수 있어야 한다.
10. 모바일 너비에서 SQL, 실행 결과의 가로 스크롤, 보고서 입력과 핵심 버튼을 사용할 수 있어야 한다. SQL 결과·문제·리뷰에 HTML 문자열이 와도 화면에 문자로 표시되어야 한다.

이 파일은 검증 절차이며 실제 화면 검증 완료 기록이 아니다. 통합 후 실행 결과를 별도로 기록한다.
