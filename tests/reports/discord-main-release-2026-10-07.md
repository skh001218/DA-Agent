- 사용자 요청: 기능 브랜치 수정 → 테스트 → PR → main 병합 → 해당 커밋 배포 → 실제 동작 확인을 프로젝트에 적용.
- 사용자 선택: main 기준 배포 명령 실행. 이 PC에 GitHub 실행기는 등록하지 않는다.
- 기존 운영 Python 소스 63개는 변경 전 main과 일치했다. 이전 이미지는 Git 커밋 라벨·실행 파일 지문 기록이 없었다.
- 표준 프로젝트 구조는 모두 존재하며 폴더 이동·삭제 없음.

## 구현

- PR·main 대상 GitHub CI: 전체 자동 검사, 전용 PostgreSQL의 Discord DB 검사, 커밋이 표시된 봇 이미지 빌드·지문 확인.
- 배포 명령은 main 이력과 최신 세 CI 성공을 요구하며 `git archive`의 해당 커밋만 이미지 소스로 사용한다.
- 이미지·실행 소스 지문 및 전체 Git SHA를 기록하고 봇 시작·배포 후 검사한다.
- 진행 중 봇 요청·동시 배포·다른 운영 변경을 감지하면 중단한다.
- 기존 환경·비밀 마운트·외부 영구 볼륨·네트워크를 보존하며 bot만 교체한다. 실패 시 이전 이미지·구성으로 돌아가 연결까지 확인한다.
- main 보호 규칙은 PR과 세 CI 성공을 필수로 설정한다. 단독 저장소 운영을 위해 타인의 승인 인원은 0명이며 테스트 요구사항은 관리자에게도 적용한다.
- [운영 절차](../../docs/discord-release-workflow.md), [Spec047](../../specs/047-discord-main-release-workflow.md), 프로젝트 AGENTS.md에 같은 흐름을 기록한다.

## 로컬 자동 검증

- 전체 기존 검사: 633개 통과 / 80개 생략.
- 배포 검사 추가 후 전체: 643개 통과 / 80개 생략.
- 복구·인증·Docker Desktop 경로 검사 추가 후 배포 검사: 15개 통과.
- 전용 DB를 제공하지 않은 기존 검사 80개가 생략됐다. GitHub CI의 전용 Discord DB 작업에서 관련 DB 흐름을 별도 실행한다.
- 소스 파일 편집·추가·삭제·경로 이탈 거절, main 커밋 제한, 최신 CI 결과 검사, 기존 외부 볼륨·환경 유지, 잠금, 시작 실패·복구 성공/실패 기록을 확인했다.
- PR #33: 전체 645개 통과 / 80개 생략, 전용 Discord DB 58개 통과, 이미지 검사 성공. PR·main 모두 성공 후 병합했다.
- PR #34: 기존 Git 인증을 메모리에서 재사용하도록 보완했다. 비로그인 API 한도 때문에 첫 배포 시도가 CI 조회 단계에서 중단된 후, 검사를 우회하지 않고 수정 PR·main 검사를 통과했다.

## 실제 운영·화면 검증 결과

- main `18aa6962af96b0fc798f35d917b0ba2f8a9d17fb` 배포 성공: 상태 verified, 실행 파일 81개 지문 일치, 재시작 0회.
- 기존 환경 변수·비밀 마운트·영구 볼륨·외부 네트워크 일치. DB 두 개와 웹 앱은 컨테이너 ID까지 동일하다. 마운트 경로의 Windows/VM 표시 차이는 호스트 경로로 정규화해 동일 원본임을 확인했다.
- Docker Desktop이 재생성 후 `/run/desktop/mnt/host/c/...`로 표시하는 경로를 Windows 호스트 경로로 변환하도록 보완하고 자동 검사와 실제 재배포 구성 생성을 확인했다. 환경 값의 달러 기호도 Compose가 치환하지 않도록 보존한다.
- 커밋 인자를 의존성 설치 이후에 배치해 반복 빌드에서 글꼴·Python 의존성 캐시를 사용할 수 있게 했다. 이미지 라벨·지문 요구는 유지한다.
- 사용자가 선택한 별도 SQL 과제를 실제 `/training` → `/sqlrun` → `/submit`으로 확인했다. [포럼 검증](discord-single-post-2026-10-07.md): 11개 섹션이 첫 메시지 임베드 2개에 표시되고, `/resume` 후 같은 글·평가 1개·영구 답글 0개·기록 지문이 유지됐다. PDF 버튼에서 다운로드한 3페이지 파일의 전체 평가 항목을 확인했다.
- 최종 운영 커밋은 배포 후 `python scripts/deploy_discord.py --status` 및 `.local/releases/current.json`에서 확인한다. 위 커밋은 기능 화면을 처음 확인한 커밋이다. 운영 보완·검증 기록도 PR·main CI를 거쳐 해당 커밋으로 다시 배포한다.

## 운영 확인 기준

main 커밋에 세 CI 성공 확인 → 배포 명령 실행 → Discord ready → 실행 소스 지문과 main 커밋 일치 → 본인 저장 평가 `/resume` → 같은 결과 포스트 첫 메시지·PDF 다운로드 → 재시도 중복 답글 없음.

민감 구성과 실제 배포 기록은 ignored `.local/releases/`에만 보관하며 GitHub 문서에는 커밋·검증 결과만 기록한다.
