# PRD-v2 후속 백엔드 통합 검증 기록

- 기록일: 2026-10-04 (Asia/Seoul)
- 대상: Spec 008~013. 기존 Spec 001~007의 완료 기록과 분리한다.
- 자동 검증과 실제 DB 실행은 구현 증거다. 사람의 의미적 품질 승인·학습 효과·출시 완료를 대신하지 않는다.
- 최종 코드 revision: 통합 담당자가 마지막 실행 snapshot의 `code_revision`으로 갱신한다.

## 재현 명령과 안전한 실행 경계

```powershell
# 환경·코드·버전만 확인: DB 테스트나 AI 호출을 시작하지 않음
python scripts/verify_v2_release.py --snapshot-only

# 모든 테스트, 실제 DB 테스트는 명시적으로 건너뜀
python scripts/verify_v2_release.py

# 기록 DB 접속 설정이 준비된 환경: 새 recorder 스키마만 생성/정리
python scripts/verify_v2_release.py --db

# 최신 src/tests/scripts를 복사한 기존 컨테이너에서 통합 회귀 실행
python scripts/verify_v2_release.py --docker da-agent-app-1 --tests /tmp/da-tests/tests --output tests/verification-v2-final.json
```

Docker 재검증 전에 통합 담당자가 현재 소스를 컨테이너에 반영했는지 확인한다. host snapshot의 revision과 실행 컨테이너 코드가 일치하는지도 기록한다. 같은 앱·기록 DB에 대한 재시작·취소·삭제 검증은 동시에 실행하지 않는다. 기본 runner는 `scripts/verify_request_training.py`이며 UUID를 붙인 `verify_request_` 스키마를 생성하고 자신의 스키마만 제거한다. 사용자 기록·공유 패키지·DB 볼륨을 초기화하지 않는다. 생성 적재 테스트는 별도 역할의 GENERATOR_DSN이 필요하며 키나 접속 문자열을 검증 기록에 복사하지 않는다.

harness는 OS·CPU 아키텍처·Python·Docker·연결 가능 시 PostgreSQL 버전, 코드 SHA와 작업 트리 변경 여부, 소스에 명시된 버전 상수와 파일 SHA256을 JSON으로 기록한다. Docker 모드에서는 실제 컨테이너의 OS·CPU·Python·기록 DB 버전·파일 해시와 host 일치 여부도 기록한다. 실제 현재 모델 호출은 하지 않으며 모델이 설정되어 있다는 사실을 호출 성공으로 세지 않는다. pytest 출력은 수치 요약만 추출하고 traceback·SQL·결과·대화·환경 변수·키·접속 문자열을 저장하지 않는다. 실패 원인을 조사할 때도 원문을 보고서에 붙이지 않는다.

## PRD의 11개 개발 작업별 근거 대조

아래 표는 검증 체크리스트다. 코드 존재만으로 완료 표시하지 않으며, 통합 담당자가 마지막 자동·DB·화면 증거와 연결해 상태를 갱신한다.

| 개발 작업 | 확인할 증거 | 별도 남은 검증 |
| --- | --- | --- |
| 자연어 훈련 요청 | 명확·부족·지원 밖·명시값 충돌·SQL 자료 포함 요청, 추가 확인, 재전송 회귀 | 자유 표현 표본의 실제 화면 안내 |
| 문제 설계와 다양성 | 서로 다른 사고 과제, 최근 5개 비교·사용자 요청 반복 분리 | 같은 주제 3개 쌍의 의미적 차이를 사람 판정 |
| 난이도 설계 | 초·중·고급 정보 공개, 고급의 필수 자료·분석 가능성 검사 | 모호함·대안 인정·난이도 적합성 사람 판정 |
| 데이터 생성과 적재 | 작은 신규 접속 데이터, PK/FK/시간·해시·재현·실제 적재 회귀 | 생성 역할 환경을 포함한 마지막 재실행 |
| 출제 전 검증 | 독립 집계와 실제 SQL 대조, 검증 실패·취소 미공개 | 취소 직전 공개·재시작 경계의 실제 연결 증거 |
| 훈련 진행 판단 | 정의 부족·집계 오류·가설 충돌·타당한 대안·제출·도움 표본 | 현재 모델의 각 표본 3회 실행과 사람 승인 |
| 대화와 학습 상태 | revision 충돌·선호·사용자 이견, 임시 원문 비수집, 삭제 후 근거 무효화 | 실제 새로고침·서버 재시작 화면 복구 |
| 상황별 힌트와 평가 | 기준·근거·대안·계산 없는 과제, 형식 오류·비공개 노출 회귀 | 현재 모델 반복 안정성·오진·미탐·대안 거부 사람 판정 |
| 대화와 분석 화면 | 요청→출제→풀이→근거 저장→대화→제출→리뷰→수정·재개 | 통합 실제 화면 기록, 삭제 취소·확정 검증 |
| 다음 훈련 추천 | 실제 수행·도움·형식 이력, 이견 반영, 삭제·최근 5개 중복 회귀 | 추천 선택 후 실제 출제 연결 화면 |
| 품질 지표 수집과 로그 관리 | 8종 분모·결측·중복·p95·Seoul 기간·버전·JSON/CSV, 고정 오류 코드·삭제 회귀 | 사람 판정 입력·필터·다운로드·보관 만료 실제 화면 |

## 완료로 올리지 않은 외부 검증

- 의미적 품질 승인: 검토자·규칙 버전·표본·판정 시각·결과가 아직 이 문서에 없다. 확인 대기.
- 현재 모델 반복 평가: 고정 표본 각 3회, 유효 형식·핵심 판단 유지·총점 범위 10점 이하 및 오진/노출 여부를 사람이 확인해야 한다. fixture로 대체하지 않는다.
- 다른 PC: 동일 코드·패키지로 Docker 실행→요청→실제 SQL→리뷰→재개 확인 대기.
- ARM: 별도 장비·아키텍처·실행 결과 확인 대기. ARM 지원 검증을 주장하지 않는다.
- 학습자 5명 파일럿: 실제 참가자 확인 대기. 개발자·자동 테스트·fixture를 참가자로 세지 않는다. 목표는 4명 이상 직접 개입 없이 리뷰까지 완료하고 다음 수정 행동 설명, 3명 이상 놓친 핵심 조건을 수정 제출에 반영. 보완 필요자가 3명보다 적으면 분모 한계와 수정 효과를 함께 기록한다.
- 제품 출시 판정: 위 외부 검증과 PRD 12절 조건의 개별 근거 대조가 남아 있다. 자동 테스트 통과만으로 완료 처리하지 않는다.
