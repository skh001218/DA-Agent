# Game Data Analyst Trainer 향후 확장 계획

> 2026-10-04: 현재 계획은 [요청 기반 분석 훈련 PRD](PRD-v2.md)가 우선한다. 아래 문제 2·3 별도 착수와 80% 기준은 폐기했다. 시나리오 생성과 난이도 조절은 새 PRD의 핵심 범위로 이동했으며, 아래 내용은 이전 확장 아이디어로 보존한다.

작성일: 2026-10-02  
상태: 아이디어 보관 및 우선순위 초안

원래 논의한 아이디어 중 [1차 PRD](PRD-v1.md)의 MVP 필수 범위에서 분리한 기능을 보관한다. 문제 2·3은 2026-10-03 사용자 결정에 따라 MVP 구현 진행도가 80% 이상이 되면 착수한다. 다른 아이디어는 구현 약속이 아니며, MVP의 사용성과 평가 신뢰성을 확인한 뒤 필요한 항목을 골라 별도 명세로 구체화한다.

## 1. 확장 판단 기준

기능 추가는 기존 훈련의 막힘을 해결하거나 새로운 분석 역량을 연습하게 할 때 검토한다. 문제 수와 데이터 규모 자체를 성과로 삼지 않는다. 새 시나리오에도 재현 가능한 데이터, 검증된 기준 결과, 근거 중심의 루브릭이 필요하다.

문제 2·3의 착수 기준은 PRD 16.1절의 MVP 구현 작업 10개 중 8개 이상 구현·검증 완료다. 확장 작업은 MVP 진행률의 분모에서 제외하고, 남은 MVP 검증·파일럿을 병행한다. 80%는 확장을 시작하는 기준이며 출시 완료 기준은 아니다.

문제 2·3 외의 아래 우선순위는 초기 제안이다. 가까운 확장은 MVP 검증 후 검토하고, 중기 확장은 콘텐츠와 평가 체계가 안정된 뒤 검토한다. 장기 항목은 운영과 비용 검토가 필요하다.

### 확정된 콘텐츠 확장: 문제 2·3

| 문제 | 학습 목표 | 착수 시 정할 사항 |
| --- | --- | --- |
| 2. 튜토리얼 완료율 감소 분석 | 플랫폼·가입 버전·단계별 변화와 유입 구성 구분 | 데이터 기간·규모, 단계·재시도 규칙, 생성 조건, 기준 결과와 평가 기준 |
| 3. D7 리텐션 하락 분석 | 관측 완료 코호트, 튜토리얼과 재방문의 관련성, 인과 주장 제한 | 데이터 기간·규모, 재방문 생성 조건, 문제 2와 데이터 공유 여부, 기준 결과와 평가 기준 |

두 문제 모두 tutorial_attempts와 필요한 접속 데이터를 생성하고 기준 SQL·힌트·루브릭·데이터 품질 및 화면 흐름을 검증한 후 출제한다. PRD 6~8절의 시나리오·지표·품질 조건을 따른다.

## 2. 훈련 분야 확장

| 분야 | 보관할 문제 아이디어 | 필요한 데이터와 주의점 | 검토 시점 |
| --- | --- | --- | --- |
| 퍼널 | 지난주보다 튜토리얼 완료율이 12% 감소한 이유 | 감소율과 %p를 구분하고 생성 후 실제 수치 확정 | 가까운 확장 |
| 콘텐츠 | 특정 스테이지의 이탈과 재시도 증가 | 스테이지 진입, 결과, 소요 시간, 난이도, 유저 성장 | 가까운 확장 |
| 매출 | ARPPU 급감, DAU 유지 중 매출 20% 감소 | 구매, 상품, 환불, 결제 유저 정의, 통화와 집계 기간 | 중기 확장 |
| 경제 | 이벤트 보상 과다 지급과 골드 보유량 증가 | 획득과 소모, 잔액 일관성, 재화 종류, 이벤트 참여 | 중기 확장 |

| 이벤트 | 이벤트 참여율이 예상보다 낮음 | 노출, 참여 자격, 진입, 보상 수령, 기간과 분모 | 중기 확장 |
| A/B Test | 신규 보상안의 효과와 부작용 | 배정 단위, 실험군, 노출, 성과, 표본 비율과 검정 | 중기 확장 |
| 유저 생애주기 | 신규와 복귀 유저의 행동 차이 | 복귀 정의, 장기 접속 이력, 유저 구성 변화 | 중기 확장 |

표의 수치는 원래 아이디어의 예시이며 데이터로 검증된 결과가 아니다. 경제 시나리오에서 골드 보유량 증가만으로 골드 가치 하락을 단정하지 않는다. 가치의 의미와 이를 관측할 거래 또는 구매 행동부터 정의해야 한다.

## 3. 난이도 체계 확장

| 난이도 | 훈련 내용 | 예시 요청 |
| --- | --- | --- |
| Junior | 지표와 기간을 주고 정확한 집계를 연습 | 신규 유저 튜토리얼 완료율을 구하세요. |
| Intermediate | 현상을 주고 원인 후보와 세그먼트를 탐색 | 완료율이 하락했습니다. 어느 구간의 변화인지 분석하세요. |
| Advanced | 업무 요청부터 정의하고 분석 범위를 협의 | PM이 업데이트 후 반응이 좋지 않다고 합니다. 무엇을 확인할까요? |

MVP는 문제 1의 기초 지표 계산을 다루고, 문제 2·3에서 Intermediate 수준의 변화 분석을 추가한다. Advanced에는 이해관계자에게 확인할 질문, 지표 선택 이유, 시간 제약에서의 우선순위, 결론의 불확실성을 평가할 기준을 추가한다. 모든 시도에 동일한 선형 단계를 강제하지 않는다.

## 4. RPG 로그 확장

기존 아이디어의 접속, 전투, 경제, 성장 로그를 장기적인 가상 RPG 데이터 모델로 발전시킨다.

| 로그 영역 | 확장 후보 | 연결할 학습 |
| --- | --- | --- |
| 접속 | sessions, 복귀 구분, 접속 환경 | 리텐션, 유저 생애주기 |
| 전투 | battle_logs, 캐릭터, 스킬, 아이템, 티어 | 밸런스, 전투 실패 원인 |
| 경제 | economy_logs, 재화 획득 및 소모, 잔액 | 인플레이션, 보상과 소모 구조 |
| 성장 | growth_logs, 레벨, 장비, 강화 | 성장 정체, 콘텐츠 진입 조건 |
| 콘텐츠 | stage_logs, 시작, 결과, 플레이 시간 | 이탈, 난이도, 재시도 |
| 구매 | purchase_logs, 상품, 가격, 환불 | 매출, 결제 전환, ARPPU |

20~30개 문제 목록은 이 스키마 전체를 먼저 완성하는 대신, 새 학습 목표별로 필요한 로그를 추가하면서 작성한다. 10만~100만 이벤트 규모의 데이터는 생성 품질과 실행 성능을 확인한 뒤 검토한다.

## 5. 시나리오 생성기

원래 아이디어의 Scenario Generator를 중기 확장으로 보관한다. 분야, 난이도, 사건 템플릿을 선택해 데이터를 생성하는 방식이다.

시나리오 패키지는 공개 상황, 비공개 생성 사건, 데이터셋과 seed, 기대 분석 과정, 핵심 및 선택 발견사항, 기준 쿼리, 힌트, 평가 기준을 묶는다. 예를 들어 이벤트 보상 과다 지급 사건에 이벤트 참여자의 획득량과 재화 보유량 증가를 설정할 수 있다.

도입 조건은 고정 시나리오 템플릿의 품질이 먼저 검증되는 것이다. 생성 후 자동 품질 검사와 기준 결과 검증을 통과한 패키지만 출제한다. LLM은 상황 문구와 설명 변형을 도울 수 있지만 데이터의 진실과 기준 수치는 생성 코드와 DB 계산으로 관리한다. 동일 사건을 반복해 정답을 암기하지 않도록 원인이 다른 변형도 준비한다.

## 6. 실제 공개 데이터와 API

| 후보 | 훈련 가능 영역 | 도입 전 확인할 사항 |
| --- | --- | --- |
| 공개 게임 데이터셋 | 판매, 리뷰, 플레이 기록, 매치 분석 | 출처, 라이선스, 기간, 누락과 편향, 재배포 허용 |
| Riot 계열 매치 데이터 | 챔피언, 패치, 티어, 게임 시간별 승률 | API 접근 조건, 호출 제한, 저장 정책, 수집 표본 |
| Steam 계열 데이터 | 게임별 통계, 리뷰와 활동 변화 | 제공 범위, 이용 조건, 수집 가능성과 지표 정의 |

위 후보는 조사 대상이며 현재 제공 범위나 이용 가능성을 확인한 상태가 아니다. 도입 시 공식 자료를 확인한다. 외부 API는 수집한 스냅샷으로 훈련해 같은 문제의 결과가 계속 바뀌지 않도록 한다.

실제 데이터에는 확정 원인이 없는 경우가 많으므로 정답 맞히기보다 근거와 한계 중심으로 평가한다. 리텐션, 내부 매출, 튜토리얼, 경제 데이터의 가용성을 가정하지 않는다. Simulation 70~80%, 실제 데이터 20~30%라는 원래 비율은 채택하지 않고 학습 목표와 확보 가능한 데이터에 따라 구성한다.

## 7. 면접과 리뷰 확장

면접 모드는 매출 감소 같은 질문에 사용자가 답하면 추가 질문을 이어간다. 지표 분해, 첫 확인 항목, 우선순위, 대안 설명을 평가하며 대화 형식의 별도 루브릭이 필요하다. SQL 실습과 목적이 달라 MVP 이후 별도 흐름으로 설계한다.

시니어 리뷰의 기본 형태는 MVP에 포함된다. 이후 사람의 리뷰와 비교한 평가 보정, 이전 시도와의 성장 추적, 역량별 약점에 맞춘 다음 문제 추천을 검토한다. 수정 보고서 점수 상승을 새로운 문제에서의 독립 수행 능력과 동일하게 취급하지 않는다.

학습자가 작성한 쿼리와 보고서를 포트폴리오로 내보내는 기능도 보관한다. 합성 데이터 사용과 힌트 및 해설 참조 여부를 표시할 수 있어야 한다.

## 8. 운영과 개인화 확장

- 오늘의 분석 문제와 정기 출제는 충분한 검증 문제와 중복 방지 정책을 확보한 후 검토한다. 현재 자동화는 생성하지 않는다.
- 계정, 클라우드 저장, 다중 사용자, 강사용 관리 화면은 실제 운영 수요를 확인한 뒤 검토한다.
- 막힌 지점에 따른 개인화 힌트는 사용자 선택형 힌트의 파일럿 결과를 바탕으로 설계한다.
- SQL 입문 보조 과정과 Python 또는 시각화 분석은 핵심 분석 훈련이 안정된 뒤 검토한다.
- 공개 배포와 과금은 LLM 호출 비용, 데이터 및 API 이용 조건, 학습 기록 관리 정책을 확정한 뒤 별도 요구사항으로 작성한다.

## 9. 다음 확장을 선택하는 절차

문제 2·3은 MVP 구현 진행도 80% 이상에서 착수하되 남은 MVP 작업을 병행한다. 다른 확장은 MVP 파일럿에서 막힌 단계와 리뷰 오류를 먼저 개선한 뒤 새로운 분야 하나를 골라 문제, 최소 추가 로그, 기준 결과, 힌트와 루브릭을 함께 설계한다. 검증된 콘텐츠가 쌓이면 생성기와 개인화를 검토하고, 실제 데이터 연결은 출처와 학습 가치가 분명한 문제에 한해 추가한다.
