# project-loop: 목적을 향해 한 바퀴씩 진행하기

## 되뇌는 문장

> **목적 → 요소 → 빠진 것 검토 → 구현 방법 → 구현 → 오류 확인 → 수정 → 목적과 비교 → 개선 탐색 → 다시 목적**

프로젝트를 시작하거나 방향을 잃었을 때 이 문장을 보여주고, 지금 어디에 있는지 짚는다. 매번 전체 과정을 처음부터 다시 하거나 이미 끝난 단계를 형식적으로 반복하지 않는다. 새로 발견한 정보가 목적이나 요소를 바꾸면 해당 단계로 돌아간다.

## 한 바퀴의 확인 질문

1. **목적 정하기:** 누구의 어떤 불편을 해결하고, 무엇이 되면 성공인가? 목적은 참가자의 말로 정한다.
2. **필요한 요소 정리:** 성공에 꼭 필요한 입력, 기능, 결과, 제약은 무엇인가? 이미 있는 자료와 아직 필요한 자료를 구분한다.
3. **AI와 빠진 부분 검토:** 사용자 입장, 빈 입력, 실패 상황, 확인 방법 중 놓친 것이 있는가? AI의 제안은 후보로 제시하고 참가자의 목적을 임의로 바꾸지 않는다.
4. **구현 방법 정리:** 각 요소를 어떤 순서와 방식으로 만들고, 첫 번째로 눈으로 확인할 결과는 무엇인가? 기술 용어는 쉬운 말로 풀어 쓴다.
5. **함께 구현:** 합의된 범위부터 실제 결과물을 만든다. 참가자에게 코드 수정을 맡기지 않는다.
6. **디버깅:** 실제 실행에서 어떤 일이 일어나는지 확인하고, 관찰한 오류와 원인 추측을 구분한다. 디버깅은 오류를 찾아 원인을 좁히는 과정이라고 설명한다.
7. **수정:** 확인된 문제를 고치고 관련 동작을 다시 확인한다.
8. **목적과 일치하는지 검토:** 처음 정한 성공 조건을 실제 결과와 하나씩 대조한다. 통과하지 못한 항목은 구현·오류 확인·수정 단계로 되돌린다.
9. **개선 사항 탐색:** 목적을 충족한 뒤 실제 사용에서 아쉬운 점과 다음 개선 후보를 찾는다. 선택한 개선을 새 목적과 성공 조건으로 삼아 다음 바퀴를 시작한다.

## 사용할 때

- 현재 프로젝트의 목표, 기존 결정, 파일과 실제 동작을 먼저 살펴본다. 확인하지 않은 단계를 완료로 표시하지 않는다.
- 참가자에게 **현재 단계 / 이미 확인된 것 / 놓친 부분이나 남은 일 / 바로 다음 행동**을 짧게 보여준다. 질문이 필요하면 결과를 좌우하는 것 한 가지만 묻고, 가능한 작업은 계속한다.
- 각 단계의 산출물이 있으면 눈으로 확인할 방법을 알려준다. 목적과 일치하는지 검토할 때는 참가자의 실제 사용 결과를 반영한다.
- 진행 기록은 최상위 `작업일지.md`에 필요한 만큼 덧붙인다. 기존 결과물과 기록은 보존한다.
- 이 스킬은 진행 방향을 점검하는 길잡이다. 기획서 작성, 오류 해결, 개선 구현 등 구체적인 작업에는 해당 프로젝트 지침과 관련 스킬을 함께 적용한다.
