## 요청과 목적

Spec 033의 삭제 동작을 보관·잠금으로 대체한다. 완료된 과제 기록은 남기고 활성 목록을 정리한다. `/resume`은 완료 기록을 열람하며 보관 상태를 해제하지 않는다. 과거에 이미 삭제된 스레드는 복구할 수 없으며 완료 결과가 게시돼 있으면 새 공간을 만들지 않는다.

새 스레드는 `[중급 - 튜토리얼 완료율 변화와 우선 대응]`처럼 공개 문제명과 한국어 난이도를 표시한다. 본문 전체를 제목으로 사용하거나 모델을 추가 호출하지 않는다. 전체 제목은 40자 이내다. 같은 사용자·서버·부모 채널에서 같은 난이도와 표시 문제명이 반복되면 `[중급 #2 - 문제명]`, `[중급 #3 - 문제명]`으로 구분한다. 실제 사이드바에서 끝에 붙인 순번이 잘리는 것을 확인해 순번을 난이도 바로 뒤에 배치했다. 긴 문제명은 `…`로 줄이고 순번의 공간을 확보한다. 줄인 제목이 같아지는 경우에도 구분한다. 난이도가 다르면 별개 제목으로 센다. 뜻이 비슷하더라도 표시 제목이 다른 과제에는 순번을 강제로 붙이지 않는다.

이름과 순번은 스레드 생성 전에 DB에 예약하며 PostgreSQL 트랜잭션 잠금으로 동시 요청을 직렬화한다. 생성 실패·재시도·삭제된 진행 과제 복구에서 같은 저장 이름을 재사용한다. 다른 사용자의 이름은 별도로 센다. 기존 ID 제목을 일괄 변경하지 않는다.

완료 게시 후 과제 스레드와 부모 채널에 결과 링크를 남긴다. 보관·잠금 실패는 게시 실패와 구분하고 `/resume` 재시도를 안내한다. 본인 소유·서버·전용 스레드·최신 완료 평가를 확인하며 다른 사용자의 공간은 처리하지 않는다.

보관된 개인 스레드는 읽기 권한과 소유자 참가 상태를 확인하되 열람 과정에서 잠금 해제·보관 해제·불필요한 참가 요청을 하지 않는다. 완료 후 논의는 결과 포럼 댓글에서 이어간다. `/history`는 기록을 변경하거나 모델을 호출하지 않는다.
