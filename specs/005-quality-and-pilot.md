## 범위와 사용자 결정

사용자는 스크립트·검토표에 더해 앱 안에서 결과를 보는 검증 화면을 선택했다. 기존 로컬 단일 사용자 환경에서 운영자용 별도 화면을 제공한다. 별도 회원·역할 시스템은 추가하지 않는다. 학습 화면과 일반 코칭에는 평가 표본·기대 평가를 전달하지 않는다. 운영자 화면은 정답이 포함된 검증 자료를 표시하므로 학습 전에 보지 않도록 구분한다.

사용자는 결과를 더 시각적으로 보기 위해 선택했으며, 이후 사용자가 볼 필요가 없어지면 제거할 수도 있다고 설명했다. 페이지·JavaScript·CSS·운영자 API를 별도 모듈로 두고 훈련 리뷰의 공통 코드를 재사용해 화면 제거 시 핵심 훈련 흐름의 변경 범위를 줄인다.

## 평가 품질

- 문제 1의 정확한 분석, 중복 집계, 미관측 포함, 인과 과장, 올바른 대안 SQL 표본을 제공한다.
- 표본 SQL을 실제 PostgreSQL에서 실행하며 결과를 지어내지 않는다. 정확한 SQL과 대안 SQL은 패키지 기준 결과와 대조하고, 오류 표본은 정상 결과와 실제 차이가 있는지 확인한다.
- 기대 판정은 초기 제안으로 표시한다. 사람이 검토하며 AI가 자신의 품질을 최종 승인하지 않는다.
- 표본 v2부터 항목별 수준 허용 범위 제안을 함께 표시한다. 기존 실행 묶음의 표본 내용은 바꾸지 않는다.
- 명시적인 실행 버튼으로만 AI를 호출한다. 패키지·문제·데이터·표본·평가 규칙·모델 버전을 저장한다.
- 한 묶음은 5개 표본 × 3회다. 진행 중 상태와 완료된 호출을 저장하고 실패를 표시한다. 중단된 묶음을 성공으로 보지 않는다. 실패·중단 재시도는 새로운 묶음으로 보존한다.
- 점수 범위 10점 초과는 검토 필요, 실패 호출은 완료 미달이다. 사람이 각 회차의 필수 판정과 중대한 오류 여부를 확인해야 품질 통과로 표시한다.

## 파일럿

- 기존 훈련 시도에 P01 등 참가자 코드를 연결한다. 한 코드는 한 시도에 연결하고 평가 검증용 실행은 학습 시도 목록에 넣지 않는다.
- 훈련 시작·제출·리뷰 시각과 힌트·해설·저장 근거는 기존 기록에서 계산한다.
- 연결 이후 SQL 실행의 성공/오류 코드와 화면 단계 이동만 수집한다. 미저장 SQL·결과·코칭 질문은 파일럿 이벤트에 넣지 않는다.
- 도움 유무·도움 내용·중단 지점·학습자의 다음 수정 행동·검토자의 구체성 판정·핵심 조건 보완 판정을 저장한다. 실제 참가자의 답변을 대신 만들지 않는다.
- 최초·수정 보고서와 리뷰를 비교하고 JSON으로 내보낸다. 내보내기는 명시적으로 저장한 근거만 포함한다.
- 실제 참가자 5명 테스트와 사람이 검토한 AI 품질 통과는 구현 완료와 별도로 기록한다.

## 완료와 출시 검증의 구분

모의 AI를 이용한 실행·실패·UI 검증은 도구 동작 검증이다. 실제 모델의 15회 평가와 사람 판정, 실제 학습자 파일럿을 대신하지 않는다. 이 Spec의 구현 완료만으로 PRD의 평가 품질·파일럿을 완료 처리하지 않는다.
