## 목적과 범위

사용자는 Discord 스레드 `1557274382223540284`에서 자연어로 요청하면 현재 있는 데이터로 조회하고, 없는 자료는 빠진 정보를 구체적으로 안내하기를 원한다. `shop_profiles` 전체 조회는 실제 200행이 있어도 기존 집계 계약 때문에 거절됐으며, 판매 아이템 변화 요청은 아이템·가격·변경 이력 자료가 없는데 일반적인 지원 범위만 안내했다.

- 요청별 생성 분석 과제의 `/query` 및 동일 조회 경로를 확장한다. 고정 튜토리얼 과제의 기존 지표 계약은 유지한다.
- 자연어를 단일 PostgreSQL SELECT로 해석한다. 현재 세션의 공개 스키마로 표·컬럼·별칭·CTE를 검증한 뒤 기존 읽기 전용 실행기에서 실행한다. 시스템·외부 접근, 변경·잠금·재귀 조회는 거절한다.
- 원본 행, 컬럼 선택, 조건, 정렬, 여러 집계, 산술 비교, 공개 자료 연결을 허용한다. 모호한 기간·분모·단위는 확인한다. 원본 전체 요청에 임의 LIMIT·필터를 넣지 않는다.
- 필요한 자료가 없으면 부족한 항목과 현재 조회 가능한 표·컬럼을 안내한다. 없는 값을 생성하거나 다른 지표로 대체하지 않는다. 계산 방식 미지원 및 공급자 실패와 구분한다.
- 결과는 기존 10행 표 미리보기와 전체 수집 데이터 JSON 첨부로 제공한다. 기존 수집 시간·행 수·바이트 제한을 유지하며 불완전 결과를 전체 결과로 표시하지 않는다. 조회 SQL·실행 ID·데이터 버전·전체 저장 근거는 유지한다.
- 로컬 검증에서는 사용자 세션을 수정하지 않는다. 후속 배포 요청에 따라 PR·main 병합·운영 배포와 사용자의 기존 Discord 스레드에서 조회 검증을 진행한다.

## 완료 기준

1. 현재 실제 문제의 `shop_profiles의 전체 데이터를 조회해줘` 요청으로 200행을 얻는다.
2. 상점 판매 아이템의 전후 변화 요청에 판매 아이템 목록·변경 이력이 없음을 구체적으로 안내하고 SQL을 실행하지 않는다.
3. 숙련도 조건의 원본 조회 및 상점 구성별 초기·후기 소모 비교를 실제 DB 결과와 대조한다.
4. 존재하지 않는 표·컬럼, 여러 문장, 변경·잠금·시스템 SQL, 계획 변조를 실행 전에 거절한다.
5. 표 미리보기, 전체 데이터 첨부, 기존 집계 회귀와 실패 안내를 검증한다.
