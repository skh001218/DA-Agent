## 목적과 확정 사항

문제 1은 신규 유저의 이탈률을 계산하는 기초 문제다. 사용자는 게임뿐 아니라 다른 서비스에서도 발생하는 문제이기 때문에 이 주제를 선택했다. 문제 배경은 PRD의 가상 RPG를 유지하며, 가입 코호트와 재접속 여부를 이용하는 분석 방식은 다른 서비스에도 응용할 수 있다.

2026-10-03 사용자가 확정한 이탈 기준은 **가입 다음 날부터 7일 동안 한 번도 재접속하지 않은 신규 유저**다. 지표와 관측 조건 설계는 확정했지만 데이터 생성·SQL 실행·정답 검증은 아직 수행하지 않았다.

## 학습자에게 제시할 문제

> 지정된 가입 기간의 신규 유저 중, 가입 다음 날부터 7일 동안 한 번도 재접속하지 않은 유저의 비율을 구하세요. 해당 기간을 끝까지 관측할 수 있는 유저만 계산에 포함하세요. 분석 대상 유저 수, 이탈 유저 수, 이탈률과 계산 기준을 제출하세요.

출제 시 가입 기간의 시작·종료 시각과 데이터 수집 완료 경계를 함께 제공한다. 구체적인 날짜와 표본 수는 데이터 생성 설계에서 정한다. 이번 문제의 필수 제출 범위는 정확한 지표 계산과 조건 설명이다. 이탈 원인 규명이나 업데이트 전후 비교는 필수로 요구하지 않는다.

## 지표와 관측 조건

| 항목 | 확정 기준 |
| --- | --- |
| 지표 이름 | 신규 유저 D1~D7 미재접속 이탈률 |
| 분석 단위 | 고유 유저 1명 |
| 가입 코호트 | 제공된 가입 시작 시각 이상, 종료 시각 미만에 가입한 유저 |
| 시간대 | Asia/Seoul |
| D0 | 가입 시각이 속한 달력 날짜 |
| 관측 시작 | D1 00:00, 포함 |
| 관측 종료 | D8 00:00, 제외; D1부터 D7까지 총 7개 달력 날짜 |
| 재접속 | 관측 구간 안에 로그인 시작 시각이 있는 세션이 한 번 이상 있음 |
| 이탈자 | 관측 구간 안의 로그인 세션이 0회인 유저 |
| 분모 | 가입 코호트 중 D8 00:00까지 수집이 완료된 고유 유저 수 |
| 분자 | 분모에 포함된 유저 중 이탈자 수 |
| 이탈률 | 이탈자 수 ÷ 분석 대상 유저 수 × 100 |
| 중복 처리 | 세션이 여러 개여도 유저는 한 명으로 계산 |
| 관측 미완료 | 분모와 분자에서 모두 제외하고 제외 인원은 별도 표시 |
| 분모 0 | 이탈률을 계산 불가로 표시; 0%로 대체하지 않음 |
| 결과 표시 | 인원은 정수, 비율은 소수점 한 자리; 평가 계산은 반올림 전 값 사용 |

수집 완료 경계 T는 **T 미만의 데이터가 모두 수집되었다는 보장**을 뜻한다. 각 유저의 D8 00:00이 T 이하인 경우만 관측 완료로 판정한다. T를 마지막으로 기록된 세션의 시각으로 추정하지 않는다. 실제 저장 형식과 SQL 날짜 변환은 스키마 설계에서 정하되 이 조건을 그대로 유지한다.

D0에 여러 번 접속해도 이번 지표의 재접속으로 세지 않는다. D0에 시작해 D1까지 이어진 세션도 로그인 시작 시각이 관측 구간 밖이므로 재접속에 포함하지 않는다. 이는 접속 시작 로그를 기준으로 정한 운영상 정의이며 영구적인 서비스 탈퇴를 의미하지 않는다. D8 이후에 돌아온 유저도 D1~D7 미재접속 조건을 충족하면 이번 지표에서는 이탈자로 계산한다.

D7 당일에 접속하지 않았어도 D1~D6 중 접속한 적이 있다면 이탈자가 아니다. 따라서 이 지표를 `1 - D7 리텐션`으로 계산하면 안 된다.

## 계산 예시

가입일이 2026-09-01이면 관측 구간은 2026-09-02 00:00 이상, 2026-09-09 00:00 미만이다. 수집 완료 경계가 2026-09-09 00:00 이상일 때 평가 대상이 된다. 날짜는 모두 Asia/Seoul 기준이다.

관측 완료 유저가 100명이고 그중 D1~D7 재접속자가 65명이면 이탈자는 35명, 이탈률은 35.0%다. 이 수치는 계산을 설명하는 예시이며 생성 데이터의 정답이 아니다.

## 제출과 평가 기준

필수 제출물은 대상자 수, 이탈자 수, 이탈률을 계산한 SQL과 실행 결과, 가입 범위·시간대·관측 구간·관측 미완료 제외·중복 처리에 대한 설명이다. 관측 미완료 제외 인원도 별도 제시한다.

평가는 기준 SQL의 문자열이 아니라 대상 유저와 집계 결과가 정의에 맞는지 확인한다. 올바른 대체 쿼리를 인정한다. 반올림 전 분자·분모로 비율을 비교하고 소수점 한 자리 표시 결과도 확인한다. PRD의 공통 평가 배점은 유지하되 문제 1에서 요구하지 않은 원인 분석이나 세그먼트 비교의 누락을 오류로 취급하지 않는다. 항목별 상세 평가 예시와 비공개 정답 패키지는 후속 설계에서 작성한다.

## 구현 후 확인할 경계 사례

| 사례 | 기대 결과 |
| --- | --- |
| 가입 시작 시각에 가입 | 가입 코호트에 포함 |
| 가입 종료 시각에 가입 | 가입 코호트에서 제외 |
| D0에만 접속 | 관측 완료라면 이탈자 |
| D1 00:00에 로그인 시작 | 재접속자 |
| D7 마지막 순간에 로그인 시작 | 재접속자 |
| D8 00:00에만 로그인 시작 | 이번 관측 구간에서는 이탈자 |
| D3 접속, D7 미접속 | 재접속자 |
| D1~D7에 반복 접속 | 재접속자 1명 |
| D0 시작 세션이 D1까지 지속, 추가 로그인 없음 | 관측 완료라면 이탈자 |
| 수집 완료 경계가 D8 00:00과 동일 | 관측 완료로 포함 |
| 수집 완료 경계가 D8 00:00 이전 | 관측 미완료로 분모·분자에서 제외 |
| 관측 완료 유저 없음 | 대상자 0명, 이탈자 0명, 이탈률 계산 불가 |

위 표는 검증 계획이며 실제 SQL 검증 결과가 아니다.

## 후속 작업과 범위

1. [학습 데이터·패키지 명세](./002-training-data-packages.md)에 따라 users와 sessions를 구현한다. 데이터·문제·평가 자료의 패키지 ID와 배포 버전을 일치시킨다.
2. 데이터 기간·수집 완료 경계·표본 수를 확정하고 데이터를 생성한다.
3. 기준 쿼리와 경계 사례를 실행해 정답 자료를 검증한다.

훈련 시도의 입출력·저장 형식은 [훈련 기록 명세](./003-training-record-contracts.md)를 따른다. SQL은 PostgreSQL로 구현하고 사용자가 선택한 실행만 저장한다. Docker·ChatGPT 로그인 등을 포함한 실행 구성은 [기술 구성 명세](./004-local-technology-stack.md)를 따른다.
