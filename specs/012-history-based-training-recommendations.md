## 목적과 의존성

[PRD-v2](../docs/PRD-v2.md) 5·6·11·13·15절을 따른다. 기존 유형 순환 추천을 확장해 학습 목표·요구 판단·데이터 상황·검증된 수행을 반영한다. 출제 엔진의 사용 가능 능력과 Spec 009의 근거·선호를 입력으로 사용한다. 자유 분야 지원이나 능력 인증을 약속하지 않는다.

## 비교와 후보

최근 5개의 공개 완료 과제를 공개 시각 내림차순으로 비교한다. 실패 요청은 제외하고 사용자가 요청한 반복은 별도 표시한다. 비교 범위는 설정 가능하며 초기값 5를 유지한다.

과제 서명에는 분야, 학습 목표, 요구 판단, 형식, 데이터 상황 계열, 모호함 조건, 평가 필수 판단을 넣는다. seed·제목·숫자 변경은 동일 계열로 분류한다. 단순 형식 변화도 요구 판단이 같으면 의미적 다양성의 근거가 되지 않는다. 알고리즘 판정 이유와 사람 판정은 분리한다.

후보는 사용 가능 생성·평가 규칙에서만 만든다. 같은 주제에 다른 판단 후보가 없으면 반복 가능성을 안내하고 다른 목표/주제 또는 의도적 반복을 제안한다. 지원 밖 주제로 조용히 변경하거나 중복을 새 과제로 위장하지 않는다.

## 선택 규칙

1. 사용자의 명시 주제·수준·형식·반복 의도를 우선한다.
2. 유효한 보고서·리뷰·수정 판정·학습 상태에서 확인한 보완점을 후보 목표와 연결한다. 시험 운영 리뷰 단독 관측은 잠정 근거로 표시하고 강제 수준 변경에 사용하지 않는다.
3. 도움 사용은 필요한 지원의 근거로 활용하며 무조건 난이도를 낮추거나 감점하지 않는다. 서로 다른 신호·표본 부족이면 요청 수준을 유지하고 선택 이유에 한계를 표시한다.
4. 같은 목표 후보는 최근 의미적 반복이 적은 것을 우선한다. 동률이면 마지막 사용 시각과 안정적인 후보 ID 순서로 결정한다. 점수·선택 규칙 버전을 기록해 재현 가능하게 한다.

난이도 변경은 제안이며 사용자가 수정 가능하다. 이전 훈련 조건을 바꾸지 않는다. 새 과제 계획·데이터 검증은 사용자가 추천 시작을 선택한 뒤 출제 엔진이 수행한다.

## API 계약과 기록

기존 `/api/training/recommendation`을 확장해 recommendation_id, 생성 시각, 규칙 버전, 입력 학습 상태 revision·최근 과제 ID, 후보, 추천 목표·수준·형식, 이유, 근거 ID, 잠정 여부, 반복 판정, 사용 가능 범위를 반환한다. 추천에는 비공개 사건·원인·정답을 넣지 않는다.

출제 요청에서 recommendation_id와 사용자 수정값을 선택적으로 받는다. 근거 이력·능력 목록이 바뀌었으면 새로 계산하고 변경 이유를 표시한다. 추천 표시·선택 이벤트를 남기되 수락을 도움 효과 판정으로 집계하지 않는다. 선택 이유는 공개 계획·훈련 기록에 보존한다. 삭제된 근거를 참조하는 기존 추천은 무효화하고 재계산한다.

## 검증

이력 없음·명시 수준·핵심 오류·수정 성공·힌트 다수·상충 리뷰·실패 리뷰·같은 형식의 다른 판단·다른 형식의 같은 판단·5개 모두 중복·명시 반복·삭제 이력·버전 변경 표본을 고정해 후보와 이유를 확인한다. 자동 서명 비교와 별개로 사람이 같은 주제 과제 쌍의 의미적 차이를 판정한다. 실제 저장 이력→추천→사용자 변경→새 데이터 검증→새 과제 공개를 화면과 DB에서 확인해야 완료다.
