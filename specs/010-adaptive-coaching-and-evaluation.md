## 맥락과 다음 행동 계약

입력은 고정 공개 과제·질문으로 공개된 업무 사실·저장 대화·사용자의 정의/가설·초안·선택 저장 근거·도움 이력·현재 임시 근거다. 일반 코칭에는 비공개 원인·seed·기준 SQL·정답·평가 기대 발견사항을 전달하지 않는다. 요약은 원문 출처를 유지하며 임시 근거가 섞이면 요약도 임시 처리한다.

출력은 `action_type`, 이유, 한 가지 우선 행동, 확인한 공개/저장 근거 ID, 근거 상태, 필요 시 불확실성이다. action_type은 기존 clarify/check/suggest_analysis/submit/hint를 유지하고 유의미한 개입이 없을 때 `none`을 추가한다. 변경 계약 버전에서만 허용한다.

| 상황 | 기대 행동과 금지 사항 |
| --- | --- |
| 정의 부족 | 가장 중요한 미확정 조건 질문. 이미 답한 질문 반복 금지 |
| 집계·관측 오류 | 실제 근거로 오류 설명과 확인 행동 제시. 추정 원인 단정 금지 |
| 가설 충돌 | 비교·대안 설명 확인 제안. 가설에 맞게 결과 바꾸기 금지 |
| 타당한 다른 경로 | 목표 충족 여부와 이유 확인 후 진행. 기준 SQL 순서 강요 금지 |
| 근거 충분 | 결론·한계 정리와 제출 제안. 새 필수 분석 요구 금지 |
| 도움 요청 | 현재 시도에 맞는 힌트. 비공개 정답 조기 제공 금지 |

계획에 없는 업무 사실 질문에는 미확인으로 응답한다. 사용자의 SQL을 대신 실행하지 않는다. 제안과 실제 수행을 분리하고 실행 근거가 없으면 계산 미확인으로 표시한다.

## 트리거·힌트·한도

- 자동 코칭 기본 꺼짐, 직접 질문 가능. 켠 경우 질문 응답·SQL 결과 확인·제출 행동 완료 뒤 필요할 때 1회 제안한다. 질문의 응답과 자동 제안은 한 호출로 합쳐 중복 호출을 피한다. 제출 제안과 리뷰는 별도 작업이며 리뷰 응답에 포함한 다음 행동으로 추가 호출을 생략할 수 있다.
- 의미 있는 행동 ID와 훈련·트리거에 유일성을 적용한다. 동일 ID·내용은 기존 결과, 내용 충돌은 409. 임시 응답은 메모리 내 재사용만 하며 재시작 후 원문 복구하지 않는다. 호출 수행 기록은 원문 없는 이벤트로 남겨 재전송 중복 호출을 막는다.
- 기존 AI 90초, 훈련당 30회, 직렬 호출, 자동 재시도 0회, 임시 근거 10분을 유지한다. 코칭·힌트·리뷰를 합해 한도를 계산한다. 실패 시 초안·보고서를 보존한다. 모델·프롬프트·규칙 버전을 작업마다 기록한다.
- 도움 수준은 방향→지표/조건→SQL 구조. 요청 단계의 내용만 제공한다. 힌트 사용 자체로 감점하지 않는다. 기준 SQL 전체·원인·정답은 명시적 해설 공개 이후만 제공하고 해설 사용을 기록한다.

## 평가 계약

출제 시 평가 항목·양의 배점 합 100·필수 판단·필요 근거·허용 한계·적용하지 않는 항목을 고정한다. 설계 과제는 sql_accuracy를 제외한다. 0점 항목을 만들지 않고 미적용 항목은 생략한다. 리뷰 중 조건을 추가하지 않는다. 새 목표는 새 과제다.

리뷰는 항목별 level(정수 0~4), 이유, claim_ids, saved_execution_ids, 강점·보완점·다음 행동과 판정 불확실성을 반환한다. 서버가 항목 유일성·배점·동일 훈련/보고서 참조를 검증하고 `sum(weight*level/4)`를 소수 첫째 자리로 계산한다. 불확실성과 미확인 근거는 별도 표시하며 허위로 확인 처리하지 않는다.

계산 정확성은 학습자가 실제 실행하고 선택 저장한 완전한 결과와 고정 기준의 비교로 확인한다. 불완전·잘린 결과는 제공 범위의 사실만 확인하고 전체 분모·비율을 확정하지 않는다. 모든 대안 SQL에 문자열 일치를 요구하지 않는다. 기준 집계와 다른 정의가 허용되는 과제는 그 정의·관측 조건에 대응하는 검증 계약을 사용한다. 검증할 수 없는 대안은 틀렸다고 단정하지 않고 미확인과 필요한 검증을 표시한다.

생성 사건과 관측 데이터의 결론을 분리한다. 비공개 실제 원인을 맞히지 않았다는 이유로 감점하지 않는다. 결과의 차이를 원인으로 단정하는 보고서는 공개 근거와 설계로 확인 가능한 수준에서 평가한다.

## 노출·실패 처리

평가 전용 비공개 자료는 최소한으로 전달하고 일반 코칭과 입력 조립 경로를 분리한다. 비공개 기준 숫자뿐 아니라 기준 SQL·원인·사건 이름·변형 ID의 노출 표본을 검사한다. 학습자가 이미 실행한 동일 수치를 근거로 설명하는 것은 허용하되 출처를 연결한다. 숫자 문자열 필터만으로 의미적 노출 방지를 완료 처리하지 않는다.

형식·참조·노출 검사 실패 시 피드백을 정상 리뷰로 공개하지 않고 고정 오류를 표시한다. 제출본 보존, 수동 재시도 가능, 실패 회차 이벤트·사용량 기록을 따른다. 실제 모델의 의미적 품질 승인이 없으면 시험 운영 표시를 유지한다.

## 품질 표본과 완료 기준

각 지원 과제 유형에 정확한 풀이·핵심 오류·근거 부족·타당한 대안·불확실성/관측 한계·비공개 정보 요청 표본을 준비한다. 코칭은 위 6종 상황과 이미 답한 질문·임시 근거 만료·꺼짐 표본을 추가한다. 기대 판정과 근거는 검토자가 모델 출력 전에 고정한다.

고정 표본마다 현재 모델로 3회 실행한다. 형식 및 핵심 판정 유지, 허위 수치 승인·오진·해설 전 정답 노출 없음, 총점 max-min 10점 이하를 확인한다. 실패 회차를 제외해 안정적으로 보이게 하지 않는다. 10점 초과나 금지 실패는 원인 개선 뒤 같은 표본과 관련 회귀 표본을 재검증한다. 다른 타당한 풀이를 거부하지 않는지 사람이 판정한다.

권장 신규 모듈은 `coaching.py`, `evaluation.py`, `quality_fixtures.py`다. 기존 reviews.py·quality.py 연결은 API·근거 계약 확정 후 수행한다. 자동 형식 검사→실제 DB 근거 검증→실제 모델 반복→사람 판정→화면 공개 흐름 확인 순서로 검증한다. 테스트 결과와 사람 판정은 tests 아래 별도 기록한다.
