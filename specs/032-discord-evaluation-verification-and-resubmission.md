## 목적

후속 [Spec033](033-trustworthy-evaluation-quality-loop.md)에서 중복 감점 검사·제한된 수정과 **유형 반복 검증 미통과 시 점수 보류**를 추가했다. 아래 점수 결과는 당시 검증 기록이며 현재 제출 점수 제공 정책은 Spec033을 따른다.

현재 실제 조회에서 1주차 두 채널 모두 80%인데 구성만 바꿔 전체70%가 된다는 보고가 100점을 받았다. 평가 완료 이후 `/report`도 거부됐다. 공개된 실제 실행 결과로 확인 가능한 계산과 모델의 의미 평가를 분리하고, 동일 과제의 수정 보고와 이전 평가를 보존한다.

## 범위와 설계

- Discord 분석 훈련만 변경한다. 요청 주제 확장·난이도 분리·데이터 생성 변경은 포함하지 않는다.
- 새로운 슬래시 명령 없이 완료 상태의 `/report`로 수정 버전을 시작한다. 기존 보고·평가·게시 연결은 변경하지 않는다. 중단 과제는 먼저 재개해야 한다.
- 평가에 사용된 최신 보고, 해당 보고의 선택 근거와 후속 답변을 기준으로 검산한다. 옛 보고의 틀린 주장으로 수정 보고를 감점하지 않는다.
- 계산 근거는 성공·전체 수집 완료·비절단 저장 실행과 공개 조건이다. SQL 재실행·비공개 생성 원인·정답 SQL을 평가에 사용하지 않는다.
- 전체 비율은 분자 합/분모 합으로 검산한다. 비교는 동일 지표·단계·분모·이벤트 관측·시간대·필터·데이터 버전, 겹치지 않는 두 주 가입 기간일 때 수행한다. 전체 조회와 채널 조회를 합산하지 않는다. 중복 조회는 같은 조건으로 묶어 중복 집계하지 않으며 충돌하면 비교를 보류한다.
- 자유 형식 보고의 명확한 기간·채널·비율·변화 주장 및 구성만으로 설명한다는 확정 주장부터 지원한다. 지원 밖·애매한 문장·질문·가설·인용·부정문은 오류로 단정하지 않는다. 검산 범위와 미확인 항목을 함께 표시하며 모든 자연어를 검산했다고 주장하지 않는다.
- 구성만 변경한 기대 비율은 기준 주 채널 비율에 비교 주 가입자 비중을 곱한다. 어느 주를 기준으로 했는지 공개한다. 다른 타당한 분해 기준이나 인과 판단 보류는 감점하지 않는다.
- 확정된 계산 오류의 자동 점수 조정은 `evidence_interpretation` 한 항목에 등급 상한1로 반영한다. 원래 모델 등급과 조정 이유·보고 문장·실행 ID·기대 값·다음 수정 행동을 보존한다. 검산 코드는 점수를 올리거나 다른 항목을 추가 감점하지 않는다. 모델에도 중복 감점 금지를 지시하지만 모델 자체의 의미 평가까지 일관성을 보장하지 않는다. 실제 중복 감점 사례는 아래 검증 기록의 남은 품질 문제로 보존한다.
- API/실행 문제로 모델 평가가 보류이면 검산으로 확정 점수를 만들지 않는다. 검산 실패나 모호함은 학습자 오류와 구분한다.
- 공개 검산 정책 버전을 결과에 저장한다. 기존 기록은 원래 기준 버전을 유지하며 새로운 평가에만 정책 버전을 추가한다.

## 수정 흐름

1. 보고1과 후속 답변을 제출해 평가1을 저장한다.
2. 완료 상태에서 `/report`로 새 내용을 입력하면 보고2를 저장하고 후속 질문을 새로 발행한다. 빈 보고는 완료 상태를 바꾸지 않는다.
3. 필요 시 추가 조회·근거 선택 후 보고를 다시 저장한다. 보고1의 근거 목록은 바꾸지 않는다.
4. 새 보고의 후속 답변을 마친 뒤 `/submit`으로 평가2를 저장한다. 예전 후속 답변은 새 보고의 제출 조건을 대신하지 않는다.
5. 평가2는 이전 평가 ID·보고 버전·항목별 변화·검산 오류 변화와 함께 표시한다. 점수 상승을 학습 효과로 확정하지 않는다.
6. 완료 상태의 동일 제출·이벤트 재시도는 마지막 저장 평가를 재사용하며 모델을 다시 호출하지 않는다. 평가별 포럼 글 구분은 기존 계약을 따른다.

## 완료 기준

- 실제 감사의 잘못된 구성 보고를 모델이 전 항목4로 반환해도 100점으로 저장하지 않는다.
- 올바른 전체 비율·%p·감소율과 기준 시점이 다른 타당한 분해, 구성 가설의 기각·질문·합리적 보류는 검산 오류로 처리하지 않는다.
- 조건 불일치·잘린 결과·0분모·미선택 근거·중복/충돌 실행은 확정 계산 근거로 사용하지 않는다.
- 실제 PostgreSQL 격리 기록에서 최초 평가→수정→새 평가→프로세스 재개가 보존된다. 타 사용자의 수정·빈 보고·후속 미답변·중복 제출 경계가 통과한다.
- 실제 Gemma의 틀린/수정 보고를 대조하며 호출 제한은 보류로 기록한다. 화면은 실제 결과 카드 렌더링·브라우저 확인 범위와 실제 Discord 전달 미확인 범위를 구분한다.
