## 범위와 웹 분리

PRD 2.1, 4.1, 6.5, 6.6, 12.1에 대응한다. 새 모듈만 추가하며 기존 웹 출제·평가·정적 파일·DB 설정을 수정하지 않는다. 세 테이블의 대표 튜토리얼 과제만 지원한다. 지원하지 않는 주제를 실행 가능한 과제로 가장하지 않는다.

적재는 `DISCORD_ADMIN_DSN`/`DISCORD_LEARNER_DSN` 또는 별도 설정 객체의 `admin_dsn`/`learner_dsn`을 명시해야 한다. 기존 웹 기본 DB인 training/records는 거절한다. DB와 호스트가 같아야 하며 학습자는 별도 비관리자 계정이어야 한다. fresh `discord_<UUID>` 스키마만 생성하고 학습자에 USAGE/SELECT만 부여한다. 프로비저닝 실패는 트랜잭션 롤백으로 처리한다. 운영 계정 생성은 운영 설정 단계다.

## 공개 교육 계약

- 단위: users는 고유 가입자, tutorial_attempts는 단계별 재도전 이벤트, sessions는 접속 이벤트.
- 기간: UTC, 시작 포함·끝 제외, 기준/후속 두 주, 관측 종료 공개.
- 질문: 튜토리얼 3단계 완료 고유 사용자 / 기간 내 신규 가입 고유 사용자.
- 품질 판단: 재도전 중복을 확인하며 이벤트 수를 사용자 수로 간주하지 않는다. 실제 수집 누락은 합성 테이블만으로 확인 불가.
- 대안: 주별 변화와 유입 채널별 변화·구성을 비교할 수 있다. 서로 다른 조회 순서와 타당한 보류를 인정한다.
- 고정 배점: 문제 정의 20, 지표·비교 설계 25, 가설·대안 20, 근거 해석 20, 한계·의사결정 15.
- 등급: 내용 없음 0, 공개 핵심 오류 1, 필수 누락 2, 필수 충족 3, 추가 검증·한계 조건까지 충족 4. 시스템 관측 불가는 null/판정 보류이며 필수 항목 보류면 총점도 null이다.
- 총점 계산: 항목 배점 × 등급 / 4의 합. SQL 작성 역량·문장 길이·전문 용어 수·조회 횟수는 채점하지 않는다. 동일 결함 중복 감점 금지.

평가 공급자에는 공개 과제 키만 화이트리스트로 전달한다. 출제 내부 원인·정답 SQL은 전달하지 않는다. 제출 보고 버전, 메시지 ID, 실행 ID는 인용 가능 ID를 고정한다. 없는 ID, 실패 실행의 성공 근거 인용, 잘못된 등급·항목·보류 이유·개선 행동이 있으면 총점 확정 대신 보류한다. 의미 판정은 실제 공급자와 사람 검토 대상이며 가짜 공급자 시험은 판정 타당성을 입증하지 않는다.

## 도움과 성장

초급 기본 수준은 guided, 중급/고급 independent. 요청 확인은 의도를 묻는 중립 질문이며 hint=false다. 개념·방향·중간 피드백은 hint=true이고 도움 전 사용자 답변과 대상 항목을 함께 돌려준다. 자동 응답에는 정답 수치·내부 SQL이 없다. 전체 저장·소유권은 Discord 저장·진행 모듈이 수행한다.

성장은 같은 사용자·기준 버전·난이도에서 사람이 비교 가능성을 승인한 다른 과제를 비교한다. 도움 전 등급은 before_help, 도움 후는 after_help로 별도 표시한다. 시스템 보류·근거 부족·비교 미승인은 제외 사유와 실제 건수를 표시한다. 자료가 부족하면 성장 판단 자료 부족이며 완료율로 보충하지 않는다. 숫자 차이는 관측 결과이며 학습 효과 입증으로 표시하지 않는다.

## 자동 검증 및 검토 표본

격리 컨테이너/DB에서 `python -m pytest tests/automated/test_discord_education.py -q`: **18 passed**. 고정 공개 계약, 40명·130도전 fixture, 후속 변형, 잘못된 주제, 도움 구분, 숨겨진 키 차단, 배점 계산, 없는 근거·잘못된 등급·실패 실행·공급자 실패 보류, 무보조 비교 조건과 읽기 전용 PostgreSQL 권한을 확인했다. 기존 실행 중인 웹 컨테이너/DB는 사용하지 않았다.

| 사람/실제 모델 검토 고정 표본 | 기대 판단 |
| --- | --- |
| 같은 사실·실행 ID를 짧게/길게 표현한 보고 | 문체만으로 등급이 바뀌지 않음 |
| 초기 원인 가설을 기각하고 채널 구성 대안을 비교 | 잘못된 초기 가설 자체로 감점하지 않음 |
| 채널 구성을 검토한 타당한 다른 결론 | 비공개 생성 원인을 맞히지 않아도 인정 |
| 수집 상태를 관측할 수 없어 보류·로그/실험 제안 | 한계·대응 조건 충족 인정 가능 |
| 집단 완료율 차이만으로 광고 유입의 인과 효과 확정 | 공개 근거 해석 핵심 오류 |
| 시스템 실행 실패로 선택 근거를 확인할 수 없음 | 사용자 0점 처리 대신 항목/총점 보류 |

실제 Gemini 응답의 의미·인용 충실도, 운영 DB 적재, 실제 Discord 화면과 두 사용자 핵심 흐름, 사람의 과제 비교 승인은 아직 확인하지 않았다. 사용자 확인 행동은 Discord에서 도움 요청 전 답변을 남기고 최종 제출 후 도움 전/후 이력이 구분되는지 확인하는 것이다.
