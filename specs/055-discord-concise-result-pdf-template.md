## 목적과 범위

사용자는 9쪽 결과 PDF의 글이 많고 가독성이 떨어진다고 판단했다. 문제 안내의 반복과 긴 평가 정책 설명을 줄이고, 핵심 수치와 다음 행동을 먼저 읽을 수 있는 재사용 템플릿과 실제 제출 기반 시안을 만든다.

사용자는 3쪽 학습형(요약·분석 근거·평가 피드백 각 1쪽)을 선택한 뒤 운영 다운로드에도 적용하도록 요청했다. 범위를 로컬 시안 3개 작업에서 운영 연결·Git·배포 검증을 포함한 7개로 확장했다. 다른 작업에서 Spec 054가 사용되어 이 문서는 055로 옮겼다.

분석 과제의 기본 `PDF 다운로드`는 3쪽 학습형 결과를 제공하고 `상세 원문 PDF`는 전체 내용과 인용을 제공한다. SQL 연습 형식은 유지한다. 기존 게시글은 `/resume` 또는 기존 평가 재제출 시 같은 게시글에 요약을 보완하며 원문 첨부를 재사용한다. 저장 기록·평가 ID·게시글 연결을 변경하거나 새 평가·모델 호출을 추가하지 않는다.

## 완료 기준

- 1쪽: 제목·기간·대상, 핵심 결론, 대표 수치 표, 우선 행동, 주요 한계.
- 2쪽: 추가 근거 표, 근거 해석, 비교 조건과 데이터 점검, 판단 한계.
- 3쪽: 평가 5항목을 한 표로 정리, 후속 확인 행동, 평가 상태와 원문 경로.
- 본문 11pt 이상, 표 10pt 이상. 글자를 줄여 억지로 3쪽에 맞추지 않는다.
- 입력이 페이지 분량을 초과하면 실패를 명확히 알리고 원문을 자르거나 숨기지 않는다.
- 실제 저장 조회값과 관측 등급을 사용하고, 점수 보류를 확정 점수로 바꾸지 않는다.
- 시안은 작성자가 편집한 문장이고 운영 생성은 저장된 공개 원문의 완결된 문장 발췌다. 새 모델 호출·새 SQL 실행 없이 작성한다.
- 저장 행·열의 발췌 범위 및 긴 셀·피드백의 생략을 표시한다. 긴 원문은 상세 PDF에서 확인한다.
- 비율 단위가 불명확하면 원값을 유지한다. `completion_rate`는 완료/전체 값과 일치할 때만 백분율로 변환한다.
- 일반 입력이 3쪽을 초과하면 글자 축소 대신 명시적으로 더 짧은 발췌를 제공한다. 두 형식의 생성 실패·업로드 실패는 평가를 보존하며 게시 완료로 표시하지 않는다.
