## 확정 사항

2026-10-03 사용자는 훈련 ID를 중심으로 입력·SQL 결과·보고서·리뷰를 연결하는 방안을 채택했다. 단, SQL 실행 기록은 사용자가 선택한 것만 저장하며 학습 SQL 엔진과 방언은 PostgreSQL을 사용한다.

사용자가 설명한 선택 저장의 이유는 단순 데이터 확인용 SQL까지 저장하면 불필요한 저장 공간 사용이 커질 가능성이 있다는 것이다. PostgreSQL은 무료이며 로컬 환경 구축과 Python 연결이 편하다는 사용자의 판단으로 선택했다. 따라서 전체 실행 기록을 보존하는 기능보다 필요한 실행을 선택해 저장하는 흐름을 우선한다.

여기서 저장은 재시작·새로고침 후 복구 가능한 영구 저장을 뜻한다. SQL 실행과 선택 저장을 분리한다. 미저장 실행은 현재 화면과 처리에 필요한 메모리에서만 유지한다. 코드와 DB는 아직 구현하지 않았다.

## 기록의 연결

- 훈련 1회에 고유 `attempt_id`를 부여한다. 같은 문제를 새로 풀면 새 ID를 만든다.
- 시작 시 `package_id`, `release_version`, `dataset_id`, `problem_id`를 고정한다.
- 하위 기록은 attempt_id로 훈련을 참조한다. 저장·제출·리뷰 시 서버가 콘텐츠 연결 정보의 일치를 검증하며 클라이언트가 다른 버전으로 변경할 수 없게 한다.
- 모든 입출력은 항목이 정의된 JSON을 사용한다. API 계약 자체의 변경을 위한 `contract_version`은 콘텐츠 배포 버전과 구분한다.
- 시각은 UTC ISO 8601 문자열로 교환하고 화면의 날짜 기준은 Asia/Seoul로 안내한다.

## PostgreSQL 실행 결과 형식

실행 응답은 execution_id, status, executed_at, duration_ms, columns, rows, preview_row_count, total_row_count, result_complete, truncated, error를 포함한다.

- status는 success / error / timeout / blocked로 구분한다. 결과 0행은 success다.
- columns는 이름과 PostgreSQL 자료형을 포함한다. rows는 컬럼 순서와 일치하는 배열로 표현하고 DB NULL은 JSON null로 전달한다.
- 정밀도가 필요한 numeric·큰 정수는 문자열로 전달하고 자료형 정보로 구분한다. 시각·날짜·기타 지원 자료형의 직렬화 규칙은 구현 계약에 명시한다.
- result_complete는 전체 결과를 확보했는지, truncated는 화면 미리보기가 잘렸는지를 구분한다. 총 행 수를 확인하지 못했으면 total_row_count는 null이다. 미리보기 행 수를 전체 건수로 표시하지 않는다.
- 초기 실행 제한은 5초, 화면 미리보기는 200행 제안을 유지한다. 전체 결과 보관의 행·용량 한도는 구현 전에 정하고, 부분 결과를 저장한 경우 결과 범위도 보존한다.
- error는 오류 코드·사용자가 이해할 메시지를 포함한다. 연결 자격 증명과 비공개 서버 경로를 노출하지 않는다.

학습자 연결에는 공개 데이터에만 접근하는 전용 최소 권한 계정을 사용하고 읽기 전용 트랜잭션과 실행 제한을 적용한다. 임의 SQL을 관리자·학습 기록 저장 계정으로 실행하지 않는다. 사용자 SQL에서 쓰기, 외부 접근, 위험한 함수 실행을 차단하는 정책과 Docker 실행 방식은 [기술 구성 명세](./004-local-technology-stack.md)를 따른다. 정확한 PostgreSQL 버전과 세부 권한은 구현 시 검증한다.

## 사용자가 선택한 실행만 저장

1. 실행 결과마다 `기록에 저장` 행동을 제공한다. 성공·실패 모두 선택 가능하지만 자동 저장하지 않는다.
2. 저장은 실행 당시 원문과 실제 응답을 사용한다. 편집기에 나중에 수정한 SQL을 이전 결과와 묶거나 클라이언트가 임의로 바꾼 결과를 저장하지 않는다.
3. 서버는 유효한 임시 실행 응답을 짧은 시간 메모리에서 보관하고 저장 요청과 연결한다. 임시 보관 만료·프로세스 종료 시 다시 실행하도록 안내하며 SQL을 몰래 재실행하지 않는다. 만료 시간은 구현 시 정하고 화면에 안내한다.
4. 선택 저장 성공 후에만 저장 완료를 표시한다. 실패 시 현재 결과를 화면에서 유지하고 같은 요청을 재시도할 수 있게 한다. 중복 저장 요청은 같은 기록을 반환한다.
5. 새로고침·종료 후에는 저장된 실행만 복구한다. 화면에 미저장 상태를 표시하고 떠날 때 미저장 SQL·결과가 사라짐을 안내한다.
6. 미저장 SQL·결과를 브라우저 저장소, 임시 파일, API 요청 본문 로그, 서버·PostgreSQL의 SQL/오류 문장 로그, APM·분석 도구 등에 자동 보관하지 않는다. 구현 시 각 경로의 설정과 실제 파일·저장소를 검사한다. SQL 본문을 제외한 장애 코드·시간 등 운영 정보는 별도 관리할 수 있다.
7. 미저장 실행을 사용하는 코칭은 일시적인 도움으로 처리한다. 해당 SQL·결과를 담은 코칭 대화도 영구 저장하지 않는다. 지속할 코칭 이력은 선택 저장한 실행만 참조한다.

SQL 원문을 사용자가 자유 서술이나 보고서에 직접 입력해 저장하는 것은 사용자 작성 내용의 저장이다. 앱이 미저장 SQL을 해당 구역으로 자동 복사하거나 끼워 넣지 않는다.

## 보고서 근거와 리뷰

보고서는 문제 정의, 가설·접근, 발견사항, 한계, 다음 행동으로 구성한다. 주요 발견마다 claim_id, text, evidence_refs를 둔다. evidence_refs는 같은 훈련의 saved_execution_id와 필요한 행·컬럼 참조를 담는다.

- 보고서 근거 선택 목록에는 저장된 성공 실행만 표시한다. 저장되지 않은 결과를 쓰려면 먼저 저장을 선택해야 한다. 선택 없이 보고서 제출 과정에서 자동 저장하지 않는다.
- 실패 실행은 복습 기록으로 보존할 수 있지만 수치 주장의 증거로 사용하지 않는다.
- 부분 결과로 전체 집단을 단정하면 리뷰에서 결과 범위의 한계를 확인한다. 전체 결과가 없다는 이유만으로 모든 주장에 동일한 오류 판정을 하지 않는다.
- 근거가 없는 발견도 제출은 허용하되 근거 부족으로 표시한다. 에이전트가 실제로 확인한 수치처럼 승인하지 않는다.
- 제출본은 수정하지 않고 새 report_version을 만든다. 리뷰는 특정 report_id에 연결하고 기존 리뷰를 덮어쓰지 않는다.
- 리뷰에는 항목별 평가, 참조한 claim_id·saved_execution_id, 잘한 점·보완점·다음 행동을 저장한다. LLM 연결 실패는 실패·재시도 상태로 기록하고 제출본과 근거는 보존한다.
- 저장 실행 자체를 모두 정오 채점하는 방식은 채택하지 않는다. 최종 주장에 연결된 SQL·결과를 검토할 수 있는 구조를 제공한다. SQL 평가의 상세 기준·배점 조정은 별도 확정이 필요하다.

## 저장 모델과 동시 수정

논리적 저장 대상은 attempts, draft_revisions, saved_executions, reports, report_evidence, reviews, hint_history다. 해설 참조 여부도 훈련에 기록한다. 미저장 executions를 영구 저장 테이블로 만들지 않는다.

초안은 revision을 함께 보내 이전 수정 번호로 덮어쓰려는 요청을 충돌로 반환한다. 실행 저장·보고서 제출·리뷰 생성은 중복 요청 방지 ID를 사용한다. 보고서와 근거 연결은 함께 저장하고 하나라도 실패하면 제출 성공으로 처리하지 않는다.

학습 SQL 엔진과 학습 기록 저장소는 각각 별도의 PostgreSQL DB로 확정됐다. [기술 구성 명세](./004-local-technology-stack.md)에 따라 Docker Compose로 실행하고 Python + FastAPI·Psycopg 3로 연결한다. PostgreSQL 학습자 계정은 기록 저장소에 접근할 수 없어야 한다. AI는 공식 ChatGPT 로그인 기반으로 연결한다.

## 구현 후 검증

| 흐름 | 확인 조건 |
| --- | --- |
| A·B 실행 후 A만 저장하고 새로고침 | A만 복구; B의 SQL·결과는 영구 저장소·로그에 없음 |
| SQL 문법 오류와 제한 초과 | 실제 상태 안내; 선택 전 영구 기록 없음 |
| 실행 후 편집기 SQL 수정, 이전 실행 저장 | 이전 실행 당시 원문·결과 저장 |
| 동일 저장·제출 요청 재시도 | 중복 기록·제출본 없음 |
| 임시 실행 만료 후 저장 | 재실행 필요 안내; 자동 실행·잘못된 결과 연결 없음 |
| 미저장 실행을 보고서에 연결 시도 | 명시적 저장을 안내하고 자동 저장하지 않음 |
| 다른 훈련·버전의 근거 연결 | 연결 거부 |
| 저장 실패와 초안 충돌 | 성공으로 표시하지 않고 화면 입력·결과 유지 |
| 보고서 수정·리뷰 재시도 | 이전 제출·리뷰 보존, 새 기록은 해당 제출본에 연결 |
| 새 패키지 배포 후 기존 훈련 재개 | 기존 데이터·문제 버전 유지 |
| 학습자 SQL의 쓰기·비공개 조회 시도 | 접근 차단 |

위 검증은 아직 실행하지 않았다. 화면 기능 구현 후 실제 동작까지 확인한다.
