## 목적과 사용 흐름

사용자는 DA-Result 포럼에 게시한 분석 내용을 PDF로 내려받는다. `/submit`으로 저장된 제출 보고서와 평가를 게시할 때 PDF를 함께 생성한다. 첫 요약 카드의 `PDF 다운로드` 버튼을 누르면 해당 사용자에게만 파일을 제공하며 Discord 기본 파일 다운로드로 저장한다. 첫 카드 첨부에서도 직접 저장할 수 있다.

## 요구사항

1. PDF는 `build_submission`의 공개 카드, 해당 보고 버전에 근거로 선택한 성공 조회, 해당 평가가 실제 인용한 성공 조회와 공개 대화 근거만 사용한다. 요약, 보고 버전·제출 시각, 보고서 전체, 후속 답변, 평가 근거·개선 행동, 다음 연습, 학습 판단 한계와 원래 과제 링크를 포함한다. 저장된 결과 행·컬럼·집계 조건을 제공하며, 비공개 정답·생성 데이터·원시 기록·SQL·선택되지도 인용되지도 않은 조회/대화는 포함하지 않는다. 모델을 다시 호출하거나 점수를 변경하지 않는다.
2. 사용자가 선택한 1번 표준 보고서형을 사용한다. A4, 좌우 여백48pt, 내장 한글 일반/굵은 폰트, 제목22pt, 섹션13pt, 본문11pt/행간18pt를 적용한다. 근거 조회 결과의 그래프와 표를 먼저 보여준 뒤 제출 요약·분석 원문·후속 답변·평가·다음 연습·학습 한계를 보존한다. 본문·평가의 기술적 조회 ID는 해당 도표 번호로 표시한다. 연결되지 않은 조회 ID는 결과 연결을 확인할 수 없다고 표시한다. 자동 줄바꿈·페이지 나눔과 페이지 번호를 제공한다. 원문에 존재하는 보고서 항목 표지에 문단 간격을 추가하며 수치·주장·점수는 재작성하지 않는다. Markdown 이스케이프는 사람이 읽는 원문으로 복구하고 HTML은 실행하지 않는다.
3. 파일명은 세션·평가 ID의 해시로 결정해 안전하게 고정한다. 게시 시 Discord 첨부로 보관한다. 봇 서버의 임시 파일이나 다운로드 HTTP 서버가 필요하지 않다.
4. 봇의 파일 첨부 권한과 서버 업로드 한도를 사전 확인한다. 생성 실패 시 게시를 완료 처리하지 않으며 저장된 평가를 보존한다. 부분 게시·기존 게시글도 `/submit` 또는 `/resume`으로 PDF와 버튼을 복구할 수 있다. 정상 PDF가 있으면 다시 생성·첨부하지 않는다.
5. 최초 생성에는 PDF·요약 카드·버튼을 함께 보낸다. 기존 게시글에서는 첫 카드만 보완하고 다른 첨부와 카드를 보존한다. `published`는 모든 카드와 PDF 연결 이후에만 저장한다.
6. 다운로드 버튼은 영속 View로 등록한다. 클릭할 때 원본 메시지를 다시 조회하고 파일을 읽어 제공하므로 만료된 CDN URL을 저장하지 않는다. 허용된 서버, 봇이 작성한 포럼 메시지, 사용자의 현재 채널 보기·기록 읽기 권한을 검증한다. 접근 가능한 포럼 회원은 PDF도 받을 수 있다.
7. 삭제·접근 차단·다운로드 오류는 사용자에게 재개 방법을 안내한다. PDF 제공 시 멘션을 실행하지 않는다.
8. 시각화는 서술문에서 숫자를 추측하지 않고 저장 조회 행만 사용한다. 구분별 유효한 비율 결과(8행 이하)는0~100% 축의 가로 막대그래프로 비교하고 정확한 수치를 표로 함께 제공한다. 나머지 결과는 표를 제공하며, NULL·범위 밖 값은 그래프에서 제외하고 안내한다. 기존 Discord 표 이미지 생성 코드를 재사용하고 긴 표는 판독 가능한 크기의 PDF 표로 전환한다. 선택 결과의 저장된 행을 임의로10행까지 잘라내지 않으며, 일부만 저장된 결과는 불완전성을 표시한다.
9. 평가의 `evidence_refs`를 구조적으로 해석한다. 이미 표시된 조회는 “앞의 조회 결과 N 그래프·표 참조” 또는 “표 참조”를 클릭하면 해당 시각화로 이동하게 한다. 평가에서 처음 인용한 조회는 해당 평가 근거 위치에서 한 번만 시각화하고 재인용 시 참조로 바꾼다. 보고서는 해당 버전의 본문으로 연결한다. 대화가 요약/후속 답변과 같으면 기존 위치를 참조하며, 그 외 공개 인용 대화는 실제 원문 박스로 한 번만 표시한다. 누락·실패·지원하지 않는 근거는 확인 불가를 안내하고 다른 결과와 임의로 연결하지 않는다.

## 완료 기준과 수동 확인

- 자동: 한글·특수문자·긴 본문·보류 점수 보존, 비공개 데이터 제외, 권한/용량/생성/업로드 실패, 기존 글 보완, 중단 후 재개, 반복 게시 중복 방지, 버튼 영속성과 권한·파일 전달 확인.
- PDF: 대표 긴 보고서를 실제 렌더링하여 글자·줄바꿈·여백·페이지 번호 확인.
- 실제 Discord: 테스트 서버에서 `/submit` 후 첫 카드의 버튼으로 파일 저장·열기, 봇 재시작 후 다시 다운로드, `/resume` 시 카드·첨부 중복이 없는지 확인. 실제 확인하지 않은 항목은 검증 대기로 둔다.

## 운영 변경

- 선택적 Discord 의존성에 ReportLab을 추가한다. Docker Discord 이미지에는 내장 가능한 Nanum 한글 TTF를 설치한다. Windows는 맑은 고딕을 사용한다. 사용자 지정 TTF는 `DISCORD_PDF_FONT`로 지정한다.
- 기존 평가·게시 저널의 DB 스키마는 유지한다. PDF 원본은 Discord 게시글의 첨부이며 게시글 삭제 시 함께 사라진다.
