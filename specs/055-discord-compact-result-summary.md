## 목적과 범위

사용자는 포럼 결과물의 내용이 길고 읽기 어렵다고 판단해 핵심 요약형 템플릿을 테스트한 뒤 운영 적용을 요청했다. 첫 메시지에는 결론 1문장, 근거 최대 3개, 평가 상태/점수·잘한 점·개선점, 다음 행동 1개를 표시한다. 전체 제출·후속 답변·항목별 평가·SQL·근거 자료는 기존 PDF에 보존한다.

- 저장된 보고서의 구조화 필드와 명시적인 제목/라벨에서 발췌한다. 라벨 없는 글은 `제출 발췌`로 표시하며 결론이나 수치를 생성하지 않는다.
- 추가 모델 호출이나 새로운 평가를 하지 않는다. 평가에 연결된 정확한 보고 버전을 사용한다.
- 저장된 해석 한계가 별도로 있으면 결론에 함께 발췌한다. 모든 잘린 문장은 말줄임표로 표시한다.
- 평가 보류는 점수보다 우선하고 보류 이유와 해결 행동을 표시한다. 공급자 실패와 문제 유형 검증 미통과를 학습자 근거 부족으로 바꾸지 않는다.
- 확인된 계산 오류는 본문에 건수와 수정 필요를 표시하고 다음 행동에서 오류 수정을 우선한다.
- SQL은 충족 항목 수, 저장 실행 결과의 앞부분, 전체/일부 수집 상태를 표시한다. 분석 점수나 독립 역량 판정을 생성하지 않는다.
- 본문 900자 이하, 한 카드, 최대 3개 근거로 제한하고 UTF-8 전송 예산을 검증한다. 작성자·원래 과제 링크·PDF 다운로드 버튼·기존 게시 연결을 유지한다.
- 신규 제출과 `/resume`에 적용한다. 기존 게시글은 재개 시 같은 첫 메시지를 수정한다. 전체 포럼 일괄 재게시나 기존 댓글 삭제는 하지 않는다.
- 기능 브랜치·PR·CI·main·지정 main 배포·실제 Discord 확인을 진행한다. `.local`은 Git에 추가하지 않는다.

## 완료 기준

1. 구조화/라벨 있는 보고서와 자유 문장 보고서가 저장된 내용을 벗어나지 않는 요약으로 표시된다.
2. 평가 보류·계산 오류·SQL 미충족·일부 실행 결과가 요약에서 숨겨지지 않는다.
3. 제출 입력과 평가 점수·평가 수가 바뀌지 않고 PDF의 전체 카드·근거가 보존된다.
4. 재시도·재개에서 동일 게시글/첨부를 재사용하며 평가 재호출·중복 답글이 없다.
5. CI와 main 배포 후 실제 Discord 화면·PDF 다운로드를 확인한다.
