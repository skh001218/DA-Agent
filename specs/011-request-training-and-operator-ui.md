## 범위와 원칙

[PRD-v2](../docs/PRD-v2.md) 4·10·12절과 Spec 009·010·012를 화면에 연결한다. HTML·CSS·JavaScript 기존 구성을 유지한다. 과제 유형이 달라도 같은 분석 순서를 강요하지 않는다. 운영자의 검증 표본·비공개 자료를 학습 화면에 섞지 않는다. 실제 기능 없는 버튼과 모의 API 결과를 완료로 표시하지 않는다.

## 학습 흐름

1. 요청 화면은 자연어, 난이도, 선택적인 목표·형식, 실제 지원 분야, 생성/기존 데이터 사용 구분, 이어하기를 제공한다. 지원 밖 요청은 이유·대안을 표시하고 원 입력을 유지한다.
2. 추가 질문은 꼭 필요한 항목만 보여주고 답변을 같은 요청 revision에 연결한다. 사용자가 선택한 수준과 서버의 제안이 다르면 이유와 변경 수단을 제공한다.
3. 준비 화면은 설계→데이터 준비→검증→출제 가능 상태와 완료된 작업·경과 시간을 표시한다. 실제 진행량이 없으면 임의의 백분율이나 ETA를 표시하지 않는다. ready 이전 취소·실패/중단 후 재시도 버튼을 제공한다.
4. 분석 화면은 과제 목표·기대 제출물·배점·사전·질문으로 확인 가능한 업무 정보·SQL·결과·대화를 연결한다. 공개 정보 API만 사용하며 DOM·네트워크 응답·다운로드에 비공개 원문이 없어야 한다.
5. 결과에는 완전성·미리보기/전체 행 수·만료 안내·선택 저장을 표시한다. 일반 메시지와 임시 자료 입력을 구분한다. 임시 근거 코칭에는 재개 불가 안내를 제공하고 저장 여부를 사용자가 결정한다.
6. 자동 코칭은 기본 꺼짐이고 선택 시 비용·한도·도움 수준을 안내한다. 제안은 이유와 한 가지 다음 행동으로 제시하고 SQL 자동 실행을 하지 않는다.
7. 계산·검토 과제는 주장과 필요한 근거를 연결하고, 설계 과제는 SQL 없이 제출할 수 있다. 실패 리뷰는 제출 실패와 구분하고 제출본을 유지한다. 시험 운영 여부·항목별 이유·근거·수정 행동·명시적 해설 버튼을 제공한다.
8. 수정 제출은 새 보고서 revision으로 관리한다. 새로고침·서버 재시작 후 원 패키지·평가·저장 대화·보고서·리뷰를 복원하고 임시 자료는 제거됐음을 표시한다.

## 학습 이력과 삭제

학습 상태에는 출처와 미관측·사용자 이견을 표시하고 수정 시 기대 revision을 보낸다. 추천은 근거·반복 회피 이유·수준 변경 이유를 보여주며 그대로 시작/주제·수준 변경/반복 연습을 제공한다.

훈련 삭제 확인에는 해당 훈련의 저장 자료·연결 판정·집계 영향과 내보내기 파일·백업 제외를 설명한다. 취소 시 API 요청이 발생하지 않고 목록·입력이 유지되어야 한다. 확정 시 연결 기록 삭제 뒤 목록·추천·집계를 갱신한다. 작업 실행 중 삭제가 차단되면 이유와 종료 후 재시도를 안내한다. Spec 007에 남은 삭제 취소 검증은 실제 확인 후 그 문서도 갱신한다.

## 운영 화면

기존 품질 페이지에 전체 지표와 판정을 확장한다. 기간·분야·난이도·유형·모델·규칙 버전 필터, 지표 정의·분모·표본 수·미판정·결측·실패·취소·진행 중·보관 범위를 함께 표시한다. 0과 미측정은 다르게 표시한다. 서버 이벤트·알고리즘 추정·사람 판정·학습자 응답을 구분한다.

사람 판정은 대상 버전·표본·회차와 이전 판정을 볼 수 있고 revision 충돌 시 최신 상태를 확인한 뒤 수정한다. 연결한 명시적 저장 표본만 검토 자료로 제공한다. JSON/CSV 다운로드는 현재 필터·정의 버전을 포함하고 실제 파일의 내용까지 확인한다. 로그 수집 실패와 불완전 집계는 화면에서 감지 가능해야 한다.

## 오류·사용성

저장·AI·출제·SQL·DB 오류를 각각 고정 메시지로 구분한다. 요청/초안/제출 입력은 실패 시 유지하고 성공·실패 상태를 색만으로 전달하지 않는다. 키보드로 요청·SQL·저장·제출·확인창 취소를 조작할 수 있고 입력 label·진행 상태 알림·초점 이동을 제공한다. 기준 화면은 데스크톱 1280px와 좁은 화면 390px다. SQL 표는 가로 스크롤을 제공하고 주요 행동은 화면 밖으로 사라지지 않아야 한다.

## 검증

독립 모의 API로 화면 작업을 준비할 수 있지만 완료는 실제 PostgreSQL·현재 모델과 연결한 핵심 흐름으로 판정한다. 계산·검토·설계 세 유형 및 확장 유형마다 요청→출제→근거→대화→제출→리뷰→수정·재개를 확인한다. 취소 경쟁·추가 질문·AI 실패·SQL 오류·만료·저장 충돌·로그 장애·삭제 취소/확정·다운로드를 포함한다. 브라우저 콘솔과 비공개 응답 검사 결과, 사용 환경·실제 확인 단계·미확인 항목을 tests 검증 기록에 남긴다.
