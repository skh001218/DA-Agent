## 사용자 흐름

- /query는 항상 새 조회를 시작한다. 기존 대기 질문은 교체됨으로 남기고 답변 조건을 새 요청에 섞지 않는다.
- 봇 질문에는 Discord 답장 기능 또는 실제 봇 계정 멘션으로 답한다. /answer text:...는 현재 대기 질문에 답하는 대체 명령이다.
- 현재 질문 하나에 차례로 답한다. 새 질문이 이전 질문을 교체하면 과거 질문에 대한 답장은 거부하고 최신 질문으로 안내한다.
- 일반 채팅은 자동으로 조회하거나 답변으로 저장하지 않는다. 질문이 없을 때 멘션 답변을 보내면 /query 사용을 안내한다.

## 저장과 해석

questions는 질문 ID·종류·본문·상태·Discord 메시지 ID 목록을 보존한다. pending_question은 현재 질문이다. query_conditions는 기존 조회를 보완하고, analysis_reason은 이유·가설을 모델 조회 없이 기록하며, followup은 보고 후속 답변으로 처리한다. 답변과 봇 질문을 messages에 보존한다.

확인 답변은 모델 해석 전에 pending_query.answers에 저장한다. 모델 입력에는 최신 답변·기존 요청·직전 질문·부분 조건·누적 답변을 전달한다. 같은 지표의 기존 부분 조건은 새 응답에 없는 항목을 유지하며 새 값이 우선한다. 신규 /query에는 이 맥락을 전달하지 않는다. API 실패 시 대기 질문과 답변을 보존하고 서비스 오류로 안내한다.

질문 송신 뒤 반환된 Discord 메시지 ID를 영구 저장한다. 긴 질문의 여러 메시지 및 /resume로 재출력된 질문 메시지도 같은 질문에 연결한다. 완료·중단 상태의 답변은 기존 상태 검사를 적용한다. 사용자·서버·스레드 소유권 검사와 이벤트 중복 방지는 유지한다.

기존 저장 과제에는 조회 확인 대기 상태, 보고 후속 질문 상태, 마지막 미응답 멘토 질문을 최초 처리 시 복구한다. 예전 Discord 질문의 메시지 ID가 저장되지 않은 경우 /answer로 답하거나 /resume로 질문을 다시 출력해 연결한다.

## 메시지 수신 제한

Message Content Intent 설정을 확대하지 않는다. 봇 계정을 실제로 멘션한 메시지는 수신 대상으로 처리한다. 답장 내용이 비어 있으면 멘션 또는 /answer 사용을 안내한다. 공식 근거: https://github.com/discord/discord-api-docs/blob/main/developers/events/gateway.mdx#message-content-intent
