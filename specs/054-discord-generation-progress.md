## 목적과 결정

사용자는 출제 중 퍼센트를 메시지로 볼 수 있도록 요청하고, ‘단계 완료율 + 현재 단계 표시’를 선택했다. 동일한 메시지를 수정한다. 최초 구현·로컬 검증 3/3개 완료 후 운영 배포를 요청하여 Git·운영 반영과 실제 Discord 확인을 추가했다. 전체 작업 수를 3→5개로 갱신했다. 최신 main의 Spec 053 사용에 따라 번호를 054로 조정했다.

## 완료율 계약

- 전체 3단계는 문제 설계·검토, 자료 생성·검산, 문제 공개 준비다. 자료 생성·검산은 현재 `stage_adaptive`의 작업 경계에 따른다.
- 저장 상태 `planning`은 0/3 (0%), `preparing_data`는 1/3 (33%), `validating`은 2/3 (67%), `ready`는 3/3 (100%)로 표시한다. `validating`의 메시지는 실제 작업인 ‘문제 공개 준비’다.
- 시간 경과·모델 토큰 수로 진행률을 추정하지 않는다. 남은 시간 비율이 아니라는 안내를 함께 표시한다.
- 완료 단계 수는 세션에 저장한다. 실패·취소·중단·추가 질문에서는 마지막 완료 단계 수를 보존한다. 기존 종료 기록에 완료 단계 수가 없으면 확인 불가로 표시한다.
- 재시도·추가 답변으로 출제를 실제 시작하면 0%부터 새로운 시도의 한 메시지를 갱신한다. 기존 시도의 메시지는 보존한다.
- 최종 공개 저장이 성공한 뒤만 100%다. 표시 전송·수정 실패가 생성·검증·취소·공개 결과를 바꾸지 않아야 한다.
- 비공개 스레드에서 기존 소유권·서버·권한 검사 후 표시한다. 진행 알림에는 고정 상태와 완료 수만 전달하며 설계 초안·정답·예외 원문을 전달하지 않는다.
- 새 출제, `/retry`, `/answer`와 봇 질문 답장으로 시작한 출제를 동일하게 지원한다. `/end`는 진행 메시지에 취소를 즉시 반영한다.

## 검증

단계 전환의 저장 후 알림과 종료 상태 보존을 검증한다. 전송 계층에서 한 메시지 수정, 재시도·추가 답변 경로, 취소 중 경쟁, 표시 실패를 확인한다. 실제 Discord 운영 확인은 배포 후 확인할 항목으로 구분하고 로컬 미리보기로 과장하지 않는다.
