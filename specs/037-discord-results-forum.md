## 1. 목적과 문제

사용자는 `/submit`의 긴 출력이 읽기 어렵다고 경험했고, 제출 내용을 DA-Result 포럼에 정리해서 보여주기를 요청했다. 서버에 해당 포럼이 있으면 재사용하고, 없으면 생성한다.

완료 결과를 게시글에 모아 제출 원문·평가 근거·개선 행동을 찾아 읽을 수 있게 한다. 게시글 댓글에서 결과에 대한 의견을 이어갈 수 있게 한다. 과제 진행 중 질의·보고·후속 답변은 기존 개인 과제 공간에서 계속한다.

## 2. 범위와 기본 결정

2026-10-06 최종 정책: 완료 과제의 결과 전체 게시 후 원래 과제 스레드를 보관·잠금하고 부모 채널에 결과·과거 대화 링크를 남긴다. 요약은 과제 ID를 표시한다. 완료 과제 `/resume`은 결과 글·대화를 안내하며 보관 상태를 해제하지 않는다. 아래의 기존 개인 공간 링크·재개 흐름은 [Spec 043](043-discord-archived-training-and-titles.md)의 조건으로 대체한다. 평가 보류와 게시 실패의 개인 공간 보존·복구는 유지한다.

- 대상: Discord 서버에서 제출·평가 기록이 저장된 분석 훈련. DM은 대상이 아니다.
- 게시 단위: **평가 기록 하나당 게시글 하나**. 과제 하나 또는 보고서 하나로 합치지 않는다.
- 채널 이름: `DA-Result`. 대소문자를 구분하지 않아 `da-result`로 표시돼도 재사용한다.
- 표시 방식: 제목과 본문이 분리된 Discord 임베드 카드. 원시 JSON이나 문자 기호를 맞춘 표로 결과를 출력하지 않는다.
- 원본 유지: 저장된 보고서·평가를 정해진 형식으로 표시한다. 게시를 위한 추가 모델 호출이나 점수 재계산은 없다.
- 공개 범위: DA-Result를 읽을 수 있는 회원에게 제출 내용과 평가가 공개된다. 개인 과제 스레드와 접근 범위가 다를 수 있다.
- 제외: 과제 시작 시 포럼 생성, 모든 진행 대화의 포럼 이관, 포럼 댓글 자동 코칭·평가, 요청별 문제 생성 확장.
- 데이터 사전·조회 결과 표 이미지는 [Spec 034](034-discord-table-images.md)의 범위다.

## 3. 사용자 흐름

### 3.1 최초 제출

1. 사용자가 개인 과제 공간에서 보고와 필요한 후속 답변을 마치고 `/submit`을 실행한다.
2. 서비스가 평가와 연결된 보고서 버전을 저장한다. 후속 답변이 필요한 상태라면 안내하고 게시를 시작하지 않는다.
3. 저장 결과로 카드를 구성하고 DA-Result를 찾는다. 없으면 권한을 확인해 생성하고, 있으면 재사용한다.
4. 평가에 연결된 게시글을 찾거나 새 글을 만들고 첫 메시지에 제출·평가 내용과 전체 PDF를 함께 게시한다. 평가 카드를 답글로 보내지 않는다.
5. 원래 과제 공간에 저장 상태와 **DA-Result 게시글 열기** 링크를 짧게 표시한다.
6. 사용자가 링크로 이동해 결과를 읽고 댓글을 작성할 수 있다.

### 3.2 재시도·평가 보류

- 완료 과제의 `/submit`: 저장된 마지막 평가를 다시 게시한다. 평가·모델 호출을 반복하지 않고 같은 글을 재사용한다.
- `/resume`: 마지막 저장 평가가 있으면 결과 게시를 다시 시도한다. 부분 게시라면 첫 메시지 내용·PDF를 복구한다. 이전 방식으로 게시한 글도 첫 메시지를 통합 방식으로 갱신하며 기존 답글과 회원 댓글은 보존한다.
- 평가 보류: 요약과 평가 카드에 보류 상태·사유를 표시한다. 정상 점수로 바꾸지 않는다.
- 보류 후 보고 상태에서 다시 `/submit`: 새로운 평가 시도가 될 수 있으며 새로운 평가 ID에는 별도 글을 만든다. 기존 보류 결과의 게시만 복구하려면 `/resume`을 사용한다.
- 포럼 댓글은 회원 간 논의 공간이다. 현재 봇은 댓글을 개인 과제 명령이나 답변으로 처리하지 않는다.

## 4. 기능 요구사항

### FR-01. 채널 검색·생성

- 현재 서버에서 이름이 일치하는 포럼을 찾는다. 여러 개면 채널 ID가 가장 작은 포럼을 선택한다.
- 같은 이름의 일반 채널만 있으면 포럼 준비를 안내한다. 기존 채널을 변환·삭제하거나 같은 이름의 다른 채널을 생성하지 않는다.
- 새 포럼은 과제 부모 채널의 카테고리와 명시적 권한 덮어쓰기를 복사하고 목록형 레이아웃을 사용한다.
- 기존 포럼의 권한은 변경하지 않는다. 실제 접근에는 서버 역할·카테고리 권한도 적용된다.
- 태그가 필수면 봇이 적용 가능한 태그 하나를 사용한다. 없으면 운영자 조치를 안내한다.

### FR-02. 결과 구성

게시글 제목은 `과제 제목 · v보고버전 · 과제ID앞8자리-평가ID앞8자리`로 구성하고 길이 제한에 맞춘다. 결과는 첫 메시지에 모은다. 한 메시지의 임베드 최대 10개·텍스트 합계 6,000자(제목·작성자·footer·필드 포함) 이내이면 전체 내용을 표시한다. 짧은 카드가 많을 때는 섹션 제목을 유지하며 묶어 카드 개수 제한을 피한다.

한도를 넘으면 요약과 항목별 일부를 첫 메시지에 표시하고 **전체 제출·평가는 같은 메시지에 첨부된 PDF**로 제공한다. 긴 보고서의 이어지는 조각이 평가 항목의 표시 공간을 차지하지 않도록 보고·후속 답변의 미리보기는 묶는다. 본문 일부 표시 사실과 PDF 다운로드 방법을 명시하며 모델 요약·재평가를 수행하지 않는다. 이 초과 처리 방식은 사용자가 2026-10-07에 선택했다.

| 순서 | 내용 | 표시 기준 |
| --- | --- | --- |
| 1 | 제출 결과 요약 | 과제·업무 목표, 점수/100 또는 보류, 사람 검토 대기, 보고 버전, UTC 제출 시각, 공개 범위, 원래 과제 링크 |
| 2 | 제출 보고서 | 저장된 질문·발견·가설·대안·신뢰성·한계·우선 대응·후속 검증 또는 자유 형식 보고 원문 |
| 3 | 후속 답변 | 저장 답변을 번호와 함께 표시. 없으면 생략 |
| 4 | 평가 항목 | 항목 이름, 등급/4 또는 보류, 비중, 근거, 개선 행동, 근거 참조 ID |
| 5 | 다음 연습 | 저장 평가의 추천 항목. 없으면 평가 상태에 맞는 기본 안내 |
| 6 | 학습 관측과 한계 | 사용 가능·제외 관측 수, 저장된 변화 관측, 자료 부족과 사람의 비교 가능성 검토 필요 안내 |

보고 원문을 추가 요약으로 대체하지 않는다. 전체 개인 대화, 비공개 출제 정보, API 진단·비밀값, 내부 게시 상태 원문은 게시하지 않는다. 근거를 식별하는 조회·대화 ID는 표시할 수 있다. 개인 과제 링크는 그 스레드의 접근 권한을 새로 부여하지 않는다.

학습 관측은 모델 평가와 구분한다. 자료 부족이나 비교 조건 미확인을 학습 효과 확정으로 표시하지 않는다.

### FR-03. 게시 연결·중복 방지

- 세션 문서의 `result_publications`에 평가 ID별 상태·포럼 ID·글 ID·오류 코드·갱신 시각을 저장한다.
- 같은 서버의 게시 작업은 현재 봇 프로세스의 잠금으로 직렬화한다. 저장소에서도 동일 평가의 생성 상태 변경을 확인한다.
- 글 ID가 저장돼 있으면 그 글을 사용한다. 연결이 없으면 활성·보관 글에서 제목, 봇 작성자, 과제·평가에 대응하는 카드 표식을 함께 확인한다.
- 첫 메시지 footer의 결과 식별 표식으로 기존 글을 확인하고 같은 메시지의 임베드·PDF·다운로드 버튼을 갱신한다. 기존 표식 형식도 인식하며 추가 평가 답글을 보내지 않는다.
- 생성 결과가 불확실하고 기존 글을 확인하지 못하면 새 글을 만들지 않고 연결 확인을 안내한다.
- 연결된 글이 삭제됐거나 다른 포럼에 있으면 운영자 복구를 안내한다. 대체 글을 자동 생성하지 않는다.

| 저장 상태 | 의미 | 재시도 처리 |
| --- | --- | --- |
| `creating` | 생성 시작 기록 | 기존 글 확인·복구. 확인 불가 시 중복 생성 방지 안내 |
| `failed` | 생성 요청의 명확한 거부 등 실패 | 원인 해결 후 기존 글 확인·생성 재시도 |
| `uncertain` | 생성 결과를 확정하지 못함 | 기존 글 확인. 없으면 운영자 확인 필요 |
| `partial` | 글 연결은 있으나 첫 메시지/첨부 갱신이 미완료일 수 있음 | 기존 첫 메시지·PDF 복구 |
| `published` | 첫 메시지 내용과 PDF 게시 완료 | 같은 글 재사용, 누락이 생긴 경우 복구 |

### FR-04. 오류 안내·기록 보존

포럼 게시 실패가 이미 저장된 제출·평가를 취소하지 않는다. 개인 과제 공간에 기록 보존 사실, 필요한 조치, 결과 카드를 안내한다. 임베드 전송이 실패하면 읽을 수 있는 텍스트로 대체한다.

| 상황 | 안내할 조치 |
| --- | --- |
| 생성 권한 부족 | 운영자가 포럼 생성 또는 봇 채널 관리 권한 설정 |
| 게시·읽기 권한 부족 | 운영자가 봇·제출자의 포럼 접근 권한 확인 |
| 같은 이름의 비포럼 채널 | 사용할 포럼 준비 |
| 필수 태그 없음 | 봇이 적용 가능한 태그 준비 |
| 생성 결과 불확실 | 실제 게시글·저장 연결 확인 |
| 연결된 글 삭제·연결 오류 | 운영자 연결 복구; 제출·평가 보존 |
| 첫 메시지 갱신·PDF 첨부 실패 | 완료 과제는 `/submit`, 저장 결과 복구는 `/resume`으로 재시도 |

## 5. 권한과 공개 조건

| 대상 | 조건 |
| --- | --- |
| 새 포럼 생성 봇 | 부모 채널의 `manage_channels` 및 Discord가 허용하는 생성 조건 |
| 포럼 게시 봇 | `view_channel`, `send_messages`, `send_messages_in_threads`, `embed_links`, `read_message_history` |
| 제출자 | 포럼의 `view_channel`, `read_message_history` |
| 보관 글 복구·관리 태그 | 상황에 따라 해당 관리 작업을 허용하는 추가 권한 |

원래 과제의 소유자·서버를 확인한 뒤 게시한다. 다른 사용자의 평가를 게시 대상으로 바꾸지 못하게 한다. 모든 결과 전송에서 멘션을 비활성화해 원문의 `@everyone` 등이 알림을 발생시키지 않는다.

운영자는 역할별 포럼 접근 범위를 확인한다. 새 포럼은 부모 채널 설정을 따르며 서버 전체 공개를 별도로 강제하지 않는다. 제한된 결과 공유가 필요하면 운영자가 DA-Result의 접근 역할을 정한다.

## 8. 남은 운영 확인

현재 봇의 생성 요청은 403 / Discord code 50013으로 실패했다. 관리자 화면에서 포럼을 생성한 뒤 봇의 게시·재사용·카드 수정은 성공했다. 서버 기능 변경이나 봇 권한 추가는 하지 않았다.

자동 생성 완료 조건은 운영자가 적절한 권한을 준비한 테스트 서버에서 포럼이 없는 상태로 제출 → 자동 생성 → 카드 게시 → 링크 이동을 확인한다. 기존 운영 포럼을 삭제해 검증하지 않는다. 운영 포럼이 이후 삭제되면 현재 권한으로는 자동 재생성이 되지 않는다.
