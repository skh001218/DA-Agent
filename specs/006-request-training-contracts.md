## 목적과 적용 범위

PRD-v2.2의 공통 규칙을 API·출제·기록·코칭·평가에서 동일하게 적용한다. 2026-10-04 사용자는 추천 방향으로 개발하고 사용 가능한 구간에서 직접 사용하며 수정하기로 했다. 본 Spec 작성만으로 구현 완료로 보지 않는다.

첫 사용 구간은 이미 생성·적재·검증된 users/sessions 패키지를 재사용한다. 새로운 데이터 생성·규칙 승인·분야 확장은 후속 범위다. 요청 기반 출제는 승인된 지표 계산, 분석 오류 수정, 업무 요청 구체화의 세 가지 능력 범위에서 제공하며 데이터 재사용과 생성은 화면에서 구분한다. D1~D7 미재접속 지표와 일자별 D7 리텐션을 혼동하지 않는다. 지원 밖 요청에는 대안과 추가 질문을 반환한다.

## 요청과 식별자

- 요청: request_id(UUID), message(1~4,000자), difficulty(beginner/intermediate/advanced), task_kind(auto/calculation/review/design).
- request_id는 재전송 멱등 키다. 동일 ID·동일 내용은 기존 상태를 반환하고 내용이 다르면 409 idempotency_conflict. 재시도는 같은 요청의 새 operation_id, 새 과제는 새 request_id.
- 요청 ID, attempt_id(기존 훈련 ID), operation_id, event_id를 구분한다. 훈련 ID는 검증 통과 후 생성한다.
- 최초 지원 범위는 접속 데이터의 D1~D7 미재접속 계산·검토·분석 설계. 명확한 유형·난이도는 사용자 요청을 우선한다. 명시 유형과 문장이 충돌하면 확인 질문. 형식 미지정은 최근 5개 과제의 유형 빈도와 마지막 유형을 고려해 제안하되 선택 이유를 표시한다.
- 요청 원문은 출제 요청 전용 입력으로 받는다. SQL·결과 붙여넣기는 임시 근거 입력을 사용하도록 안내하고 요청·일반 대화에 포함되면 임시 처리 또는 저장 거부한다. 예외·로그에는 원문을 넣지 않는다.

## 고정된 과제 계획

contract_version=request-v1, plan_version, difficulty_version, evaluation_version, package_id, release_version, dataset_id, problem_id, task_kind, 요청 수준, 학습 목표, 요구 판단, 난이도 이유, 공개 테이블, 제출 완료 조건, 항목별 배점을 고정한다.

공개 정보·질문 시 제공 정보·비공개 기준은 서버에서 분리한다. 질문 시 정보는 저장된 고정 사실에서만 제공한다. 비공개 SQL·기준 수치·생성 사건은 재개 응답·일반 코칭·힌트·운영 로그에 넣지 않는다. 일반 평가 관점·배점은 공개한다. 풀이 중 과제 조건은 수정하지 않으며 변경은 별도 과제로 처리한다.

초급은 대상·기간·관측·중복 조건을 공개한다. 중급은 정의·관측 조건 중 일부를 질문으로 확인하게 한다. 고급은 문제 정의·분석 우선순위를 사용자가 정하게 하되 수집 범위·사전 등 분석에 필수인 사실을 확인 가능하게 한다. 데이터 부족과 지어낸 변화·원인을 고급 난이도로 쓰지 않는다.

## 상태와 오류

- 출제: accepted → planning → validating → ready. terminal 상태 failed/cancelled, 확인이 필요한 상태 needs_clarification. 초기 구간은 기존 검증 패키지 선택 단계가 데이터 준비에 해당한다.
- ready에는 attempt_id가 필수. 검증 실패에는 훈련·공개 과제가 없다. 상태·실패 코드는 저장하고 입력은 화면에서 보존한다.
- 생성·AI·DB 작업 중 DB 잠금을 길게 유지하지 않는다. 취소는 ready 이전에만 가능하며 최종 공개 직전 요청 행을 잠그고 취소 상태를 재확인한다. 취소 후 도착한 응답은 공개·재개 기록에 반영하지 않는다.
- 재시작 시 planning/validating 및 미완료 AI 작업은 interrupted로 기록한다. 자동 성공 추정·무제한 자동 재시도는 하지 않는다.
- 첫 사용 구간은 자동 생성·AI 재시도 0회, 실패 후 사용자 새 요청 또는 새 리뷰 행동으로 재시도. AI 작업 90초, 훈련당 AI 최대 30회, 임시 근거 10분, AI 호출 직렬화. 측정 후 설정값 변경 가능. 후속 신규 생성기 연결에서 같은 요청의 재시도·parent_operation_id와 상한을 구현한다.

## 근거·대화·학습 상태

- 저장 근거: saved_execution_id와 같은 attempt_id·package/release/dataset를 서버 확인. 보고서에는 성공한 선택 저장 근거만 연결.
- 임시 근거: execution_id와 현재 훈련·유효기간 확인. 코칭에 사용 가능하지만 SQL·결과·그 자료를 재현하는 사용자/코치 원문은 영구 메시지에 저장하지 않는다. 새로고침 시 코칭 화면에서도 제거한다.
- 일반 대화는 자동 저장하되 요청에서 transient=true를 선택 가능. SQL·결과로 의심되는 입력은 보수적으로 임시 처리한다. 자동 판별을 저장 안전성의 유일한 근거로 삼지 않고 입력 영역과 임시 처리 선택을 제공한다.
- 저장 대화에서도 임시 근거로 얻은 사실을 다음 호출에 재사용하지 않는다. 저장된 초안·보고서·SQL은 기존의 명시적 작성·선택 저장 계약을 따른다.
- 학습 상태는 리뷰와 도움 기록에 연결된 관측 사실과 추천으로 표현한다. 한 점수로 능력을 확정하거나 힌트 사용을 자동 감점하지 않는다. 사용자는 요청 수준과 다음 과제 유형을 변경할 수 있다.

## 코칭·평가

- 의미 있는 행동별 action_id와 trigger(question/sql_result/report)로 자동 코칭 중복을 막는다. 타이핑에는 호출하지 않는다. 자동 코칭 기본 꺼짐, 켜기 선택 시 비용·한도를 안내. 직접 질문은 항상 가능.
- 반환 행동은 clarify/check/suggest_analysis/submit/hint 중 하나와 이유·다음 행동을 제공한다. 실제 조회하지 않은 수치를 조회한 것처럼 말하지 않는다.
- 과제별 배점 합은 100. 계산 없는 design에는 sql_accuracy를 적용하지 않는다. 대안 풀이·불확실성·근거 있는 한계를 인정하고 비공개 사건을 입증하도록 요구하지 않는다.
- 평가 형식·참조 ID·수준·배점을 서버 검증해 총점 계산. 숫자 노출·오진 등 의미적 품질은 실제 모델 반복 표본과 사람 판정으로 별도 승인한다. 초기 사용 버전의 리뷰는 시험 운영으로 표시한다.

## 이벤트·보관·삭제

event_id, event_type, schema_version, occurred_at(UTC), operation_id, parent_operation_id, request_id, attempt_id, 상태·고정 오류 코드·duration_ms·model·nullable 토큰 사용량과 누락 이유를 이벤트별 허용 목록으로 검증한다. SQL·결과 행·대화·프롬프트·응답·키는 허용하지 않는다.

중복 event_id는 동일 내용만 허용. 지표에는 정의 버전·기간·분모·누락·실패·취소·진행 중을 표시한다. 초기 화면은 서버에서 관측 가능한 출제 상태·AI 상태·사용량·대기 집계를 제공하며 의미적 지표는 사람 판정 수집 전 미측정으로 표시한다.

훈련 기록은 사용자가 삭제할 때까지 보관하고 운영 이벤트는 초기 30일 보관(설정 가능). 삭제는 명시적 화면 확인 후 훈련·대화·근거·보고서·리뷰·연결 판정·관련 요청·이벤트를 함께 제거하며 집계를 다시 계산한다. 공유 데이터 패키지는 다른 훈련에서 사용하므로 삭제하지 않는다. 로컬 내보내기 파일·백업은 앱 삭제 범위에 포함되지 않음을 안내한다.

## 기존 호환과 변경 순서

기존 contract_version=v1 기록에는 새 필드를 강제하지 않는다. 신규 DB 테이블 추가 → 기존 API 회귀 검증 → 새 요청 API → 새 화면 순서로 연결한다. 기존 훈련의 패키지·평가 버전은 유지한다. 새 평가 규칙은 신규 요청 훈련에 적용하고 기존 훈련 리뷰를 소급 변경하지 않는다.
