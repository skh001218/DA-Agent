## 결정과 구현 기본값

사용자가 이번에 결정한 것은 데이터 분야·작은 규모부터 진행하는 방향이다. 기본 유저 200명, 생성 시도 최대2회, 요청 설계 AI 최대3회, 준비300초·단계60초는 이를 구현하기 위한 설정 가능한 초기값이다. AI90초·훈련30회·직렬화·자동 재시도0회·임시근거10분·운영로그30일은 기존 Spec 006을 유지한다. 초기값은 성능·비용·품질 검증 후 조정하고 변경 이유·버전을 기록한다.

AI 요청 해석·계획은 승인된 생성·검증 능력 안에서만 수행한다. 임의 생성 코드를 실행하지 않고 새 분야·규칙은 사람 검토 후 사용 가능 등록한다. 매 과제는 자동 데이터 검증 후 출제한다.

## 진행도와 현재 한계

008~013의 구현을 통합했다. 완료 조건별 진행도는 008 4/6, 009 5/5, 010 2/5, 011 0/5, 012 2/4, 013 2/6이며 각 문서 상단의 근거를 따른다. 011은 화면 코드와 일부 실제 흐름을 확인했지만 각 행의 모든 유형·장애 조건을 확인하지 않아 검증 대기다. 기존 007은 삭제 취소의 실제 화면 확인으로 5/5가 되었다.

학습 상태/로그/지표, 코칭/평가, 화면은 새 관리 워크트리 3개와 서브에이전트로 분리했다. 공통 계약과 API, 생성/검증/공개, 추천은 주 작업 공간에서 순차 연결하고 모든 커밋을 통합했다. 기존 DB 볼륨과 사용자 기록을 초기화하지 않았다.

자동/실제 DB 회귀, 실제 모델 요청·SQL·리뷰·재개, Chrome의 삭제 취소·학습 저장·8종 지표·다운로드·390px를 실행했다. [백엔드 검증](../tests/verification-v2-backend-2026-10-04.md), [화면 검증](../tests/verification-v2-ui-2026-10-04.md)을 참고한다. 신규 규칙은 draft이며 운영 화면에서 실제 3단계 표본을 사람이 검토한 뒤 승인해야 한다. 의미적 품질·다른 PC/ARM·5명 파일럿은 완료로 표시하지 않는다.
