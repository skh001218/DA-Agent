[Spec035](035-discord-sql-practice-mode.md)은 `/training`의 필수 SQL/분석 선택, 제공된 `sql` 코드 블록을 채운 답장 제출, 실제 SQL 실행·오류 수정·재제출, SQL 전용 평가와 완료 분석 연결을 다룬다. 코드·격리 DB 검증을 마쳤으며 4/8개 완료(50%)다. 실제 Discord 선택·입력·결과 화면은 검증 대기이며 실행 봇에는 아직 반영하지 않았다. [검증 기록](../tests/reports/verification-spec035-2026-10-06.md).

## 평가 신뢰성 공통 검증 흐름 (2026-10-06)

[Spec033](033-trustworthy-evaluation-quality-loop.md)은 공개 기준·인용·중복 감점 검증, 평가당 최대1회 수정, 여섯 표본×세 번 반복 검사, 유형 검증 미통과 시 점수 보류·분석 피드백, 수정 오류 비교와 새 지표 등록 절차를 다룬다. 코드/자동·화면 검증과 실제 모델 품질 승인은 구분한다. 최신 진행도는 Spec 상단과 [검증 보고](../tests/reports/verification-spec033-2026-10-06.md)를 따른다.

## Discord 평가 검산·수정 재제출 (2026-10-06)

[Spec032](032-discord-evaluation-verification-and-resubmission.md)은 저장 실행 기반의 제한된 계산 검산과 완료 보고의 새 버전·후속 답변·재평가, 이전 제출 비교를 다룬다. 정의한 코드·격리 서비스·카드 미리보기 검증은5/5개 완료다. 실행 봇 배포·실제 Discord 전달과 모델 의미 평가 품질 보완은 남아 있다. [검증 기록](../tests/reports/verification-spec032-2026-10-06.md)에 성공과 API 보류를 구분했다.
## Discord 분석 결과 PDF (2026-10-06)

## PRD-v2 기준

- 작성일: 2026-10-04 (Asia/Seoul)
- 기준: [PRD-v2.11](../docs/PRD-v2.md), 최신 검증 반영일 2026-10-05
- 결정: 접속 데이터부터 작은 규모로 신규 생성·검증하고 다른 분야는 후속으로 확장한다. 사용자 이유는 개발 중 작은 데이터로 테스트한 뒤 다른 데이터를 추가해 테스트하기 위해서다.

## 결정과 구현 기본값

사용자가 이번에 결정한 것은 데이터 분야·작은 규모부터 진행하는 방향이다. 기본 유저 200명, 생성 시도 최대2회, 요청 설계 AI 최대3회, 준비300초·단계60초는 이를 구현하기 위한 설정 가능한 초기값이다. AI90초·훈련30회·직렬화·자동 재시도0회·임시근거10분·운영로그30일은 기존 Spec 006을 유지한다. 초기값은 성능·비용·품질 검증 후 조정하고 변경 이유·버전을 기록한다.

AI 요청 해석·계획은 승인된 생성·검증 능력 안에서만 수행한다. 임의 생성 코드를 실행하지 않고 새 분야·규칙은 사람 검토 후 사용 가능 등록한다. 매 과제는 자동 데이터 검증 후 출제한다.

## 진행도와 현재 한계

평가 기준v3는 [코드·검증 기록](../tests/reports/verification-evaluation-v3-2026-10-05.md)에 따라 새 출제에 연결했다. Spec010의v3 세부 구현/검증4/5 완료(80%)와 상위2/5를 구분한다. 최종18회 형식/출처 정상이나 핵심 오류 조건 변화로 품질fail·사람 승인false를 유지한다. 8087 화면 작업은 보존하며 일반 앱 반영은 화면 브랜치 통합 후 진행한다.

최신 수정 후 [재검증](../tests/reports/verification-prd-v2-revalidation-2026-10-05.md): 실제 DB255개 통과, 화면10개 중8개 전체통과·2개 평가차단, 조사 중급/고급은 별도 화면 작업 반영 후 재검증. 코칭 완료16/18·기대 행동14/18, 평가 완료17/18·형식 실패1·핵심 오류 편차13.8점으로 품질판정fail을 유지한다. 아래 이전 회차는 역사적 기록이며 최신 상태는 각 Spec 상단을 따른다. 분모·완료 수는 유지한다.

008~013의 구현을 통합했다. 완료 조건별 진행도는 008 4/6, 009 5/5, 010 2/5, 011 2/5, 012 3/4, 013 2/6이며 각 문서 상단의 근거를 따른다. 2026-10-05 재검증에서 011의 요청·출제 진행 및 판정·지표 운영 화면을 완료로 갱신했다. 해석 템플릿 적용 후 추천 그대로 기존 데이터ready를 확인해012 계약·화면 연결도 완료로 갱신했다. 승인 신규 생성 연결·전체 장애/난이도 화면은 남아 있다. 기존007은 삭제 취소의 실제 화면 확인으로5/5가 되었다.

학습 상태/로그/지표, 코칭/평가, 화면은 새 관리 워크트리 3개와 서브에이전트로 분리했다. 공통 계약과 API, 생성/검증/공개, 추천은 주 작업 공간에서 순차 연결하고 모든 커밋을 통합했다. 기존 DB 볼륨과 사용자 기록을 초기화하지 않았다.

자동/실제 DB 회귀, 실제 모델 요청·SQL·리뷰·재개, Chrome의 삭제 취소·학습 저장·8종 지표·다운로드·390px를 실행했다. [백엔드 검증](../tests/reports/verification-v2-backend-2026-10-04.md), [화면 검증](../tests/reports/verification-v2-ui-2026-10-04.md)을 참고한다. 신규 규칙은 draft이며 운영 화면에서 실제 3단계 표본을 사람이 검토한 뒤 승인해야 한다. 의미적 품질·다른 PC/ARM·5명 파일럿은 완료로 표시하지 않는다.


## 2026-10-05 요청별 데이터 확장

[Spec 014](014-request-specific-synthetic-data.md)는 사용자 요청에 맞춘 과제·합성 데이터 설계와 자동 검증 후 시험 과제 제공 경로를 추가한다. 사용자가 이 경로는 사람 승인 전에도 자동 검증을 통과하면 시험 과제로 제공하도록 선택했다. 위의 신규 규칙 사람 승인 정책은 기존 접속 규칙에 유지하고, adaptive 경로의 시험 과제 제공과 사람 품질 승인 상태를 구분한다. 최종 진행도는 Spec 014를 따른다.

[Spec 015](015-adaptive-generation-repair.md)는 여러 요청에 공통인 원본·요약·시간 일관성과 실패 수정·이력 보존을 다룬다. adaptive 호출 상한은 이 Spec부터 6회이며 기존 접속 경로의 3회는 유지한다.

## 2026-10-05 검증 대기 재검증

[검증 기록과 직접 확인 목록](../tests/reports/verification-prd-v2-pending-2026-10-05.md)을 PRD와 Spec 008·010~013에 반영했다. 실제 DB242개 통과, 네 유형 제출·수정·리뷰·재개·390px, 요청/운영 충돌·취소·재시도·삭제·다운로드를 확인했다. 현재 모델 코칭16/18회 형식 실패·응답2회 행동 불일치, 평가 핵심 오류 편차13.8점, 추천 해석 형식 실패를 보존하고 제품 전체 진행도5/11을 유지한다. 운영자 사람 검토 표본12개는 준비했으며 승인하지 않았다. 테이블 생성 제약 확장은 사용자 요청에 따라 계속 보류한다.

2026-10-05 후속 [실패 원인 보완](../tests/reports/verification-v3-failure-fixes-2026-10-05.md): 전체DB289·단위68·Chrome 충돌 코칭/리뷰 저장/재개 통과. 평가 입력·누락/오류·철회·명시 충돌 규칙·API 진단을 보완했으며 해당 표본은 안정화됐지만 전 유형·사람 품질 대기를 유지한다.
