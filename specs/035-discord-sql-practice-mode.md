## 1. 요청과 범위

사용자 요청은 `/training`을 시작할 때 **SQL 연습 / 분석 연습**을 필수로 선택하게 하고, SQL 연습 요청은 [Discord PRD 10절](../docs/prd-discord.md#10-후속-sql-연습)의 직접 작성·실행·수정·평가 흐름으로 처리하도록 Spec을 작성하는 것이다. 요청의 `/traning`은 현재 등록된 `/training`을 가리키는 것으로 해석한다.

이 문서는 구현 계약이다. 문서 작성 이후 사용자의 `코드 구현까지 가보자` 요청에 따라 현재 체크아웃의 봇 코드와 검증 자료를 추가했다. 초기 구현 당시 운영 봇은 변경하지 않았고, 2026-10-07 사용자 요청에 따라 운영 봇을 배포·검증했다. 기존 DB 기록은 보존했다. 필수 연습 유형과 SQL 코드 블록 답장 입력은 사용자 확정 요구사항이다.

첫 구현은 현재 지원하는 `topic:tutorial` 데이터와 지표를 사용한다. 임의 주제 출제·임의 스키마 확장은 포함하지 않는다. D7·주간 재방문 문제는 해당 데이터와 출제 전 검증 자료가 준비된 경우에만 제공하고, 준비되지 않은 문제를 완료율 문제로 조용히 바꾸지 않는다.

## 2. 시작 명령과 호환

`/training practice:<선택> topic:<기존 주제> difficulty:<기존 난이도> help_level:<기존 도움 수준> source_session_id:<선택>`

| 속성 | 필수 여부 | 값 / 동작 |
| --- | --- | --- |
| `practice` | 필수 | 표시 `SQL 연습` / `분석 연습`, 저장 `sql` / `analysis`. 기본값 없음 |
| `topic` | 선택 | 기존 `tutorial` 기본값·지원 목록 유지. 연결 과제에서는 원본 주제를 사용 |
| `difficulty` | 선택 | 기존 `beginner` / `intermediate` / `advanced`, 기본값 `intermediate` |
| `help_level` | 선택 | 기존 `guided` / `independent` 정책 재사용; SQL 도움 이력은 별도 기록 |
| `source_session_id` | 선택 | 완료 분석을 SQL 연습에 연결할 때만 사용. 본인·현재 서버·완료 분석 여부 확인 |

- Discord 등록과 서비스 진입점 모두 `practice` 누락·지원 밖 값을 거부한다. 누락을 자동으로 분석 연습으로 처리하지 않는다. 검증 실패 시 과제·데이터·스레드를 만들지 않는다.
- `/training practice:analysis`는 기존 자연어 조회→가설·해석→보고→평가 흐름으로 분기한다.
- `/training practice:sql`은 SQL 과제 흐름으로 분기한다. 진행 중 세션의 유형은 변경하지 않으며 변경하려면 새 과제를 시작한다.
- `source_session_id`가 있는 경우 원본 주제와 명시적 `topic`이 충돌하면 생성을 거부하고 안내한다. SQL 연습의 난이도는 새 요청 기준으로 적용한다.
- 기존 유형 없는 저장 세션은 재개·기록 조회 시 `analysis`로 해석한다. 과거 기록을 삭제하거나 새 SQL 성적으로 재해석하지 않는다. 새 과제 생성 요청의 필수 검증과 구분한다.
- PRD의 `/sql연습` 예시는 이 필수 선택으로 대체한다. 별도 시작 명령이나 `/traning` 별칭은 이번 범위에 넣지 않는다.

예: `/training practice:SQL 연습 topic:tutorial difficulty:중급` → SQL 문제 안내, `/training practice:분석 연습 topic:tutorial` → 기존 분석 과제 안내. 표시값과 내부 저장값을 안내 예시에서 혼동하지 않는다.

## 4. 공개 문제와 난이도

공개 문제에는 문제 ID·버전, 연습 유형, 주제·난이도, 데이터 버전, 표·열·관계·행 단위, 지표 정의, 집계 단위, 기간과 시간대, 관측 종료, 필요한 분자·분모, 출력 열·자료형·정렬 요구, 0 분모/NULL 처리, 공개 평가 기준, 실행 제한을 포함한다.

초급은 용어·지표 정의와 작은 단계별 요구를 제공한다. 중급은 필요한 정의를 공개하되 조인·집계·쿼리 구조를 학습자가 결정한다. 고급은 중복·코호트·관측 경계 등을 함께 다루며 검증 방법도 설명하도록 요구한다. SQL 블록 밖의 중복·기간·분모/NULL 방법을 별도 저장·검토한다. 타당한 추가 검산 계획도 방법 설명으로 인정하되 실제 수행 여부와 학습 효과의 증거로 간주하지 않는다. 설명 누락은 보완 필요, 검토 연결/응답 실패는 판정 보류다. 기존 v1 과제는 생성 당시 계약을 유지한다. 난이도별 실제 문제·검증 표본을 먼저 작성하고 문구만 바꿔 난이도를 구분하지 않는다.

비공개 자료에는 기준 SQL, 기준 전체 결과, 검증 데이터·기대 결과, 판정 규칙·버전을 보관한다. 기준 SQL은 과제 안내, 데이터 사전, 일반 힌트, 오류 응답, 공개 로그·첨부에 포함하지 않는다. 제출 전 정답을 생성해 공개하지 않는다.

- D7: 가입 날짜 + 7일 접속 여부, 관측 완료 신규 가입 코호트만 분모에 포함. 문제의 시간대·관측 종료 경계를 고정한다.
- 주간 재방문: 첫 기간의 고유 접속자 중 두 번째 기간 접속자 비율. D7과 다른 지표임을 명시한다.
- 튜토리얼 완료율: 공개 가입 기간의 전체 고유 가입자 중 관측 기간 내 3단계 완료 고유 가입자 비율. 도전하지 않은 가입자도 분모에 포함한다. 재도전·조인 중복을 포함한 테스트 데이터를 준비한다.
- 공개 명세가 모호하거나 기대 결과가 서로 충돌하면 학습자 오답으로 평가하지 않고 문제 판정을 보류한다.

## 5. SQL 입력과 명령별 역할

### 5.1 사용자 확정: `sql` 코드 블록을 채운 답장

봇은 과제 안내에 다음 코드 블록과 `이 틀을 복사해 SQL을 작성한 뒤 이 메시지에 답장하세요` 안내를 제공한다. 봇 메시지 자체를 수정하는 입력창으로 표현하지 않는다. 모달은 이번 입력 방식에 포함하지 않는다.

````markdown
```sql
-- 여기에 풀이 SQL을 작성하세요.
```
````

사용자는 틀을 복사해 채운 `sql` 코드 블록을 봇의 문제/풀이 요청 메시지에 답장으로 보낸다. 소유자·현재 서버·SQL 과제 스레드·답장 대상 봇 메시지 ID를 검증한 뒤 SQL 제출로 처리한다. 답장이 아닌 일반 대화나 다른 메시지에 대한 답장은 실행하지 않는다. 멘션이 필요한 수신 환경이면 해당 답장에 봇 멘션을 넣도록 안내한다.

- 메시지 전체에 정확히 하나의 `sql` 언어 코드 블록을 요구한다. 코드 블록 밖의 설명은 대화 원문으로 보존하되 실행 문자열에 넣지 않는다. 다른 언어·여러 블록·닫히지 않은 블록은 실행하지 않고 틀을 다시 안내한다.
- 코드 구분자만 제거하고 내부 SQL의 조건·구조는 바꾸지 않는다. 원문 메시지와 실제 실행 문자열을 모두 저장한다. 공백·주석만 있는 틀은 실행 시도를 만들지 않는다.
- 첫 결과와 오류 안내에도 새 답장 대상으로 사용할 메시지 ID를 기록하고, `수정한 전체 SQL을 sql 코드 블록으로 다시 답장`하도록 안내한다. 과거 실행 결과에 답장한 수정은 해당 시도를 부모로 연결하고 최신 결과를 덮어쓰지 않는다.
- 전송한 메시지의 사후 편집은 자동 재실행하지 않는다. 수정 재실행은 새 답장으로 요청한다. 중복 Gateway 전달은 Discord 메시지 ID로 중복 실행을 억제한다.
- 클라이언트·봇 설정에 맞는 코드 블록 포함 최대 길이를 구현 시 확인해 안내한다. SQL이 길면 여러 메시지를 자동 합쳐 실행하거나 잘라 실행하지 않고 한 번에 제출 가능한 길이를 안내한다.
- 일반 메시지 수신은 Message Content Intent와 `DISCORD_MESSAGE_CONTENT` 설정을 확인한다. 코드 블록 답장 제출을 실제로 확인한 뒤 기본 흐름 완료로 판정한다. 내용이 비어 수신되는 환경에서는 성공·실행으로 처리하지 않고 멘션 답장 또는 슬래시 대안을 안내한다.

| 입력 | SQL 연습에서의 역할 |
| --- | --- |
| 문제/풀이 결과에 `sql` 코드 블록 답장 | 기본 제출. 블록의 학습자 SQL을 검사·실행·저장하고 시도 ID와 실제 결과 반환 |
| `/sqlrun text:...` | 메시지 내용 수신이 제한된 환경의 대안. 동일 코드 블록 입력·검사·실행 경로 사용 |
| `/sql execution_id:...` | 본인 과제의 제출·실행 SQL 열람. 기존 열람 명령을 풀이 제출로 바꾸지 않음 |
| `/help` | 사전·평가 기준·개념·방향·중간 검토 제공. 도움 유형과 노출 기록 |
| `/query` | 자연어 자동 SQL 실행을 거부하고 직접 풀이 입력 안내. 정답 경로 우회 방지 |
| `/report`, `/followup`, `/evidence` | 분석 보고용 동작을 실행하지 않고 SQL 작성·제출 경로 안내 |
| `/submit execution_id:<선택>` | 본인 문제의 성공 시도 선택·SQL 전용 최종 평가. SQL 모드에서는 생략 시 최신 성공 시도 사용 |
| `/end`, `/resume`, `/history` | 중단·복원·유형별 이력 확인. 입력 SQL·실행·평가 버전 보존 |

`/submit`에 선택 `execution_id`를 추가해도 분석 모드의 기존 무인자 제출은 유지한다. 분석 모드에서 이 인자를 받으면 조용히 무시하지 않고 안내한다. SQL 모드에서 최신 시도가 실패했지만 이전 성공 시도가 있으면, 생략 제출은 막고 이전 성공 ID를 명시하도록 안내한다. 성공 시도가 없으면 실행 후 제출하도록 안내한다.

SQL 모드의 등록된 풀이 요청/실행 결과에 대한 유효 코드 블록 답장만 자동 SQL 제출로 처리한다. 코드 블록 없는 답장은 도움 대화로 처리하거나 입력 안내를 제공하며, 분석 모드의 기존 답장 흐름은 유지한다. Message Content Intent가 꺼져 있어도 슬래시 대안으로 실행할 수 있어야 한다. 대안 검증만으로 사용자가 요청한 기본 코드 블록 답장 흐름을 완료 처리하지 않는다.

## 6. 실행과 시도 보존

`SQL 입력 → 소유권·유형·문제/데이터 버전 확인 → check_query → SqlRunner.execute → SqlRunner.get → 영구 저장 → 결과 표시`를 하나의 명확한 처리 경로로 제공한다. 실제 runner의 호출 계약에 맞춰 연결하며 임시 결과 TTL에 의존해 재개하지 않는다.

- 하나의 허용된 읽기 전용 조회만 실행한다. 기존 허용 표·함수·쿼리 시간·행/바이트 제한을 적용하며 공개하지 않은 표나 기준 자료 접근을 막는다.
- 사용자 SQL을 모델이 만든 정답 SQL로 대체해 실행하지 않는다. 문법 검사 성공을 결과·의미 정확성으로 처리하지 않는다.
- 시도마다 새 `attempt_id`와 `execution_id`를 부여하고 이전 성공·실패 시도를 보존한다. 전달 재시도는 같은 이벤트로 처리해 중복 실행·채점을 억제한다.
- 실행 결과는 상태, 열/자료형, 미리보기, 전체 수집 결과, `result_complete`, 제한·소요 시간, 안전한 오류를 기록한다. 실제 DB 결과만 보여준다.
- 미리보기 제한과 전체 결과 불완전을 구분한다. 불완전 결과로 정답 판정을 내리지 않는다. 빈 결과·NULL·분모 0도 문제 명세에 따라 처리한다.
- 문법·표·열 오류와 정책 차단은 풀이 수정 안내를 제공한다. DB 연결·모델 장애는 인프라 실패/판정 보류로 기록하며 오답 감점으로 바꾸지 않는다. 원시 DB 예외·접속 정보는 노출하지 않는다.
- 기존 비용·동시 처리·호출 한도와 재시도 정책을 적용한다. SQL 실행과 모델 평가 비용을 구분하고 DB 실행 자체를 모델 호출로 세지 않는다.

## 7. SQL 전용 평가와 피드백

분석 보고 평가를 그대로 사용하지 않는다. 문제 생성 시 아래 항목의 공개 기준과 적용 여부를 고정하고, 선택한 시도 ID·문제/데이터/루브릭 버전에 연결한다. 이번 첫 버전은 검증 가능한 항목별 판정(`충족`, `보완 필요`, `해당 없음`, `판정 보류`)을 제공한다. 별도 총점·SQL 역량 등급은 타당성 검증 전 만들지 않는다.

| 항목 | 판정 근거 |
| --- | --- |
| 구문·실행 가능성 | 실제 파싱·읽기 전용 실행 성공. 정책 차단과 인프라 실패 구분 |
| 계산 의미·출력 | 요구 열·집계 단위·비율 단위·전체 결과의 기준 비교 |
| 중복 처리 | 고유 사용자·재도전·조인 증폭 데이터에서 기대 계산 확인 |
| 기간·관측 | 경계 시각·시간대·코호트·D7 관측 완료 여부 확인 |
| 분모·누락 | 분자/분모 대상·0 분모·NULL·관측 부족 처리 확인 |

문자열이 기준 SQL과 같아야 정답이라는 규칙을 사용하지 않는다. CTE·서브쿼리·타당한 다른 조인 등 동등 풀이를 인정한다. 한 데이터에서 우연히 같은 값이나 상수 출력이 나오면 의미 정답으로 확정하지 않는다. 동일 스키마의 비공개 검증 데이터에 학습자 SQL을 실행해 경계·중복·빈 집합 등을 대조한다. 기준 결과는 독립 계산과 교차 검증하고, 정렬이 요구되지 않으면 행 순서를 무시하되 행의 중복 수는 비교한다. 수치 허용 오차·자료형/NULL·필수 열의 비교 규칙은 문제 계약에 고정한다.

이 검증은 준비된 문제와 검증 데이터 범위의 근거이며 모든 SQL에 대한 수학적 동치 증명으로 표현하지 않는다. 지원하지 않는 유효 쿼리의 의미는 오답 확정 대신 판정 보류·검토 필요로 표시한다. 모델은 검증 근거에 연결된 설명을 만들며 실행 실패·비교 결과를 임의로 바꾸지 않는다. 모델 실패 시 검증된 실행·비교 사실을 보존하고 설명/의미 판정 미완료를 표시한다.

실행 피드백은 상태·결과·수정 방향을 제공하고 정답 전체를 자동으로 공개하지 않는다. 최종 평가도 항목별 근거·보완점을 제공한다. 해설/정답 공개는 첫 SQL 제출 이후 학습자가 명시적으로 요청한 경우에만 허용하며, 노출 이후 풀이를 무보조 독립 성적으로 기록하지 않는다. 도움·정답 열람 이력은 숨기지 않고 결과와 함께 표시한다.

수정 재제출은 새 평가 버전을 생성하고 이전 시도·평가·노출 이력을 보존한다. 같은 평가 요청 재전달은 중복 평가·게시를 만들지 않는다. 게시 실패는 평가 실패와 구분하고 저장된 같은 결과로 재시도한다.

## 8. 완료 분석 연결·영구 기록·결과

완료 분석 연결은 `/training practice:sql source_session_id:<본인 완료 분석 ID>`로 새 SQL 세션을 만든다. 원본 분석을 SQL 유형으로 바꾸지 않는다. 공개 지표·기간·데이터 정의를 바탕으로 작성 과제를 만들며 원본 데이터 버전을 재사용하거나 새 버전을 검증·적재한다. 원본 스키마가 없어졌으면 새 데이터 버전임을 명시하고 원본과 동일 결과라고 주장하지 않는다.

원본의 `/sql` 열람, SQL 보기 버튼, 결과 카드·PDF 등 정답 SQL 노출 경로를 추적한다. 이미 공개된 자료 등 노출 여부를 확실히 알 수 없으면 `미상`으로 기록하고 독립 풀이 능력으로 단정하지 않는다. 열람 이력이 있으면 `열람 후 재현 연습`으로 표시하고 다른 문제의 무보조 풀이와 분리한다.

영구 세션 문서에는 최소한 다음을 보존한다.

- `practice`, 문제 ID·버전, 공개 계약, 주제·난이도·도움 수준, 데이터·루브릭 버전
- 원본 분석 세션 ID, SQL 노출 상태(`없음 확인` / `열람 확인` / `미상`)와 근거 이벤트
- 각 시도의 원문·실행 SQL·실행 ID·결과/오류·완전성·시각·부모 시도 ID
- 코드 블록 입력을 요청한 봇 메시지 ID, 제출 메시지 ID·답장 대상 ID·수신 방식; 멘션/슬래시 대안 여부
- 선택한 최종 시도, 항목별 평가·검증 근거·버전·보류 사유, 도움/해설 노출 이력
- 세션 수명 상태·스레드 연결·처리 이벤트·게시 결과 ID

문제 준비·진행·중단·완료 상태는 기존 수명 정책과 연결하고 평가의 `판정 보류`와 구분한다. `/resume`은 저장 기록에서 유형·문제·최근 시도·평가를 복원한다. 완료 후 열람은 보관·잠금을 해제하지 않는다. 명시적 새 SQL 실행/수정만 본인 세션을 다시 열고 새 버전을 만들며 이전 결과는 보존한다.

스레드 제목·첫 카드·`/history`에 연습 유형을 표시해 같은 주제의 SQL·분석을 구분한다. 제목 길이·중복 순번 정책은 Spec034를 따른다. SQL 결과는 문제, 제출 SQL, 실행 결과, SQL 전용 평가, 도움·노출 상태를 표시하며 분석 보고서 평가로 잘못 표시하지 않는다. 기존 포럼/PDF를 재사용할 경우 유형별 렌더러를 연결하고 비공개 기준 SQL·검증 데이터·원본 비공개 대화를 게시하지 않는다. 새 공개 범위 옵션은 추가하지 않고 기존 본인/서버 접근·게시 정책을 따른다.

## 9. 구현 연결과 검증

기존 Discord 전송·저장·수명·테이블 표시와 `sql_runner.py`를 재사용한다. SQL 문제 계약·기준 검증·SQL 평가는 별도 모듈로 분리해 `discord_service.py`의 유형 분기로 연결한다. 기존 자연어 컴파일러 `DiscordQueryEngine`은 분석 연습 경로에 남기고 SQL 제출의 실행 문자열을 생성하는 데 사용하지 않는다.

| 검증 사례 | 완료 조건 / 근거 |
| --- | --- |
| 명령 필수 선택 | 등록 스키마에 `practice` 필수·두 선택 표시, 서비스 누락/잘못된 값 거부·생성 부작용 없음 |
| 분석 회귀·기존 기록 | 기존 분석 조회·보고·평가 유지, 유형 없는 과거 기록을 분석으로 재개 |
| 문제 준비·정보 분리 | 공개 요구·난이도 기준 제공, 기준 검증 실패 시 출제 중지, 제출 전 정답 노출 없음 |
| 직접 입력·수정 | 틀 제공→답장 블록 추출→실행 일치, 빈/주석만/여러 블록/잘못된 언어/닫힘 누락/초과 무실행, 새 답장 수정 시도 보존 |
| 답장 수신·대상·편집 | 올바른 봇 메시지 답장만 실행, 일반 대화·잘못된 대상 무실행, 제한 수신 대안 안내, 사후 편집 무재실행·중복 전달 억제 |
| 실제 DB 실행 | 정답·문법 오류·없는 열·읽기 정책 차단·시간 초과·DB 연결 실패를 실제 상태로 표시 |
| 의미·동등 풀이 | CTE와 대안 쿼리 인정; 상수 답·중복·경계·0 분모·NULL·관측 미완료를 검증 데이터로 판별 |
| 결과 제한·평가 장애 | 미리보기 제한과 불완전 수집 구분, 미완료/모델 실패 시 보류·기존 근거 보존 |
| 유형별 명령·노출 | SQL의 `/query` 정답 우회 차단, 명시적 해설 노출 기록, 분석의 SQL 실행 인자 오용 안내 |
| 최종 시도 선택 | 이전 성공 뒤 최신 실패 시 명시 선택 안내, 없는/타인/다른 문제 실행 ID 거부 |
| 연결 분석·권한 | 본인 완료 분석만 연결, 주제 충돌·진행 분석·다른 사용자/서버 거부, 열람/미상 구분 |
| 재시작·중복·게시 | 기록 복원, 같은 이벤트 중복 실행/평가 없음, 재평가 버전·게시 재시도 보존 |
| 결과·보관 회귀 | SQL 전용 결과 렌더링, 분석 결과 유지, 열람 보관 유지·명시 수정 재개 |

자동 검사는 격리 DB와 고정 검증 데이터로 수행하며 운영 데이터·봇을 초기화하지 않는다. 모델 평가를 모의 응답으로 확인한 결과와 실제 모델 품질 검증을 분리한다. 대표 정답·오답·동등 풀이·판정 보류의 설명 정확성은 사람 검토를 포함한다.

실제 Discord에서는 필수 유형 선택과 두 경로, 새 SQL 문제와 코드 블록 틀, 복사·작성·답장 수신, 빈 틀/잘못된 블록, 잘못된 SQL 실행→수정한 전체 SQL 새 답장→성공 결과, 성공 시도 최종 평가, 중단·재시작·재개, 완료 분석 연결·노출 표시, 결과 게시·열람을 확인한다. 멘션 유무·수신 설정별 동작과 슬래시 대안도 확인한다. 실시간 UI·DB 증거를 `tests/artifacts/`와 `tests/reports/`에 남긴다. 화면·실제 모델 확인 전 해당 작업을 완료로 올리지 않는다.

## 10. 관련 문서와 결정 상태

## Spec036 텍스트 출제와 통합 (PR #28)

현재 통합 명령은 practice와 text가 모두 필수다. SQL 예: `/training practice:sql text:튜토리얼 신규 가입자 3단계 완료율 difficulty:intermediate`. 분석 text는 Gemma 출제로 연결한다. SQL은 기존 튜토리얼 완료율 검산 계약을 유지하므로 다른 text 또는 생성 분석 과제의 SQL 연결은 지원 범위를 안내하고 거부한다. 기존 튜토리얼 완료 분석의 연결은 유지한다. 기존 문서의 명령 예시에 text를 함께 입력해야 한다.

통합 회귀: 전체573 passed/83 skipped, 실제 격리 DB의 Discord 생성·SQL·전송73 passed. 운영 배포·Discord 화면 검증 상태와 진행도는 변경하지 않는다. [통합 검증](../tests/reports/verification-spec036-2026-10-06.md).

## 동일 요청의 난이도 추가 점검

2026-10-06 현재 체크아웃에서 전체573 passed/83 skipped, 격리 PostgreSQL Discord 관련164 passed를 확인했다. 같은 요청과 independent 도움 수준, 같은 본 데이터에서 초급은 전체1행(75%), 중급은 채널별2행(70%/80%), 고급은 주차×채널별4행을 출력했다. 계산 구조 차이는 확인했지만 고급 검산 설명은 평가되지 않았다. `튜토리얼 완료율 대신 D7 리텐션을 계산해줘`가 완료율 SQL 과제로 바뀌는 문제도 재현됐다. 제품 수정·운영 배포·실제 Discord 검증은 수행하지 않았다. 상세 증거와 해결 방안은 [추가 점검 보고](../tests/reports/verification-spec035-036-levels-2026-10-06.md)에 기록했다. 위 통합 회귀 당시 진행도 유지 기록과 구분하여 현재 진행도는3/8(37.5%)로 갱신했다.
