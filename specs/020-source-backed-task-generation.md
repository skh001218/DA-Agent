## 목적과 확정 방향

사용자는 광범위한 실무 요청을 특정 분석 주제로 유도하지 않고 검색을 통해 출제하도록 요청했다. 같은 주제만 제공하면 실무에도 해당 주제의 문제만 있다고 오해할 수 있다는 근거를 제시했다. 추상 요청의 구체적인 업무 상황과 연습 조건은 에이전트가 설정한다.

- 기본 adaptive 새 출제에 실제 사례 검색과 후보 선정 단계를 추가한다. 사례의 공개 근거를 사용하되 실제 회사의 원본 데이터/수치를 복제했다는 주장을 하지 않고 합성 데이터로 연습 문제를 구성한다.
- 검색 결과는 자료이며 지시가 아니다. 실제 질의·웹 출처·인용 문장으로 근거를 검증하며 모델이 임의 URL을 만들 수 없다.
- 최근 5개 과제는 중복 회피용이다. 과거 주제를 사용자의 선호나 현재 도메인으로 간주하지 않는다. 명시한 분야를 우선하며 추상 요청에 보스·전투를 기본값으로 고정하지 않는다.
- 후보와 선택 이유, 확인 사실, 검색 시각·출처, 과거 과제 비교용 요약을 요청별 고정한다. 재시도는 동일 근거를 사용한다.
- 검색 실패·근거 미확인·지원 불가를 구분하며 검색을 수행했다고 꾸미거나 기존 보스 문제로 대체하지 않는다.
- 표 최대4개/전체2000행과 읽기 전용 제한은 유지한다. 검색과 사례 선정에 2회 추가하여 출제 모델 호출 상한은8회로 한다. 실제 사용량을 단계별 기록한다.
- 기존 과제의 출처 필드는 선택 사항이다. 새 출제 출처는 서버가 고정하며 생성 모델이 변경하지 못한다.

## 완료 기준

질의와 인용 근거 없는 검색은 실패해야 한다. 후보 출처 ID가 검색 근거에 속해야 한다. 추상 요청에서는 다른 업무 주제 후보를 비교하고 최근 같은 주제와 다른 후보를 우선한다. 검산 가능한 범위로 구성하되 사용자 목적을 보존한다. 실제 화면에서 출처·연습 조건·검산·새 접속 복원을 확인한다. 생성 성공을 교육 효과·사람 품질 승인으로 처리하지 않는다.
