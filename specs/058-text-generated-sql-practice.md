## 목적과 범위

사용자는 원하는 분석 주제를 자유롭게 지정하기 위해 SQL도 분석 연습처럼 text 기반으로 문제를 생성하도록 요청했다. 초기 범위는 구현과 난이도별 리텐션 테스트이며, 후속 요청으로 PR·main 병합·운영 배포·실제 동작 확인을 추가했다. 이 범위 확대에 따라 전체 작업을 4개에서 5개로 늘렸다.

## 사용 흐름

`/training practice:sql text:<분석 주제·목표> difficulty:<난이도>` → 요청 해석·문제와 합성 데이터 설계 → 독립 검산 → 코드 블록 직접 풀이 → 실행·오류 수정 → `/submit`.

기존 text 없는 내부 고정 과제와 저장 기록은 유지한다. text 경로는 주제 키워드로 튜토리얼 문제에 고정하지 않는다. 핵심 의도 충돌은 확인 질문, 현재 선언형 생성·검산 연산으로 목표를 달성할 수 없으면 원래 주제를 바꾸지 않고 출제를 보류한다. 기존 완료 분석 연결은 text 기반 SQL에서 아직 지원하지 않으며 명시적으로 안내한다.

## 출제와 채점 계약

- 모델은 실행 SQL이 아닌 Recipe를 설계한다. 공개 관계·행 단위·조건·집계·출력 열을 고정한다.
- 지원 계산은 COUNT/DISTINCT/SUM/AVG/MIN/MAX/ratio와 최대 3개 그룹·FK 조인이다. 한 문제는 한 분석 지표를 계산한다. ratio는 denominator/numerator와 비율을 함께 출력한다.
- Python 기준 집계와 앱이 컴파일한 SQL을 실제 PostgreSQL에서 대조한다. 본 자료·시드와 표본 크기가 다른 두 자료·빈 데이터에서 결과를 비교한다. 이 검증을 모든 SQL의 동치 증명으로 표현하지 않는다.
- 숫자·NULL·시간대·열 순서·행 수를 검증하며, 행 순서는 무관하다. 실행 실패·부분 결과·고급 설명 검토 장애는 의미 판정을 보류한다.
- 정답 SQL과 기대 결과는 소유자별 비공개 generation_job에 저장한다. 문제·사전·일반 힌트·결과 카드에 유출하지 않는다. 정답은 첫 제출 후 명시적 해설 요청에만 공개한다.
- 초급: 전체 집계와 명확한 조건. 중급: 실제 FK 조인과 그룹 집계. 고급: 두 그룹 차원·FK 조인·COUNT 외 계산·관측/필터와 검산 방법 설명.
- 리텐션은 단위·Dn 정의·관측 완료 모집단·무접속자 포함을 공개한다. 요약 자료를 사용하면 이용자별 관측 요약임을 밝히고 로그에서 계산했다고 주장하지 않는다.
