## 목적과 범위

[PRD-v2](../docs/PRD-v2.md) 6·10·14·15절과 [Spec 006](006-request-training-contracts.md)을 따른다. 기존 첫 사용 이벤트·대화를 재작성하지 않고, 누적 학습 상태와 의미적 품질 판정 및 전체 집계를 추가한다. 본 문서의 0%는 확장 작업만의 진행도다.

## 기록 계약

- 학습 상태는 `state_revision`, `updated_at`, `observations`, `preferences`, `overrides`로 구성한다. 관측은 `observation_id`, 역량 항목, 확인한 행동, 출처 훈련·보고서·리뷰·판정 ID, 적용 버전, 확실성, 유효 여부를 가진다. 점수 하나로 숙련도를 확정하지 않는다.
- 역량 항목은 문제 정의, 지표·집계, 분석 설계, 근거 해석, 한계·다음 행동이다. 관측이 없으면 미관측이다. 실패 리뷰와 판정 미완료 자료는 확정 역량의 근거로 삼지 않는다.
- 사용자 선호 수준·목표는 관측과 분리한다. 사용자는 관측에 동의하지 않음을 표시하고 선호를 변경할 수 있다. 원래 관측을 사용자 의견으로 덮어쓰지 않고 수정 전후·이유·시각을 보존한다.
- 일반 대화·정의·가설·도움 사용은 기존 저장 계약을 따른다. 임시 실행을 사용한 메시지·응답·요약은 전체 임시 처리한다. 임시 자료에서 나온 수치·결론을 학습 상태로 우회 보관하지 않는다. 명시적 선택 저장 뒤 별도 행동에서 연결한 근거만 영구 기록에 사용한다.
- 맥락 요약에는 참조 가능한 저장 메시지·보고서 ID와 요약 버전을 남긴다. 원문 근거가 삭제되면 관련 요약·관측을 무효화하거나 재생성하고 추천에도 반영한다.

## 이벤트와 작업 상태

이벤트 v2는 추가 전용 기록으로 저장한다. 기존 v1은 원문을 변경하지 않고 집계 어댑터로 읽는다. 기존 이벤트에 없는 종료·판정·버전을 추정해 채우지 않는다.

공통 필드는 `event_id`, `event_type`, `schema_version`, UTC 시각, `operation_id`, `parent_operation_id`, 선택적인 요청·훈련·과제·패키지 ID, 콘텐츠·난이도·평가·모델·프롬프트 버전, 상태, 고정 오류 코드, `duration_ms`다. 이벤트별 필수·허용 필드와 타입을 명시한 서버 모델을 둔다.

이벤트군은 요청 상태, 생성·적재·검증 시작/종료, 과제 공개, SQL 실행 상태, 코칭 시작/종료, 힌트·해설 사용, 제출·리뷰 시작/종료, 추천 표시/선택, 사람 판정 변경, 파일럿 시작/종료로 나눈다. SQL 이벤트에는 상태·시간·행 수·완전성 메타데이터만 허용한다. SQL·결과 행·대화·프롬프트·응답·키 원문은 모든 지표 이벤트에서 금지한다.

- 동일 event_id·동일 본문 재전송은 기존 결과를 반환하고, 다른 본문은 409 충돌이다. 재시도는 새 operation_id와 원 작업 parent ID로 연결한다.
- 작업 상태 테이블과 이벤트를 구분한다. 실행 중→성공/실패/취소/중단 전이를 관리하며, 완료 이벤트를 임의로 성공으로 바꾸지 않는다. 재시작 시 종료가 없는 작업은 중단 처리한다.
- 필수 요청·작업 상태 저장 실패 시 해당 작업을 시작하거나 과제를 공개하지 않는다. 부가 이벤트 저장 실패는 현재 입력·완료 기록을 보존하고 별도 수집 장애 상태를 표시한다. 복구 전 집계는 불완전으로 표시하며 복구 시 서버 메타데이터로 확인 가능한 이벤트만 보충한다.
- AI 호출 성공·형식 실패·시간 초과·제공자 실패·취소를 구분한다. 호출 시작 시 한도를 원자적으로 예약하고 실패도 호출 수에 포함한다. 토큰은 null과 누락 이유를 허용하며 실패를 0토큰으로 계산하지 않는다.

## 판정 계약

판정에는 `assessment_id`, 대상 종류·ID, 검토자 식별자, 기준 버전, 결과, 기록 시각, revision, 이전 revision, 선택 메모를 둔다. 검토자 식별자는 로컬 운영자 표시명으로 충분하며 계정 시스템을 추가하지 않는다. 학습자 응답은 사람 검토와 구분한다. 메모는 운영 이벤트와 별도 저장하고 임시 SQL·원문 입력을 요구하지 않는다.

대상은 과제 쌍의 다양성, 난이도, 코칭 제안, 리뷰 표본, 파일럿 참여, 최초·수정 보고서 쌍이다. 연결 대상이 존재하고 버전이 일치해야 한다. 반복 평가 판정은 회차와 표본 ID를 포함한다. 판정 수정은 이전 기록을 보존하고 최신 유효 revision을 집계한다.

분모 0은 null/미측정으로 표시한다. p95는 정렬된 관측값의 `ceil(0.95*n)`번째 값, 중앙값은 가운데 값(짝수면 두 값 평균)으로 계산한다. 전체 출제 시간은 최초 실제 시도 시작부터 최종 상태까지, 재시도 대기를 포함한다. 각 시도 시간도 별도 제공한다. 누락 시 종료 시간을 추정하지 않는다.

필터는 기간·분야·요청/출제 난이도·과제 유형·모델·규칙 버전이다. 요청 기간은 최초 시도 시각, AI는 호출 시작, 판정 지표는 대상 발생 시각으로 고정하며 판정 갱신 시각을 별도 제공한다. 화면 Asia/Seoul 날짜 범위를 UTC 반개구간으로 변환한다. 혼합 버전은 분리 표시한다. 비용은 단가·통화·기준일이 설정된 경우만 추정한다.

## API·보관·연결

기존 `/api/training/metrics`·`/export`를 버전 식별 가능한 집계로 확장하고 JSON·CSV를 제공한다. CSV는 사용자 메모의 수식 실행을 방지한다. `/api/learning-state` GET/PATCH와 `/api/quality/assessments` GET/POST, `/{id}` PATCH를 추가한다. 수정은 expected_revision 충돌 시 409, 잘못된 연결은 422, 삭제 대상은 404다. 이 경로는 신규 설계이며 현재 존재한다고 표시하지 않는다.

학습 기록·판정은 삭제까지, 운영 이벤트는 기존 30일 설정을 유지한다. 만료된 구간은 보관 범위 밖으로 표시한다. 훈련 삭제는 연결 대화·근거·보고서·리뷰·관측·판정·요청·이벤트를 제거하고 추천·집계를 재계산한다. 삭제된 대상 쌍 판정도 제거한다. 공유 패키지는 보존하고 미참조 신규 패키지 정리는 출제 Spec의 별도 정책을 따른다.

## 구현과 검증

기록 DB에 학습 상태 revision·관측·판정 revision·작업 상태 계층을 추가하고 기존 스키마를 파괴하지 않는다. 이벤트 계약→저장·호환→집계→기능 연결→삭제 순으로 구현한다. 권장 신규 모듈은 `learning_state.py`, `telemetry.py`, `metrics.py`이며 현재 파일과 구분한다.

고정 이벤트 표본으로 8종 지표의 분모·결측·중복·p95를 독립 계산해 대조한다. 실제 DB에서 재시작·판정 수정·삭제·수집 장애·기존 v1 재개를 검증한다. 임시 SQL·행·코칭 원문을 포함한 표본이 DB·로그·내보내기·요약에 남지 않는지 확인한다. 운영 화면 실제 입력·필터·판정·다운로드 검증은 Spec 011·013과 연결한다.
