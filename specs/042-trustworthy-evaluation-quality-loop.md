## 목적과 사용자 결정

평가를 믿을 수 있게 하는 데 우선순위를 둔다. 사용자 요청 순서는 중복 감점 방지 → 반복 평가 일관성 → 수정 피드백 → 검산 범위/문제 유형 확장 준비다. 중복 감점·근거 충돌은1회 자동 수정 후 재검사하고, 실패하면 점수를 보류하고 이유·재시도를 안내한다. 사용자가 이 정책을 선택했다.

사용자는 **반복 검증 미통과 유형은 점수 보류, 피드백 제공**을 선택했다. 개별 감점 계약을 통과해도 유형 검증을 대신하지 않는다. 선택과 설명된 목적은 [나의판단과근거](../나의판단과근거.md)에 기록했다.

## 계약

- 기존5항목 공개 루브릭과 배점은 유지한다. SQL 작성·문장 길이·조회 횟수로 평가하지 않는다.
- 등급0~2에는 구조화된 deductions가 필요하다: issue_id, kind, check_id, claim, evidence_refs, reason. check_id는 해당 공개 항목의 required/core_error 중 하나다. 없는 내용의 누락은 빈 claim을 허용하되 missing_required에 한정한다.
- 같은 오류 ID 또는 동일 종류·인용·근거의 오류를 여러 항목에 배정하면 평가 응답 오류다. 확인된 산술 오류의 담당 항목은 공개 계약의 evidence_interpretation이다. 모델이 새로운 ID로 같은 오류를 반복해도 검사한다. 검사 범위 밖의 의미적 유사성을 완전히 판별한다고 주장하지 않는다.
- 오류 주장 인용은 현재 보고 또는 해당 후속 답변에서 실제 존재해야 한다. 성공 실행만 인용 가능하다. 없는 사실·미검산을 학습자 오류로 만들지 않는다.
- 구조화 사유 외의 reason에 동일 산술 결함이 들어간 의심 사례도 보류·재검토한다. 검사 실패를 학습자0점으로 바꾸지 않는다.
- 형식 보완과 의미적 재검토가 공유하는 수정 예산은 평가당 최대1회다. API 실패는 자동 반복하지 않는다. 형식 보완은 모든 등급 유지, 의미적 재검토는 검사에서 영향 대상으로 지정된 항목만 변경 가능하다.
- 수정 전 모델 응답·검사 코드·재응답·변경 항목·최종 상태를 저장한다. 원래 판정을 지우거나 높은 점수로 맞추지 않는다.
- 반복 검사의 표본은 실제 평가 입력과 분리해 저장한다. 기대 범위는 평가 모델에 전달하지 않는다. 반복 결과·보류·수정 횟수·항목 변동·점수 범위를 모두 기록한다. API 오류·미완료·표본 누락은 통과가 아니다.
- 유형 프로필은 공개 문제 정의·난이도·데이터 버전·루브릭·모델·관련 평가 코드와 일치해야 한다. 원시 결과로 가중 총점·검산·감점 계약과 반복 요약을 다시 계산한다. 저장된 pass 문자열만으로 승인하지 않는다. 실패 검사는 보존하며 활성 프로필을 덮어쓰지 않는다.
- 미등록·불일치·미통과 유형의 개별 결과는 total=null로 저장하고 후보 총점은 진단 자료로 분리한다. 카드에는 확정 총점 대신 보류 원인·검산·모델 관측 피드백을 표시한다. 같은 보고 재제출은 프로필이 계속 보류이면 추가 호출 없이 저장 결과를 재사용한다. 프로필 통과 후 재제출하면 새 평가 이력을 남긴다. 과거 확정 평가를 소급 변경하지 않는다.
- 검산은 공개 데이터/조건만 사용한다. 문제별 검산기 등록 계약과 테스트 표본을 제공하고 지원하지 않는 지표는 미검산으로 남긴다. 새 주제의 실제 Discord 출제 기능은 이번 범위가 아니다.
- 다른 데이터·정책의 수정 비교는 해결로 확정하지 않는다. 해결은 해당 주장 수정 관측이며 학습 효과 입증이 아니다.

## 완료 기준과 한계

자동 테스트는 중복 ID 변경 우회, 독립된 실제 결함, 허위 인용, 가설 기각/보류, API 실패, 수정 후 재실패,2회 호출 상한, 기존 기록 표시를 확인한다. 반복 검사에 실패해도 기능 검증과 의미 품질 미달을 구분해 기록한다. 실제 Discord 봇은 다른 worktree/PDF 이미지이므로 배포 및 전달 완료를 코드 완료로 대신하지 않는다.

등록한 고정 표본의 자동 통과도 모든 분석의 의미적 정답·사람 승인·취업 역량을 보장하지 않는다. 다른 유형은 새 계약과 독립 표본을 준비해 검증해야 한다. 현재 합계/비율의 명확한 등록 라벨만 공통 검산하며 새 주제의 출제 기능 자체는 구현하지 않았다.
