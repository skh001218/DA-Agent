## 목적

사용자가 테스트 중 ads와 organic의 뜻을 알 수 없어 분석을 이어가기 어려웠다. 모르는 용어를 `/question`으로 물어 짧게 이해하고 원래 분석으로 돌아갈 수 있도록 한다.

## 사용 흐름

- 본인의 과제 스레드에서 `/question text:ads와 organic이 뭐야?` 또는 `/question text:코호트가 뭐야?`로 질문한다.
- 용어 이름과 뜻을 첫 줄에 쓰고 필요하면 게임 분석 예시·주의점을 이어 쓴다. 이름을 포함해 용어당 1~3개 명시적 줄, 각 줄 120자 이하로 제한한다. 화면 폭에 따른 자동 줄바꿈은 기기마다 다르다.
- 기본 용어는 대소문자·한국어 별칭을 인식하며 같은 용어는 한 번만 설명한다. 일반 문장 안의 용어도 인식한다.
- 사전에 없는 용어·질문은 기존 모델에 1회 요청한다. 사전 용어와 미등록 용어가 섞인 경우에도 질문 전체를 모델에 전달해 누락을 피한다. 모델은 최대 5개 용어를 설명하며 확인 불가능한 용어는 뜻을 지어내지 않고 맥락을 요청한다.
- 빈 입력·500자 초과·한 번에 너무 많은 용어는 짧게 재입력을 안내한다. 모델 실패·잘못된 응답·호출 한도도 재시도 안내로 끝낸다.

## 구현 계약

- `/query`와 `/answer`에서 분리된 `question` 액션으로 등록한다. 기존 소유권·서버·스레드 검사를 적용한다.
- 대기 질문, 조회 조건, SQL 실행, 선택 근거, 보고·평가 및 훈련 상태를 바꾸지 않는다. 완료·중단 상태에서도 용어를 확인할 수 있다.
- 질문과 설명은 대화 기록에 남긴다. 설명은 `term_question` 도움 기록으로 남기며 점수 감점이나 SQL 요청으로 해석하지 않는다. 같은 이벤트 재처리는 기존 저장 응답을 반환한다.
- 사전 응답은 API를 호출하지 않는다. 모델 요청은 기존 사용자별 일일 한도를 적용하고 호출 기록을 남긴다.
- 모델에는 질문과 공개 데이터 사전·시간대만 전달한다. 비공개 정답·사용자 보고·다른 사용자의 기록은 전달하지 않는다.
- 응답 JSON 구조와 길이는 코드로 검사한다. Discord 전송은 기존 멘션 비활성화·문자 이스케이프를 사용한다.
- 시작 안내, 전체 명령 목록 및 `/tip command:question`에 사용법을 추가한다.

## 완료 기준

1. ads는 유료 광고를 통한 유입, organic은 광고로 분류되지 않은 자연 유입이라는 뜻과 예시를 한국어로 제공한다.
2. 여러 용어·한영 별칭·알 수 없는 용어·빈 질문·서비스 오류를 처리한다. 용어당 최대 3줄을 강제한다.
3. 질문 도중 용어 설명을 받아도 기존 `/answer`로 진행을 이어갈 수 있고 모델·SQL 불필요 호출이 없다.
4. 실제 Discord에서 `/question` 명령 선택·입력·설명 표시를 확인하고 결과를 기록한다.

## 검증 결과

2026-10-06 실제 명령 등록·입력·응답 표시를 확인했다. ads·organic은 모델 0회, ROAS는 모델 1회로 설명했다. 기록 DB를 읽기 전용으로 비교해 훈련 상태·대기 질문·대기 조회·조회 이력·실행 이력·선택 근거·보고·평가·확정 조건이 유지됨을 확인했다. 완료된 과제에서도 설명이 가능하다. 기존 운영 컨테이너와 체크아웃 간 차이가 있어 이번 기능의 변경만 반영했고 운영 중 PDF 기능을 보존했다.

- 검증 기록: [용어 질문 검증](../tests/reports/discord-term-question-2026-10-06.md)
