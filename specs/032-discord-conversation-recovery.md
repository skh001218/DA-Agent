## 범위

- 최근 실제 조회 세 번이 SQL 실행 없이 막힌 원인을 수정한다.
- SQL 생성 범위를 임의로 넓히지 않고 최초 완료까지의 유저별 단계별 조회는 명확히 미지원으로 안내한다.
- 일반 메시지 내용 권한을 추가로 열지 않고 멘션한 메시지를 처리한다. 슬래시 입력도 유지한다.
- /query는 이전 미확정 질문을 종료하고 새 조회를 시작한다. 확인 답변은 답장·멘션·/answer로 이어간다.
- API 오류 시 사용자 답변을 보존하며 새로운 사용자 요청 전 자동 재시도하지 않는다.

## 검증과 실제 적용

- `test_discord_conversation.py`와 기존 Discord 조회·전송·서비스·교육·provider 테스트: 110 passed, 테스트 DB 설정을 요구하는 19 skipped.
- `scripts/verification/verify_discord_conversation.py`: 실모델에서 최초 완료까지의 도전 수는 unsupported_query, 기존 도전 수 문맥이 있어도 최신 완료율 요청은 tutorial_rate, 보충 답변은 ready 확인. 실제 읽기 전용 조회 40명/30명/75%, 별도 EXISTS SQL 집계와 일치. 이 스크립트는 사용자 훈련 기록을 변경하지 않는다.
- 실제 Discord UI 검증에서는 기존 과제 스레드에 `기능 검증` 메시지를 남겼다. 멘션 → 소유권 검사 → 모델 → SQL → 영구 근거 저장 → 화면 응답 흐름을 확인했다. 성공 실행 ID: c33af761-2226-4859-94fa-3718d4deefdc. 사용자 과제에 검증 조회 1개가 추가됐다.
- 실제 화면 검증에서 명시된 “과제 기간”을 모델이 날짜 필드에 누락하는 경우를 발견했다. 명시된 공개 기간 참조만 보충하고, 서로 다른 지표로 변경할 때 이전 미확정 기간을 자동으로 상속하지 않는 회귀를 추가했다.
- 같은 이름의 역할과 봇 계정이 멘션 목록에 함께 표시된다. 멤버 검색 결과의 봇 계정을 선택하도록 안내한다. 역할 멘션만 보낸 경우 내용 제한 안내를 실제로 확인했다.
- 봇 이미지 빌드는 d93f 소스에서 수행하고 기존 discord-mvp 실행 설정으로 --no-build --no-deps bot 갱신한다. 웹 서비스·데이터 볼륨은 유지한다.
- 모델 의미 해석은 확률적이다. 최초 검증 성공만으로 모든 표현에 대한 정확성을 보장하지 않는다. /query로 새 조회를 시작해 초기화할 수 있다.
- 메시지 내용 권한은 그대로 false이며 일반 메시지 전체 수신은 활성화하지 않았다. 멘션·슬래시 입력을 지원한다.
