## 목적과 판단

사용자는 실제 Discord에서 배경이 너무 길고 관측 기간을 읽기 어렵다고 설명했다. 배경을 줄이고 한국 시간으로 간단히 표시하도록 요청했다. 이전 생성 문제는 전체 공개 설명을 배경에 넣던 것이 주요 원인이다. 새 문제도 업무 설명·배경·관측 현상을 중복 나열했다.

공개 배경과 관측된 문제의 첫 문장을 사용해 1~2문장으로 표시한다. 첫 안내의 미리보기 제한은 새 요구나 사실을 만들지 않으며, 전체 원문은 그대로 열람할 수 있다. 공개 질문은 모두 번호로 표시하고 장문의 판단 방법과 가정은 원문 열람으로 분리한다. 인정할 한계는 첫 안내에 보존한다. 코칭용 valid_paths를 질문이나 필수 풀이로 만들지 않는다.

## 기간과 호환

- 저장된 공개 관측 설명의 명시된 날짜·시각·시간 기준을 사용한다. ISO 오프셋과 Z를 우선하고 명시된 UTC/한국 시간 또는 저장 시간대를 적용한다. KST는 UTC+9이다.
- 여러 관측 창은 각각 한 줄에 기간 A/B 또는 번호로 표시한다. 공통 연도는 한 번만 표시하며 연도가 바뀌면 각각 표시한다. 0초는 생략하되 59초·소수 초 등 실제 경계의 정밀도는 보존한다.
- 미만·제외 경계, 명시된 observation_end를 한국 시간으로 표시한다. 불명확한 날짜·연결·시간대는 임의 추정하지 않는다. 특히 UTC의 닫힌 날짜 범위에 종료 시각이 없으면 변환을 보류하고 원문을 안내한다.
- 데이터의 최소/최대 날짜를 공개 관측 기간으로 대체하지 않는다. 저장된 날짜·SQL·지표·평가 계약·원래 문제를 변경하지 않는다.
- 이전 문제는 task_quality.public_description의 공개 표준 구역에서 배경과 질문을 읽는다. 예전 과제를 다시 생성하거나 모델로 요약하지 않는다.
- SQL 연습과 고정 튜토리얼의 안내·시간 계약은 이번 변경 범위에 포함하지 않는다.

## 원문과 검증

`/help kind:문제 원문`은 저장된 objective와 공개 구조화 조건, 인정할 한계, 시간 원문을 제공한다. 새 명령 선택지를 등록하고 기존 참고 정보 경로를 사용하므로 생성 분석의 진행/중단/완료 상태에서 모델 호출과 코칭 도움 이력을 추가하지 않는다. 데이터 사전과 평가 기준은 기존 경로를 유지한다.

가독성 판단은 같은 저장 문제의 전후 글자 수·메시지 수·배경 길이와 화면에 보이는 질문/기간을 비교한다. 모바일 너비에서 가로 넘침과 기간 줄바꿈도 확인한다. 기록: [검증·가독성 보고](../tests/reports/spec051-readability-2026-10-07.md).
