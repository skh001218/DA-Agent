## 요구사항과 분리 계약

PRD 6.4~7·9절을 구현한다. 현재 웹 서버/이미지/운영 DB·테이블은 변경하지 않는다. 별도 프로세스와 명시적인 Discord 전용 PostgreSQL DSN을 사용한다. 신규 discord_records 스키마에서 사용자별 세션 문서, 영구 대화·성공 실행·보고 버전·평가·도움·학습 관측, 이벤트 처리 기록과 일별 호출 예약을 저장한다. 사용자 ID는 Discord transport에서 전달하며 매 동작 전 소유권을 검사한다.

같은 세션은 PostgreSQL 행 잠금으로 순서를 보장한다. 이벤트 ID는 별도 트랜잭션에서 먼저 예약한다. 이미 완료한 요청은 이전 응답을 반환한다. 호출 중 프로세스가 중단된 이벤트는 처리 불확실 상태로 보존하고 자동 유료 재실행하지 않는다. 다른 세션·사용자의 이벤트 ID는 차단한다. 같은 입력의 수정은 새 이벤트로 기록한다.

기준 확인은 실행 전 대기한다. 실제 수집 결과를 SqlRunner의 임시 기록에서 즉시 가져와 영구 저장한다. 실패 조회는 성공 근거로 선택하지 못한다. 보고 버전·선택 근거를 보존하며, 보고 후 업무 담당자 질문 → 사용자 답변 → 최종 제출로 진행한다. 보류 평가는 확정 완료로 처리하지 않는다.

호출 전 일별 한도를 원자적으로 예약하며 API 실패도 호출 시도로 기록한다. 토큰 미보고는 null, 단가 미확정 비용은 null이다. 운영 한도 값은 설정으로 조정하고 초기 기본값은 일 30회다. 한도 초과 후에도 기록·SQL·재개를 열람할 수 있다.

## 검증 범위

독립 PostgreSQL 테스트 인스턴스에서 소유권, 두 사용자/서버 분리, 중복 이벤트, 중단 이벤트 재예약 차단, 동시 보고, 호출 한도, 복원을 확인한다. 실제 Gemini 응답 품질, Discord 권한/메시지 전달, 사람의 교육 품질·성장 판정은 검증 대기로 유지한다.
