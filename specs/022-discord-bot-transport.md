## 목적과 범위

[Discord PRD](../docs/prd-discord.md)의 6.1·7·8.3·9·11절을 구현한다. 별도 프로세스에서 내부 분석 서비스를 호출하고 전용 DB를 사용한다. 기존 웹 경로·환경변수·의존성 파일은 변경하지 않는다. 분석 의미·평가·영구 저장은 서비스 Spec의 책임이며 이 문서는 Discord 전달 계약을 정의한다.

## 계약

- `/training`, `/resume`, `/query`, `/help`, `/report`, `/followup`, `/submit`, `/sql`, `/evidence`, `/end`. SQL 직접 작성 연습은 후속 범위이며 `/sql`은 성공 조회의 실제 SQL 열람 명령이다.
- Interaction의 첫 작업은 ephemeral defer. DB·모델 작업은 `asyncio.to_thread`를 통해 이벤트 루프에서 분리한다.
- 허용 서버만 처리한다. 시작 전 부모 채널 권한을 검사하고 private thread를 invitable=false로 생성한 뒤 소유자를 추가하고 DB에 연결한다.
- 조회·보고·버튼 대안은 매 요청 DB 소유권, 서버, 연결 스레드 및 실제 비공개/회원/권한을 검사한다. 다른 소유자의 일반 메시지는 무응답이며 모델 호출하지 않는다.
- 시작 실패는 임의 과제·스레드를 생성하지 않는다. 삭제된 스레드는 검증된 부모에 새 공간을 만들고 같은 세션에 연결한다. 접근 거부는 원래 연결·기록을 유지한다.
- Message Content Intent는 기본 false. 일반 입력의 기능은 명령으로 대체한다. 스레드 밖·다른 봇 대화는 처리하지 않는다.
- 긴 결과는 1,900자 이하 단위로 분할하고 Markdown·멘션을 무력화한다. 모델이 원시 결과에 넣은 멘션도 발송하지 않는다.
- 원시 예외 문자열·토큰·DSN은 Discord 메시지에 노출하지 않는다. 만료된 Interaction은 재개/영구 스레드 응답으로 확인한다.
- 초기 비용 설정은 일일 30회, 양수 환경변수로 조정 가능. 실제 운영 예산은 출시 전에 결정한다.

## 검증 한계

로그인 없이 SDK 명령 등록까지 확인했다. 모의 I/O 테스트는 실제 서버의 권한 상속·스레드 지원·Intent 활성화·네트워크 응답 시간·학습자 이해도·Gemini 품질을 증명하지 않는다. 이 기능의 실제 화면 검증은 `검증 대기`이고 PRD의 Discord 출시 완료로 환산하지 않는다.
