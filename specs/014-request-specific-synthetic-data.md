## 목적과 사용자 결정

2026-10-05 사용자는 비정상 이용자 요청이 재방문 문제로 바뀐 사례를 근거로 요청 기반 문제 제공 목적을 수정하도록 요청했다. 사용자가 원하는 문제에 맞춰 데이터를 지원하는 방향과, 자동 검증 통과 시 새 과제를 시험 과제로 바로 제공하는 방식을 선택했다. 접속 분야만 늘리는 대신 요청별 데이터 설계 경로를 추가한다.

이 결정은 신규 `adaptive` 경로에 적용한다. 기존 승인 대상 접속 생성 규칙의 승인 이력을 바꾸거나 사람 판정을 자동으로 승인한 것으로 기록하지 않는다.

## 동작과 계약

1. 사용자 요청의 주제·학습 목표·난이도·형식을 바탕으로 과제와 데이터 recipe를 JSON으로 설계한다. 정보 부족은 추가 질문, 실현 불가·지원 한계는 명시적인 실패다.
2. LLM은 SQL·실행 코드·기준 수치를 제공하지 않는다. 서버가 정해진 선언 규칙으로 데이터와 검산 SQL을 만든다.
3. 독립 자동 검토 요청에서 원 요청·공개 과제·사전·비공개 생성 recipe를 비교한다. 주제 변경, 필수 자료 부족, 계정 성향 혼합, 시각/간격 모순, 정답 분류 노출은 미공개 대상이다.
4. 설계를 고정 저장하고 고정 seed로 작은 합성 데이터를 생성한다. 설계 형식·고정 데이터 조건 실패는 오류 위치·종류를 전달해 최대 두 번 수정한다. 적합성 탈락 사유를 보존해 한 번 설계를 수정·재검증한다. adaptive 합계 호출은 최대 6회다(후속 Spec 015).
5. 타입·PK/FK·유일 키·시각·재현성·실제 행·검산 집계를 확인한다. 학습자 읽기 전용 계정에서도 공개 표의 기준 조회를 실행한 후에만 과제를 공개한다.
6. 화면에 원 요청·실제 학습 목표·합성 데이터·시험 과제·사람 품질 검토 전 상태를 표시한다. SQL·선택 저장·보고서·코칭·재개는 기존 훈련 흐름을 사용한다.

`RequestV2.data_mode`에 `adaptive`를 추가하고 기본 요청과 화면의 기본 데이터 모드로 사용한다. `PublicTaskV2.plan_version=adaptive-plan-v1`과 동적으로 검증한 공개 표 목록을 지원한다. 기존 공개 표만 허용하는 SQL 정책·별도 DB 권한은 유지한다. 과제마다 고정된 평가 기준·독립 집계·비공개 자료는 새 패키지와 training_plans에 보존한다.

## 생성 범위와 한계

- 표 최대 4개, 컬럼 표당 최대 12개, 전체 최대 2,000행, 그룹 표당 최대 5개. 이는 구현 한도이며 모든 게임 분석 주제를 지원한다는 보장이 아니다.
- ID·정수·실수·문자 범주·시각·앞선 표의 FK·계정별 누적 시각을 생성한다. 계정별 요약의 유일 키를 선언하며 참조 중복을 방지한다. ID와 행 순서가 생성 그룹의 정답을 드러내지 않도록 섞는다.
- 계정별 순서 시각은 앞선 계정·간격 컬럼에서 누적하여 생성한다. 독립 무작위 시각을 실제 행동 간격과 일관된 시계열이라고 주장하지 않는다.
- 검산은 count/distinct/sum/avg/min/max 및 제한된 조건으로 서버가 SQL을 구성하고 Python과 대조한다. 요청한 현상 표본이 없으면 출제하지 않는다.
- 탐지 과제의 정상/의심/봇 정답 라벨은 기본 비공개다. 사용자가 라벨 데이터를 명시 요청한 경우만 별도 공개를 허용한다.
- 복잡한 인과 구조·게임 경제 시뮬레이션·선언 규칙 밖 자료는 자동으로 완성했다고 보지 않는다. 목표 적합성의 자동 검토도 사람 의미적 품질 승인을 대신하지 않는다.
- 평가에는 고정 검산으로 확인할 수 있는 계산과 미확인 대안을 구분한다. 새로운 SQL의 모든 가능한 의미를 자동으로 검증한다고 주장하지 않는다.

## 검증과 완료 구분

단위·실제 DB 회귀와 현재 모델의 실제 화면 결과를 별도로 기록한다. 모의 모델 DB 성공을 실제 모델 성공으로 대체하지 않는다. 새 경로의 기술 검증과 기존 PRD의 전 유형 평가 품질·반복 안정성·다른 PC/ARM·파일럿은 별개다.

최종 근거는 [검증 기록](../tests/verification-adaptive-2026-10-05.md)에 보존한다. 실패한 초기 표본과 스크립트 오류도 보존하며, 보호 규칙 변경 전에 만든 시험 과제를 최종 품질 통과로 사용하지 않는다.

## 후속 공통 오류 수정

보스 고급 요청의 실제 실패를 계기로 원본 기반 요약·시간 의존성·적합성 수정·실패 이력 보존을 [Spec 015](015-adaptive-generation-repair.md)에서 추가한다. 기존 두 주제 성공은 모든 주제/난이도의 성공 증거로 확대하지 않는다.
